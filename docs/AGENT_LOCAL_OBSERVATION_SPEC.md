人物设定也不等于观察记录。[当前人设](../Assets/CozyTown/Runtime/Content/DefaultMvpContent.cs)中的 Ren 善于留意池塘变化，只描述性格；不能据此生成“今早亲眼见到鱼群”等经历。

## 4. 首版观察合同

### OBS-01：区域、距离与身体

区域由场景内容显式登记，使用身体实际位置判断归属。进入区域后仍按附近距离筛选对象；边界归属、室内外、同区远物及跨区近物都必须有固定样例。首版不随朝向转动改变区域观察，也不把它描述成精确视线；面向、遮挡将来可以作为独立策略增加。

区域本身与对象使用稳定 ID，名称来自内容配置。首个场景只登记会面沿途和池塘周边的小集合，不自动把全部美术资产转换为事实。观察距离、区域边界和对象清单在实验前冻结；它们是本游戏参数，不引用 SDK 默认半径作为依据。

### OBS-02：显式语义与精度

首批事实覆盖实际区域、附近已登记地标／居民、本人相关资产、会面阶段、交付凭据，以及既有人设中的明确偏好。每个属性都声明数据来源及读取权限。

| 情况 | 可表达内容 | 不能推出 |
| --- | --- | --- |
| 已登记装饰植物，内容明确没有采集能力 | 附近有该装饰植物；它没有本轮支持的采集动作 | 它是可食用野蒜、具有库存或可以变成物品 |
| 未登记或不在观察范围内的物体 | 观察覆盖有限，相关信息未知 | 世界中不存在该物体 |
| 本人库存有 2 条鲤鱼 | 本人当前持有量为 2 | 今天刚钓到、很新鲜、池里还剩多少 |
| 看见池塘，鱼量未建模或未获知 | 附近有池塘，不能确定鱼量 | 0 条、无限条或某个估计数字 |
| 有成功交付凭据 | 在凭据时间转移了指定物品与价款 | 现在仍持有同样数量，或已经完成料理 |

### OBS-03：信息状态与否定范围

事实应保留对象、属性、值／单位、来源、观察者、时间和适用范围。知识状态与资源可用性分开：知道有对象，不等于知道数量；知道数量，不等于有权使用。

建议最小状态为“本次已知”“过去观察”“他人声明”“未知”；肯定／否定属于命题内容。未知、明确为零、存在但不可用、列表被裁剪必须输出不同语义。只有明确完整的特定范围查询，才允许据缺项作该范围内的否定；登记目录完整不等于整个世界都被建模。

这与 [W3C OWL Primer](https://www.w3.org/TR/owl2-primer/)解释的“信息缺失不等于为假”一致；来源与时间分离可参考 [PROV-DM](https://www.w3.org/TR/prov-dm/)。这里只借用语义区别，不引入 OWL 推理器或知识图数据库。

### OBS-04：权限先于裁剪

先按角色已知范围与听众权限过滤，再做相关性排序和条数裁剪。对方私有库存不进入输入，也不通过可选话题、缺项数量、错误原因或突然唤醒泄露。不可见对象的 ID 不应出现在“被过滤对象”清单中。

区分私下决策可读取的事实与向当前听众可表达的事实。前者保留履约所需的本人资源；后者附单独的可表达标记，覆盖本次交谈相关的本人信息、参与者已知条款／收据及公开观察。首批属性配置明确哪些本人数量可以陈述，不能让听众筛选误删决策必要值，也不能把“模型读到”当作“允许向任何人说出”。两组共享这两份视图，S 组只能引用可表达事实，F 组的越界披露另计错误。

必要信息直接提供：身份、当前事件、真实位置语义、本人资源、条款及交付结果不放在可选查询之后。附近对象采用固定次序和有界条数，裁剪必须标明不完整；具体上限由首批场景序列化结果确定，并保持现有请求字节上限。

### OBS-05：时间一致性与刷新

Unity 在同一轮世界状态应用和身体移动提交后采样观察；Runtime 接收不含 Unity 对象引用的不可变数据。记录实际采样时间，不能把队列中旧请求的时间当作稍后读取坐标的时间。序列化不临时读取可变场景对象。

本人当前资产、当前可观察对象状态、静态内容、历史收据分别定义有效性，不能共用一个随意 TTL。居民现有 `revision` 不是经济和全部环境状态的版本。提交需要当前事实的候选时，重读其获准访问的相关数据；历史记录按过去时表达，不因角色不知道的远方变化被暗中改写。

重读用于判断事实快照是否失效，不用于悄悄把新值填进旧候选。F/S 两组采用相同的发布前有效性规则：所依赖的当前事实视图失效时，不发布该候选，记录原文、失效原因及回退；下一次合法机会再采样。第一版可对整个当前事实视图作保守比较，分别统计因此增加的拒绝。自由台词不能因重读成功就被当作已修正；历史记录仅按其原时刻表达，不查阅未授权的远端当前值。

区域进出、相关对象状态变化、已确认交互结果使观察失效或更新；到下一次决策时再装配。观察缓存更新不等于必须调用模型。只有影响当前目标的已知事件进入原有机会队列，并服从既有冷却、并发和预算。

### OBS-06：自动触发与渐进式披露

初版流程为：世界事件产生机会 → 宿主装配局部事实 → 模型选择 → 校验并执行／表达 → 记录已发生结果。不依赖玩家自然语言启动观察。

社交请求必须主动携带交谈所需事实。首版对照不增加社交查询动作；普通 `inspect_location` 仍负责原可达性查询。等事实清单确实超过有效上下文时，再评估受限 `inspect_observed_entity`；该名字是候选接口，当前没有实现，查询也必须计入原决策预算。

## 5. 他人声明与个人记录

共同约束：对话记录只证明“某人在某时说过某事”，不证明其内容已成为当前世界事实。接受供货邀请不向买方暴露卖方准确库存；交付结果继续由实际经济更新和凭据确定。

用户已确认首版只保留参与者听到的声明，记录原说话者和时间，不扩展向第三人传播。复用现有会面参与者经历入口；向模型提供时明确是转述证据，不把文本内容转换成已完成事件。主动撒谎、错误信念形成和长期传播需要另外定义行为及测试，不能由自由台词直接写入世界状态。

## 6. 两组表达实验

用户已选择先比较，而不是预先采用其中一组。以下仅改变表达路径，事实集合、角色、目标、可用行动、长度上限和模型参数保持一致；不在同一实验混入新的全局知识或验证器。

| 组 | 模型输出 | 宿主处理 | 能评价什么 |
| --- | --- | --- | --- |
| F：事实上下文＋自由台词 | 当前 `say.text` 形式，允许自由组织语言 | 保留原协议、长度与阶段检查；事实错误离线标注，不用额外模型替它重写 | 真实事实输入下，自由表达仍有多少矛盾、无依据和误用来源 |
| S：同一事实上下文＋结构化表达 | 有限发言意图、合法事实引用和语气选择 | 校验事实类型、角色视角、时间和权限；整句由已审阅的句型与宿主值生成 | 相对于同一事实视图的可控程度，以及信息量、人物区分和表达变化的代价 |

S 组不附带自由尾句，也不在模板生成后交给模型润色，否则整段又回到开放语义。模板中的“又”“终于”“亲眼”等预设也必须有来源。模型不能靠选择正确 `factId` 就让任意台词通过；引用正确性与整句含义是两个检查。

首批受控意图建议只覆盖：报告观察、报告已确认结果、承认未知、提出相关问题、表达已有偏好或明确愿望。类型与事实不匹配时拒绝，返回原预算内错误或已有安全回退。回退、少说、始终不知道均单列，不算正确回答任务。

两组不是“哪一组让模型更聪明”的实验。S 组把部分表达交给程序，若错误减少，应同时报告这一机制和表达覆盖范围，不能归为模型推理提升。

## 7. 实施顺序与公共验收

GitHub 执行顺序为[实现 NPC 按区域与距离的局部观察](https://github.com/qinjunw/CozyTown/issues/73) → [对照验证 NPC 自由台词与结构化事实表达](https://github.com/qinjunw/CozyTown/issues/74) → [选择 NPC 的正式事实表达方式](https://github.com/qinjunw/CozyTown/issues/75)。最后一步由用户根据实验结果决定，当前不提前选定正式表达路径。

| 步骤 | 交付 | 公开行为边界 |
| --- | --- | --- |
| 1. 少量场景对象和观察投影 | 区域、对象语义、角色可知字段及不可变观察；普通 C# 数据与 Unity 采样分开 | 给定实际位置、授权状态和内容，读取该角色的观察结果 |
| 2. 时间、未知与权限 | 观察时间、来源、覆盖、失效规则和参与者声明 | 推进世界时间、变化可见／不可见状态，再读取上下文 |
| 3. 接入原事件与 HTTP 请求 | 主动装配事实；F/S 两组采用明确实验协议版本 | 通过原调度与 HTTP／编解码入口观察请求、候选、拒绝及最终台词 |
| 4. 受控表达与场景接线 | 有限语义帧、宿主渲染句型、结果记录 | 提交发言候选，检查实际展示文本、会面记录及资产无意外变化 |
| 5. 冻结后运行对照 | 固定请求与新建双方场景、原文及逐条标注 | 分开报告模型原始选择、校验、最终展示与游戏结果 |

首批固定测试至少覆盖：

1. 去池塘途中不提前获得目的地当前对象；进入／离开范围后观察变化。
2. 同区远物、跨区近物、室内外、区域边界；转身不改变本版区域感知。
3. 装饰植物没有资源能力；未知鱼量不是 0；完整局部否定不扩大到整个地图。
4. 截断清单与完整空清单不同；必要交易事实不被附近装饰挤掉。
5. 其余可见输入完全相同、只改变他人隐藏库存时，宿主生成的事实投影、候选话题和公开诊断相同；不要求随机模型台词逐字相同。
6. 当前观察、过去观察、他人声明和成功收据不可互换；历史声明不泄露未观察的新变化。
7. 生成期间移动、资源变化、读档；旧事实不得冒充当前事实，旧世界候选不执行。
8. 正确引用但错误类型、主体、单位或时态被 S 组拒绝；已知答案却拒答单独计失败。
9. 请求计量、总期限和原资源门禁保持；观察刷新不会每帧触发模型。

这些是首个实现阶段需要验证的目标，不是本轮已通过的测试。会面对话续调停滞仍由[复现会面对话在日程变更与预算等待后的停滞](https://github.com/qinjunw/CozyTown/issues/72)处理，不能在观察实验中通过扩大预算掩盖它。

## 8. 真实对照的预登记草案

建议总提供方上限 **96 次**：固定阶段 8 种事实情境 × F/S 两组 × 3 次 = 48 次；场景阶段为资源充足和卖方缺鱼两种初始配置 × 两组各 1 个新世界，每世界最多 12 次，合计最多 48 次。场景阶段只验证接线，不据每格一次估计长期成功率；需要更大样本时另行登记。

八种固定情境分别考察：实际位置与目的地、装饰与可用资源、未知数量、他人私有信息、旧观察与当前状态、局部否定与截断、意图与交付凭据、别人声明与本人经历。边界数值和重复次数在启动前锁定；两组使用完全相同的规范化事实快照并保留哈希，交错次序。固定阶段每个样本一次调用，失败原样保留。

继续使用 `deepseek-v4-flash`，记录返回别名；关闭思考、512 输出 token、7 秒提供方超时。固定阶段每样本只有一次提供方调用，不纠正；场景阶段沿用每决策最多两次总调用与原总期限，每世界 12 次上限包含普通活动、首次失败与纠正。原文、首个候选、校验错误、回退、实际台词、事实快照和双方初始化全部记录；不补跑替换失败，不将额外验证模型藏在预算之外。

| 指标 | 必须同时记录的分母或限制 |
| --- | --- |
| 有问题台词比例、问题断言比例 | 首候选错误与最终展示文本分开统计；后者以实际展示条数及事实断言数为分母。零断言记为不适用，矛盾、无依据、来源／时间错误、未授权信息分别计数 |
| 有效回应与事实覆盖 | 以全部预登记样本为分母，预先列出需回答内容；拒绝的帧、空输出、可答却拒答、回退和遗漏不能从任务失败中消失 |
| 角色表达 | 原文可变性、重复、语气与人设一致性；模板减少自由度需如实报告 |
| 运行结果 | 初始化、资产、会面阶段、主动结束／期限释放、日程恢复分别评价 |
| 用量与延迟 | 包含首次失败和纠正；不把少输出造成的速度变化单独宣称为整体优势 |

事实评阅隐藏分组，按最小断言与可用证据核对；自动评阅分歧保留并抽样交由人工核验。模型裁判只是评测辅助。两组结果提交后再决定是否正式采用结构化表达、保留自由表达，或为特定事实域采用不同方式。

## 9. 本轮尚不能宣称的能力

当前运行版本尚无本文的观察投影、对象语义目录或受控表达。全文方案未证明视线遮挡、开放物体识别、实际采集动作、鱼群数量模拟、长期传闻或四人跨日知识恢复。本轮提供的是可实施与可验收的范围；这些后续能力需要相应世界规则和实测。

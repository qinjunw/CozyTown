# 四人 Agent 实验操作指南

本入口在开发场景中创建 Mina、Eli、Ren、Sora 的独立实验世界，记录模型请求、宿主执行结果、世界快照和操作顺序。适用工作分支为 `codex/four-agent-experiment-platform`；具体提交和 Draft PR 由发布记录登记。推送 Draft PR 与合并是两个步骤，合并仍待后续评审。

这里描述代码入口和复现步骤。测试结果以对应运行的 XML、实验包和代理日志为准；本指南不作为图形界面验收或真实模型稳定性结论。

## 准备工程

使用 `ProjectSettings/ProjectVersion.txt` 指定的 Unity Editor，当前为 `6000.5.5f1`。Git LFS 必须取得 PNG 等二进制资源；只下载到 LFS 指针文件会导致 Sprite 导入失败。

在目标分支已推送后，可从干净检出开始：

```powershell
git clone --branch '<experiment-branch>' '<repository-url>' '<project-root>'
Set-Location '<project-root>'
git lfs pull
git lfs checkout
git lfs fsck
git status --short
```

将占位符换成实际仓库、分支和本地目录。在 Unity Hub 中打开工程，等待依赖解析与脚本编译完成。首次操作前确认 Console 没有编译或美术导入错误；不要通过重建开发场景来修复缺失的 LFS 资源。

实验窗口会打开 `Assets/CozyTown/Scenes/CozyTown_Dev.unity`，临时装配启动器，并在退出 Play 后恢复原场景布局。启动前处理 Unity 对未保存场景的提示。实验由独立服务持有状态，玩家移动与普通时间驱动交由实验入口控制。

## 选择实验输入

在非 Play 状态打开 **CozyTown > Agent Experiment**。必须显式选择运行模式和表达组。

| 选项 | 含义 |
| --- | --- |
| Fixed | 使用项目内固定客户端，不调用模型；检查移动、邀约、交谈、交易和记录流程 |
| Live | 通过已启动的本机代理调用模型；需要明确的生成配置和代理总调用上限 |
| Replay | 从已完成实验包读取场景、表达模式和输入顺序，使用录制响应回放，不调用提供方 |
| F | 自由台词；实际行动仍由宿主校验，台词本身不会改变资源 |
| S | 结构化事实表达；宿主根据允许的事实 ID 和表达方式生成台词 |
| Paired | 先 F 后 S；两组分别创建新世界，共用 `pairId` 并记录 `armOrder=["F","S"]` |

在“构建版本（含 dirty 状态）”中填写实际提交标识；有未提交改动时同时注明 `dirty` 并保留对应差异。无法确认来源时显式填写 `unknown`。窗口不会自动证明工作区对应哪个提交。

表达实验使用[合同 1.0](AGENT_EXPRESSION_EVALUATION_SPEC.md)，包内字段为 `expressionContractVersion="1.0"`。在“预登记计划引用（无则 none）”中填写冻结评测计划的文档引用，建议同时带提交标识；它保存为 `evaluationPlanReference`，引用的文档记录预登记问题、目标事实、场景和判定规则。没有预登记时显式填写 `none`。引用须为 1–4096 字符且不能全为空白；包读取会拒绝缺少字段、未知合同版本或非法引用，不从默认值推断旧记录的评测依据。

所有资源场景从第 1 天 12:00、世界种子 `12345` 开始。Mina 与 Eli 进行社交会面；Sora 与 Ren 使用既有的买鱼条款：1 条鲤鱼、25 金币。Mina/Eli 的会面开始时间为 12:20，Sora/Ren 的邀约窗口从 12:15 开始、会面从 13:00 开始。

| 资源初态 / `scenarioId` | Ren：鲤鱼 / 金币 | Sora：鲤鱼 / 金币 | Fixed 下应观察的资源结果 |
| --- | --- | --- | --- |
| 资源可交易 / `available` | 2 / 0 | 0 / 50 | 成交后双方各 1 条鱼、各 25 金币 |
| 卖方无鱼 / `seller_empty` | 0 / 0 | 0 / 50 | Ren 拒绝邀约，资产不变 |
| 买方金币不足 / `buyer_poor` | 2 / 0 | 0 / 10 | 不发起买鱼邀约，资产不变 |
| 买方已有鱼 / `need_satisfied` | 2 / 0 | 1 / 50 | 不产生补鱼需求，资产不变 |

四种场景保留 Sora 的 1 份盐及其他主体的默认配置。Mina/Eli 的社交会面仍可运行。Live 的行为需要按实际记录评价；固定客户端完成会面不能证明模型会作出同样选择。

Paired 的第二组从同一资源场景、种子和内容配置重新初始化，身份和时间账本独立。F 与 S 的表达配置有意不同，不应把 F 的完整快照直接加载到 S。除界面记录的组序外，操作者还应让两组使用相同的推进与检查点方案；窗口不会自动替第二组执行第一组的操作脚本。

## 完成一次 Fixed → 导出 → Replay

1. 选择 **Fixed / F / 资源可交易**，填写来源版本，点击“创建实验并进入 Play（初始暂停）”。确认世界为第 1 天 12:00，四人资产符合上表，请求尚未派发。
2. 点击“运行”，或逐次使用“推进 1 游戏分钟”。自动运行每次推进 0.5 游戏秒，即当前倍率下的 1 游戏分钟；四人的决定共用调度器。
3. 展开“四人当前状态”“当前局部事实”和“实验审计”。检查 Mina/Eli 的会面、Sora/Ren 的交付凭据、实际位置、双方资产及结束后恢复的日程。可先运行至 15:00 再检查结果；有失败时保留该轮记录。
4. 如需验证读档，在会面前暂停，以新的检查点标签保存；继续推进后再读取同一标签。标签只能包含 1–64 个 ASCII 字母、数字、`-`、`_`，同一实验中不能覆盖旧标签。确认世界代次改变、逻辑状态回到检查点，同时审计记录仍保留读档前的尝试。
5. 暂停后点击“处理返回（不推进游戏时间）”，让已经返回的请求进入宿主处理。确认没有在途请求，再点击“完成实验”。完成操作也记录独立的现实时间；无法完成时按提示处理待返回请求，不把未完成记录改写成完成。
6. 选择导出父目录并点击“导出已完成实验包”。保留窗口显示的具体目录。导出使用新目录，已有实验包不会被覆盖。
7. 退出 Play，选择 **Replay**，指定上一步包含 `manifest.json` 的目录，重新创建实验。使用“下一条记录”逐项执行，或点击“运行”。Replay 自动执行录制的推进、保存、读取和完成输入；发现请求、检查点、最终状态或结果分歧时停止。
8. 回放完成后可导出独立回放包；其 `runMode` 为 `replay`，`derivedFromExperimentId` 指向原实验。回放成功表示该版本对录制输入和响应产生了匹配结果，不表示模型重新生成了相同回答。

Paired 模式需先完成并导出 F，随后使用“结束 F 并启动独立 S 组”，再按相同方案运行 S。比较两份包的 `pairId`、场景、组序和初态，不把前一组的资产或记忆带入后一组。

“睡眠 / 跨日”接受 60–720 游戏分钟，且必须为整小时。窗口先暂停自动推进，再按已有世界规则快进、处理途中日程和晨间结算，并记录睡眠输入。需要覆盖完整一天时可连续睡眠两次 720 分钟，随后导出并回放，核对日期、农场及畜牧结算进度。睡眠不主动增加模型调用；后续决策仍通过正常 Tick 处理。

## 暂停、时间与调用预算

实验四人共用 **每现实分钟 16 次请求、最多 2 个并发请求**。普通决策与主动邀约的新决策按每人 30 秒冷却；社交回应按已有轮次规则继续。单次请求期限 8 秒，单次决策总期限 12 秒，最多调用 2 次；决策机会的游戏时间期限为 30 分钟。字段纠正也消耗原有调用预算。窗口显示累计请求、最近一分钟请求、在途请求及等待人数。

窗口“暂停”停止新的游戏推进 Tick，现实秒表仍在走；已发送的请求仍可能完成。“处理返回”执行一次游戏时间增量为零的 Tick，处理返回并检查现实时间期限。该 Tick 也可能派发符合条件的新请求，仍消耗预算。长时间暂停后，旧答复可能已超时，这应保留为结果。暂停间隔由下一次操作的现实时间记录，回放按记录处理该间隔。

读档恢复人物、资源、活动和决策逻辑，不退回当前进程已发生的真实调用数、滚动限流窗口或未完成物理请求占用。旧请求失去修改新世界的资格，仍在运行的任务继续占用并发槽。重新创建配对世界会创建新的游戏调度器；提供方总量仍由同一代理进程的硬上限约束。

## Live 的外部前置

使用 Python 3.10 或更新版本。凭据文件放在仓库外，由操作者自行配置；现有代理读取 `Todo` 为 `CozyTown` 的唯一记录中的 `testingAPIKey`。密钥不填写在 Unity 窗口、生成配置或实验包中。

在仓库根目录启动代理。下面的 `32` 是该次代理进程的提供方尝试上限示例，开始前按实验方案确定并登记实际总量：

```powershell
python -B Tools/agent_proxy/decision_proxy.py --credential-file '<private-credentials.json>' --port 8766 --max-calls 32 --trace 'Logs/agent-platform-live-new.jsonl'
```

日志文件必须尚不存在，父目录必须已存在。代理固定使用 `deepseek-v4-flash`，最多生成 512 Token，关闭思考模式，响应格式为 JSON object。每个代理进程最多两个提供方请求并行；失败尝试也计入 `--max-calls`，代理不自行重试。默认上限 12 次可能不足以完成四人活动，不能把游戏的每分钟 16 次限额当成该次实验的总量上限。

窗口选择 **Live**，填写 `http://127.0.0.1:8766/decide`。端口必须与启动命令一致；窗口只接受无嵌入凭据的本机回环地址。生成配置填写：

```json
{
  "model": "deepseek-v4-flash",
  "promptVersion": "Tools/agent_proxy/decision_proxy.py@<actual-commit>",
  "protocolVersion": 4,
  "maxTokens": 512,
  "thinking": "disabled",
  "responseFormat": "json_object",
  "stream": false
}
```

将提示词版本替换为实际代理代码版本；如果代理包含未提交改动，应保留对应差异。此字段是宿主声明，当前没有远程配置握手。普通场景使用的环境变量说明见[本地代理 README](../Tools/agent_proxy/README.md)；实验窗口直接使用显式填写的地址和配置。

可在另一个终端查询实际调用预算：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8766/status'
```

保留 `attemptedProviderCalls`、`remainingCalls`、`inflight` 与代理 JSONL。F/S 配对或多场景运行使用同一代理才能共用其总量上限；重启会开启新的进程预算，跨进程总量必须把此前失败和已尝试的调用一并核账。结束时先确认没有在途请求，再用 Ctrl+C 停止代理。

Live 窗口提供“刷新代理指标（不调用模型）”。它读取同一代理的 `/status` 和 `/measurements`，仅将能与当前实验请求的 `decisionId`、`step`、`npcId` 对应的明细写入报告。导出前会再尝试刷新；刷新失败仍可导出，并保留此前取得的指标，未取得的字段保持未知。导出前检查窗口提示，以区分本次刷新结果和较早的报告。

`status.source=proxy_shared` 表示状态计数覆盖整个代理进程；配对共用代理时，它包含另一组的调用。当前实验的匹配明细与共享总量分别报告，不能直接相减推算某个未记录实验的成本。原始候选最多保留 16 KiB，发生截断时记录 `rawCandidateTruncated`；缺少 Token、实际返回型号或价格依据时，相应值保持未知。

## 实验包与结果解释

```text
<experiment-directory>/
  manifest.json
  initial.json
  final.json
  checkpoint-<label>.json
```

manifest 版本为 1；各世界快照使用既有版本 4 存档格式。`initial.json` 是首次模型调用前的完整状态，`final.json` 是记录的终态，检查点按标签关联。API 允许未完成包没有 `final.json`，由 `hasFinalSnapshot` 明确表示；窗口导出未完成记录时可附带当前快照。默认读取与 Replay 均拒绝 `completed=false` 的包。

`manifest.json` 记录实验、配对和来源身份，场景、F/S、运行模式、表达合同版本、评测计划引用、配置声明、输入顺序、请求 trace、宿主结果及度量字段。问题与目标事实保留在引用的冻结计划中，评阅时据此核对；`none` 表示没有预登记计划。输入中的 `worldBefore/worldAfter` 标识读档前后的世界代次；回放会映射新生成的身份。`inputs` 包含 `advance/save/load/sleep/complete`；`trace` 记录发送、完成、交付和取消时序；`results` 保留调用次数、候选错误、最终结果及执行观察。

| 数据 | 当前可据此判断的内容 |
| --- | --- |
| 请求、候选、执行观察、结果码 | 模型当时获得的事实，以及候选被接受、拒绝、超时或取消的原因 |
| 身体、会面、背包与钱包快照 | 实际到场、会面进程和资源是否转移；文本声称不能替代这些记录 |
| 发送、完成、交付与决策结束时间 | 区分客户端任务完成耗时、等待宿主处理的时间和整次决策耗时；缺少完成时钟时该指标为未知 |
| 模型名、Token、原始提供方候选 | 刷新后可从 trace 注释及代理明细读取，并与本地代理 JSONL 核对；可选字段缺失视为未知，候选截断单列 |
| `measurementsJson` | 记录匹配明细、已记录请求数、已匹配与未匹配数量及代理共享计数；未刷新时为 `{}`，不能当作零次错误或零成本 |

实验审计可以包含读档前世界的结果，角色记忆只来自当前世界实际保留的经历。查看“最近结果”时同时核对结果世界代次，不把历史审计误当成 NPC 当前知道的事实。

Replay 导出保留原实验的测量报告。报告中的提供方计数和 Token 描述原始 Live 运行，不表示回放又调用了模型；用 `runMode` 与 `derivedFromExperimentId` 区分来源。

常见停止条件包括 `experiment.incomplete`、`experiment.configuration_mismatch`、版本不支持、非法检查点标签和回放分歧。保留原包与错误，检查是否选错场景、表达模式、代码或内容版本。代理上限、超时、`agent.observation_stale` 和候选拒绝都属于该轮结果；补跑使用新的实验身份与目录，不能覆盖失败样本。

固定与回放检查完成后，再安排带预算的 Live 轮次。界面人工检查、真实模型行为统计和配对结果分析应分别记录证据；它们不由一次代码测试通过自动推出。

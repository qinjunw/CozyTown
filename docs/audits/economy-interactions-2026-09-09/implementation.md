# 经济交互修补验收

用户在审计后要求开始迭代。本轮以审计提交 `4eb795d8c9ea4367778f9ef72905564de8a5126a` 为变更基线，修补 [审计报告](README.md) 中 ECO-01～08。本文记录实施边界与验收要求，运行结果另行记录；报告中的原始失败结果保持不变。

## 界面选择与边界

- 商店采用 Buy / Sell 页签，首次打开显示 Buy；Sell 入口持续可见，无可售物品时解释回收范围。页签切换和重新打开回到列表顶部，交易刷新后夹紧有效滚动范围。
- 保留每次交易一件、现有价格、产量、配方、随机结果、晨间规则、有限商店资金及存档格式。数量选择、卖出全部与钓鱼收益节奏不属于本次修补。
- 沿用现有英文游戏界面和图标。种植、浇水、喂食、领取和烹饪说明使用运行时提供的真实条件；错误反馈说明下一步可执行动作，不向玩家显示内部错误码。
- 正式场景只升级相关 UI 和绑定，不重建世界布局，不启用真实 AI。既有 Scene-01、Town-01 人工验收仍由用户记录。

## 公开验收入口

沿用审计公开入口：模拟鼠标/滚轮输入、可见文本和按钮、实际资产及生产状态、世界 Sprite、保存和读取结果。单元测试使用公开 View/Coordinator，场景测试使用正式场景交互与输入链路；测试之间隔离存档。

## 工作顺序

每个独立行为先运行失败测试，再作最小实现并验证通过。主代理统一运行 Unity 和升级正式场景；子代理在明确文件边界内修改，Unity 运行期间冻结 Assets 写入。完成后运行相关及全量回归，并从基线独立检查规范符合性和规格符合性。

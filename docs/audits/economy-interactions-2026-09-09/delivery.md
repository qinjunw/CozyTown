# 经济交互修补记录

本轮按 [实施验收](implementation.md) 修补现有经济交互。交易、生产、价格、钓鱼、晨间结算和存档格式保持既有规则；修改涉及 Unity 适配层、UI 场景、只读烹饪可用性投影和测试。代码验证版本为 `20cc3e0`，审计基线为 `4eb795d8c9ea4367778f9ef72905564de8a5126a`。

## 玩家可观察的变化

| 原问题 | 当前行为 |
| --- | --- |
| 文字与空白处滚轮不生效 | 列表视口接收指针事件；文字、空白和按钮区域都能滚动到后续地块。 |
| 出售入口在购买列表下面 | 商店提供 Buy / Sell 页签；无可售物品时说明回收范围。每次仍交易一件。 |
| 列表末尾空白、重新打开停在旧位置 | 商店内容高度按实际行数计算；切换页签、重新打开回到顶部，交易后夹紧有效偏移，并显示当前行范围。 |
| 生产服务已结算但世界贴图滞留 | 农田、鸡舍响应共享时间流的结算周期与重建版本；自然晨间、睡眠和成功读档都更新世界画面。 |
| 待收蛋时仍能喂食 | Feed 在待收时禁用，Collect 可用，文字提示先领取。 |
| 配方缺少材料信息 | 五种料理显示实际材料名称、持有量、需求量及缺少数量；材料变化和烹饪后刷新。材料齐全但扣料后仍放不下成品时，Cook 禁用并说明容量原因。 |
| 失败直接显示内部代码 | 常见缺钱、缺货、缺材料、容量不足、待领取等条件给出操作说明；未知错误保留诊断日志并显示通用反馈。空竿作为正常结果提示再次抛竿。 |
| 产物与成熟状态容易误读 | 鸡舍区分预期产物和待领取产物；成长作物区分干湿，成熟作物提示收获。鱼和料理成功反馈使用显示名称。 |

实际文字边界检查另外发现种子按钮与长反馈被截断。种子按钮已改为可容纳两行，生产反馈区域也支持两行；保持原有字体大小。

## 实现边界

农田、鸡舍 Presenter 由 Bootstrap 接收 `IWorldTimeFlow`，不获取完整服务集合。事件仅在结算周期或重建版本改变时刷新；禁用模态 Presenter 时继续跟随已绑定会话，重新绑定先解绑旧流，销毁时移除订阅。失败加载不发布重建事件。

烹饪面板从同一次库存快照生成材料信息。每个配方使用独立的库存候选，按现有规则扣除材料后尝试加入产物，得到 `CanCook`。查询不修改玩家库存；消耗完一叠材料腾出的格子可以用于成品。实际烹饪仍由原事务执行。

`CozyTown > Upgrade Development Scene Economy UI` 只升级现有经济 UI。与审计基线比较，正式场景变动的 464 个序列化块均属于 Debug HUD；世界布局、住宅、道路、NPC 与生产世界节点没有变化。新版商店复用一个操作按钮，删除了旧模板中运行时一直隐藏的第二个按钮，因此场景文本的删除行数较多。

## 验证方法与限制

Unity `6000.5.5f1` 全量 EditMode **468/468**、图形 PlayMode **141/141** 通过，均无跳过。EditMode 在 `dbbb52a` 验证；之后的 `20cc3e0` 仅调整 PlayMode 输入测试隔离，并通过全量图形回归。规范和规格各由独立代理复核：最终没有待修问题；规格首轮发现的烹饪容量问题已通过失败用例复现、修补并复核。

- 逐切片先运行失败测试，再作最小实现。原始审计失败保持在 [审计报告](README.md)，本轮运行摘要保存在 [implementation-verification.json](implementation-verification.json)。完整 XML 与日志位于本地忽略目录 `Logs/`，新克隆不一定具备。
- `EconomyUiInteractionPlayModeTests` 注入虚拟 Mouse 的移动、滚轮、按下与抬起；点击前核对 EventSystem 的首个命中目标。业务按钮覆盖购买、播种、浇水、喂食、收蛋、睡眠、收获、抛竿、烹饪、出售，以及菜单保存/加载。列表定位没有直接修改滚动偏移。
- 鼠标闭环从 300 金币开始，购买胡萝卜种子和两份饲料后为 255，补盐后为 250；三个有效成长周期收获两根胡萝卜，并领取一枚蛋。鲤鱼和盐加工成烤鱼，出售获得 55 金币；加载售出前的保存后恢复 250 金币和一份烤鱼。
- `ProductionWorldRefreshPlayModeTests` 检查自然经过 05:00、睡眠、同周期成功加载、失败加载、禁用 Presenter、晚注册、重新绑定和销毁后的可见 Sprite。
- `EconomyTextReadabilityPlayModeTests` 使用正式场景、正式内容配置和真实状态投影，检查五类经济面板在正常状态与已知长反馈下，文本的排版高度不超过自身区域，包含三材料料理加容量说明的五行文本。该检查不代替像素截图或人工视觉验收。
- 自动化使用内存存档；未读取或覆盖用户主存档。交互点进入与部分关闭动作使用公开入口，未模拟玩家在整张地图上的行走。

图形测试使用批处理报告的 `640×480`。既有 Scene-01、Town-01 人工验收仍待用户记录，真实 AI 保持关闭。

前期测试适配问题包括本项目 NUnit 不支持 `Assert.Multiple`、未启用 `ScreenCapture` 模块，以及测试误用 Input System 内部属性；均在测试代码中修正，未增加依赖。完整鼠标测试最初的滚轮样本过大，在列表首尾间跳过目标行，改为小步输入后通过；该夹具问题没有归类为烹饪业务缺陷。

首次全量 PlayMode 为 140/141，旧键盘用例选槽失败；单跑和部分组合通过，补齐必需的 Mouse 后全量仍失败。诊断记录显示虚拟键盘已接收按键，但 Action 持续处于 Waiting；临时重注册动作后，同一全量组合通过。正式修正是统一三个场景输入测试的初始化：在切换虚拟输入 runtime 前释放共享 InputActionAsset 的运行时状态，测试场景卸载和原 runtime 恢复后，重新启用原先启用的具体动作。该隔离修正后的全量回归通过；诊断日志、额外等待和中途重启动作代码均已移除，游戏输入实现未变。

# ADR-0013：以确定性日程驱动小镇居民，首版位置由时钟重建

- 状态：Proposed；用户已要求扩镇、独立住宅与日常活动，本文的时钟、移动和恢复方案待实施前确认。
- 日期：2026-09-05。

## 背景

四名 NPC 目前具有独立身份和静态世界入口。新增住宅和通勤要求分钟推进、地点归属、移动与居家状态。现有时钟的 `AdvanceMinutes` 能单独跨日，但农田、畜牧与商店必须由跨日协调器共同结算；v2 存档不保存角色位置。将这些行为直接写入各 NPC 的 MonoBehaviour，会产生分散时钟、重复日结和未定义的读档恢复。

## 提议决策

1. 单镇增加四户 NPC 住宅，保留玩家住宅及六个功能入口。住宅与 NPC 用稳定身份关联，住宅不是额外的 `Bed` 交互。
2. Runtime 根据统一游戏时钟和静态配置给出目标活动/地点，Unity 负责沿合法路线移动及报告实际到达。职业表现不执行生产、交易或消耗；模型只读其快照，不参与日程决定。
3. 新日内时钟只通过窄应用入口推进，并在 `23:59` 封顶。跨日继续由现有 `SleepToNextDay` 用例提交；模态和失焦暂停时不累计现实时间。具体日程与倍率见 [T1 规划](../TOWN_LIFE_PLAN.md)。
4. 首版路线采用共同布局中的小型道路节点图，按脚底占地与非 Trigger 世界障碍校验。正常行走不得直接改坐标跳到目的地；到家以入门完成为准。NPC 与玩家/其他 NPC 暂不实体互挡。
5. 首版 NPC 世界位置和路径进度为可重建状态。成功加载后按时段合法归位，不承诺保存中途原地续走；保留 schema v2，不给经济主体添加坐标字段。若需要精确续走，另行定义世界状态快照、迁移及整体恢复失败语义。
6. 建筑继续底图/屋顶前景两层。玩家与 NPC 使用脚底前后排序，角色整体仍位于底图与屋顶之间；住宅室内、全建筑动态透明和人群导航不进入本阶段。

## 取舍

- **确定性日程与模型规划**：固定四人的日常可以在无网络时复现，并给模型提供实际事实。模型自主定路线会扩大权限、费用和恢复协议，与已确认的只读 Agent 首版不同。
- **道路图与通用自由导航**：固定住宅和职业地点可用少量共享节点表达；代价是不能直接支持任意地点漫游。自由建造或自由目标成为需求后再评估规则网格/导航库。
- **归位重建与精确位置持久化**：前者不引入新快照模块；代价是加载后 NPC 可能改变位置，返家时段临近结束的加载也可能延迟到家。该行为须告知并验收，不能描述为精确恢复。
- **日末封顶与自然跨午夜**：封顶保持唯一日结用例和已有经济事务；自然跨日则需要处理剩余分钟、失败重试和多日结算，本阶段不预先引入。

## 与既有决定的关系

本提案生效后，只对 T1 局部取代 ADR-0008 的静态 NPC 站位、全程三单位间距和不含日程约束，以及 ADR-0009 中 NPC 15/玩家 20 的固定相对排序。A1 历史结果保持原记录。

ADR-0002 的 AI 无游戏写权限、ADR-0005 的窄接口注入、ADR-0011 的原子日切与 ADR-0012 的 v2 经济存档继续有效。只读代理可以知道“正在返家”，但 `action` 标签仍不是移动或修改作息命令。

## 验证与复审

按 [T1 公开测试缝隙与矩阵](../TOWN_LIFE_PLAN.md#8-tdd-验收与交付顺序) 验证分钟边界、真实往返、模态、受阻、成功/失败加载、经济无副作用及场景升级幂等。扩大版联合 Scene-01/Town-01 人工通过前不启用真实 AI。

出现室内探索、精确途中恢复、自动经济行为、营业时间或模型写命令需求时，重新评估对应边界；不能以“NPC 更真实”为由自动加入。

## Unity 技术依据

Unity 提供自定义排序轴，竖直轴可用于俯视场景的前后关系；项目将该机制限制在角色层内。[2D 排序文档](https://docs.unity3d.com/6000.0/Documentation/Manual/2d-renderer-sorting.html)

物理移动仍需针对实际 Rigidbody2D 类型和碰撞配置验证。`MovePosition` 文档建议小距离、物理帧调用，并明确 Kinematic 刚体自身不会因碰撞自动停下；不能把选用该 API 当作“不穿墙”的证明。[Rigidbody2D.MovePosition](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rigidbody2D.MovePosition.html)

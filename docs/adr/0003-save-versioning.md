# ADR-0003：单槽位存档使用版本化数据包

- 状态：已接受
- 日期：2026-08-28

## 背景

MVP 需要恢复天数、金币、背包、农田、鸡舍和其他玩家可观察的持续性状态。开发期间模块 DTO 和静态数据会变化；未版本化存档无法区分旧数据、损坏数据和未来版本数据。

Unity 对象引用、资源实例 ID 和显示名称不具备稳定的跨版本身份，不能直接作为持久化契约。项目当前只需要一个本地存档槽位，不需要云同步或多设备冲突解决。

## 评估选项

### 选项 A：直接序列化运行时对象

文件结构与类字段同步变化，初始代码少，但重命名、资源重导入和组件重构会破坏读取，并把表现层类型带入存档契约。

### 选项 B：无版本的独立 DTO

运行时和持久化状态可以分离，但读取方无法可靠判断缺失字段来自旧版本还是损坏数据。

### 选项 C：带 schema 版本的独立数据包

顶层快照记录 `SchemaVersion` 和游戏状态 DTO。读取先识别版本，再按受支持版本迁移和校验，最后恢复模块。

## 决策

采用选项 C，并保留一个逻辑槽位。

顶层契约至少包含：

```text
GameSaveSnapshot
├─ SchemaVersion
├─ Clock（Day、MinuteOfDay）
├─ Wallet
├─ Inventory
├─ Farm
└─ Livestock
```

具体序列化格式由文件适配器决定；业务模块只导出和恢复 DTO，不读取文件路径或 JSON 字段。

规则如下：

- 当前骨架定义 `CurrentSchemaVersion = 1`；后续可写格式继续使用递增正整数。
- 物品、作物、鱼、配方和 NPC 使用稳定 ID；显示名称和 Unity 实例 ID 不进入身份字段。
- 新增可选字段必须定义旧存档默认值。
- 删除、重命名、拆分、合并字段或改变字段语义时增加版本，并提供逐版本迁移函数。
- 读取版本高于当前支持版本的存档时返回“不支持的未来版本”，不得尝试降级写回。
- 数据迁移完成后执行数值范围、必需 ID 和引用完整性校验，再恢复模块。
- 后续磁盘文件适配器先写临时文件并验证完成，再替换正式槽位；写入失败保留原文件。
- 解析、迁移或校验失败时保留原始文件并返回错误，不自动覆盖为新游戏。
- 模型生成对话正文默认不进入权威游戏状态。若未来保存对话历史，需要单独定义容量、脱敏和迁移规则。

当前 `InMemorySaveStorage` 对 `GameSaveSnapshot` 执行复制、schema v1 校验和槽位读写；它不执行磁盘序列化或旧版本迁移。MVP 调用方使用一个固定槽位 ID，存储接口保留 `slotId` 参数以支持隔离测试。

## 后果

正面结果：

- 运行时类和 Unity 场景可以重构而不直接改变存档格式。
- 读取路径可以区分空槽、损坏数据、不支持版本和有效数据。
- 迁移规则可通过固定夹具做回归测试。

成本和风险：

- 每次破坏性格式变更需要迁移函数和旧版本测试夹具。
- 稳定 ID 一旦发布不能随显示名称一起随意修改。
- 跨模块快照需要同一保存时点；保存协调器必须避免在部分模块已推进、部分模块未推进时组装状态。
- 单槽位减少 UI 和冲突处理，但不能满足多个角色存档需求。

## 测试要求

- 当前版本写入后读取，所得可观察状态与写入前一致。
- 空槽返回明确的“无存档”结果。
- 每个受支持旧版本都有迁移夹具和期望结果。
- 未来版本、截断文件、未知必需 ID 和越界数值均被拒绝。
- 模拟写入失败后，原有效存档仍可读取。
- 相同逻辑状态生成的 DTO 不包含场景对象引用或机器路径。

## 复审条件

增加多槽位、云同步、跨设备合并或玩家可编辑存档时，需要新 ADR 定义槽位身份、并发、冲突、校验和备份策略。该扩展不改变业务模块使用 DTO 的原则。

# ADR-0003：单槽位存档使用版本化数据包

- 状态：已接受；经济字段与 v1 迁移见 ADR-0012，结算日期语义见 ADR-0014；schema v4 完整逻辑快照见 [ADR-0019](0019-complete-logical-snapshots-and-agent-continuation.md)
- 日期：2026-08-28

## 背景

MVP 需要恢复天数、金币、背包、农田、鸡舍和其他玩家可观察的持续性状态。开发期间模块 DTO 和静态数据会变化；未版本化存档无法区分旧数据、损坏数据和未来版本数据。

Unity 对象引用、资源实例 ID 和显示名称不具备稳定的跨版本身份，不能直接作为持久化契约。项目当前只需要一个本地存档槽位，不需要云同步或多设备冲突解决。

## 评估选项

### 选项 A：直接序列化运行时对象

文件结构与类字段同步变化，初始代码少，但重命名、资源重导入和组件重构会破坏读取，并把表现层类型带入存档契约。

### 选项 B：无版本的独立 DTO

运行时和持久化状态可以分离，但读取方无法可靠判断缺失字段来自旧版本还是损坏数据。

### 选项 C：带 schema 版本的独立数据包

顶层快照记录 `SchemaVersion` 和游戏状态 DTO。读取先识别版本，再按受支持版本迁移和校验，最后恢复模块。

## 决策

采用选项 C，并保留一个逻辑槽位。

顶层契约至少包含：

```text
GameSaveSnapshot
├─ SchemaVersion
├─ Clock（Day、MinuteOfDay）
├─ Wallet
├─ Inventory
├─ Farm
└─ Livestock
```

具体序列化格式由文件适配器决定；业务模块只导出和恢复 DTO，不读取文件路径或 JSON 字段。

规则如下：

- 初始骨架定义 schema v1；后续可写格式使用递增正整数。
- 物品、作物、鱼、配方和 NPC 使用稳定 ID；显示名称和 Unity 实例 ID 不进入身份字段。
- 新增可选字段必须定义旧存档默认值。
- 删除、重命名、拆分、合并字段或改变字段语义时增加版本，并提供逐版本迁移函数。
- 读取版本高于当前支持版本的存档时返回“不支持的未来版本”，不得尝试降级写回。
- 数据迁移完成后执行数值范围、必需 ID 和引用完整性校验，再恢复模块。
- 后续磁盘文件适配器先写临时文件并验证完成，再替换正式槽位；写入失败保留原文件。
- 解析、迁移或校验失败时保留原始文件并返回错误，不自动覆盖为新游戏。
- 模型生成对话正文默认不进入权威游戏状态。若未来保存对话历史，需要单独定义容量、脱敏和迁移规则。

## 当前实现

默认 Unity 游戏写入独立于运行对象的 schema v4 JSON 数据包，包含统一时刻、资源、四人身体与活动、会面、有限经历及逻辑决策进度。独立资源用例可显式使用旧格式 v3。v1/v2 保留 ADR-0012 与 [ADR-0014](0014-continuous-world-time-and-morning-settlement.md) 的原协议校验和逐版本迁移；v1–v3 缺少的人物状态按 [ADR-0019](0019-complete-logical-snapshots-and-agent-continuation.md) 初始化。

`JsonFileSaveStorage` 在目标文件同一目录写临时文件，复读并校验后替换正式槽位；临时写入或替换失败时，上一份有效存档保持可读。读取区分空槽、截断或结构损坏、未来版本和无效载荷，迁移不重写原文件。常规 Editor Play 与构建使用 `<Application.persistentDataPath>/CozyTown/main.json`；批处理测试注入独立存储。

`GameSaveCoordinator` 的完整模式先准备全部资源、身体和 Agent 候选，再提交。准备失败保留当前世界和合法请求；提交后核心恢复异常由 [ADR-0020](0020-post-commit-world-recovery.md) 暂停会话。旧资源适配路径保留原模块失败回滚和独立回滚错误。`DaytimeClockCoordinator` 在提交完成后恢复小数余量并发布重建通知；旧请求通过新运行代次失去写入权限，实际调用预算继续保留。配置、迁移与测试证据见[完整快照实现报告](../verification/complete-agent-snapshots-2026-09-19.md)。

## 后果

正面结果：

- 运行时类和 Unity 场景可以重构而不直接改变存档格式。
- 读取路径可以区分空槽、损坏数据、不支持版本和有效数据。
- 迁移规则可通过固定夹具做回归测试。

成本和风险：

- 每次破坏性格式变更需要迁移函数和旧版本测试夹具。
- 稳定 ID 一旦发布不能随显示名称一起随意修改。
- 跨模块快照需要同一保存时点；保存协调器必须避免在部分模块已推进、部分模块未推进时组装状态。
- 单槽位减少 UI 和冲突处理，但不能满足多个角色存档需求。

## 测试要求

- 当前版本写入后读取，所得可观察状态与写入前一致。
- 空槽返回明确的“无存档”结果。
- 每个受支持旧版本都有迁移夹具和期望结果。
- 未来版本、截断文件、未知必需 ID 和越界数值均被拒绝。
- 模拟写入失败后，原有效存档仍可读取。
- 相同逻辑状态生成的 DTO 不包含场景对象引用或机器路径。

## 复审条件

增加多槽位、云同步、跨设备合并或玩家可编辑存档时，需要新 ADR 定义槽位身份、并发、冲突、校验和备份策略。该扩展不改变业务模块使用 DTO 的原则。

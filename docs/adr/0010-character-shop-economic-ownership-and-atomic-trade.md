# ADR-0010：角色与商店独立拥有资产并原子提交交易

- 状态：已接受
- 日期：2026-09-01

## 背景

当前玩家背包与钱包是全局服务，商店没有自己的库存和资金。购买会生成物品，出售会销毁物品并生成金币；未来 NPC 也无法复用统一的经济主体模型。

## 评估选项

### 选项 A：角色与商店保持独立聚合，由经济 Unit of Work 提交

角色拥有背包和钱包，商店拥有库存和钱包。交易先生成双方完整候选状态，再同时提交或全部拒绝。

### 选项 B：使用单一世界经济聚合

一个聚合持有所有角色和商店资产。跨主体交易较直接，但主体数量增长会扩大写入边界并耦合无关状态。

### 选项 C：顺序修改双方资产并在失败时补偿

该方案接近当前服务结构，但补偿本身可能失败，不能提供普通交易的强守恒保证。

## 决策

采用选项 A。

- `CharacterEconomyState` 由稳定 `CharacterId` 标识并拥有 `Backpack` 与 `Wallet`；玩家和未来可交易 NPC 使用同一模型。
- `ShopState` 由稳定 `ShopId` 标识并拥有 `Stock` 与 `Wallet`。
- 静态价格规则与动态角色、商店状态分离。
- 购买和出售先校验角色与商店的库存、资金和报价，再构造双方候选状态。
- 经济 Unit of Work 只同时发布两份合法候选状态；任一条件不满足时双方状态均不变化。
- 普通购买和出售保持参与双方的物品合计与金币合计不变。
- Unity 表现对象只映射稳定角色或商店 ID，不持有权威经济资产。
- 生产及其他资源来源或去向必须通过具名用例改变世界合计。

## 后果

- 当前玩家全局背包与钱包需要迁移为角色所有资产。
- 商店需要获得独立库存和钱包，报价目录不再代表实际库存。
- 玩家和未来 NPC 可以复用同一交易边界。
- 组件测试需要验证购买、出售、资金不足、库存不足及提交失败时的双方状态和守恒不变量。

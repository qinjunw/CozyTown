# ADR-0011：每日确定生成并完整替换商店基础库存

- 状态：已接受
- 日期：2026-09-01

## 背景

商店需要每天出现不同的基础补给，允许部分商品完全缺货，同时保持足够的可玩供给。角色出售的鱼、作物、鸡蛋和料理会进入商店库存，但这些物品不应被每日补货凭空生成，并允许在后续刷新中被清退。

刷新必须支持存档恢复、自动化测试和日切失败时的无部分提交。打开商店或重复调用当天刷新不能撤销当天已经发生的买卖。

## 评估选项

### 选项 A：按日完整替换目标库存

每个新游戏首日和成功进入新一天时生成完整目标库存，并替换现有商店库存。当天未入选的基础补给和前一天角色售入物品归零。

### 选项 B：补到目标数量

库存低于目标时补足，高于目标时保留。该方案会让未入选物品和角色售入物品长期累积，使随机缺货逐渐失效。

### 选项 C：基础库存与售入库存分区

基础库存按日替换，售入库存按来源或保留期清退。该方案能够表达寄售与保鲜期，但需要额外保存来源、批次和过期规则。

## 决策

采用选项 A。

- 自动补货只覆盖土豆种子、胡萝卜种子、番茄种子、鸡饲料、盐和面粉。
- 鸡饲料出现率为 100%，数量范围为 6–12。
- 每种种子出现率为 70%，数量范围为 3–6。
- 盐和面粉出现率均为 75%，数量范围为 3–8。
- 每日保证至少四类基础补给具有正库存；首次抽取不足时，从未入选规则中按同一确定性随机序列补足。
- 鱼、作物、鸡蛋和料理只能通过角色出售进入当天商店库存，并在下一次完整替换时清退。
- 刷新结果由 `WorldSeed`、`ShopId`、日期和 `RestockAlgorithmVersion` 的稳定组合决定；规则遍历顺序固定。
- 同一天已经刷新时，重复调用不改变实际库存。
- 刷新只改变商店库存，不改变商店钱包。
- 日切先生成时间、农田、畜牧与商店的完整候选状态，再同时发布或全部拒绝。

### 补货算法 v1 协议

`RestockAlgorithmVersion = 1` 固定使用以下协议；改变任一编码、遍历或抽取步骤都需要新的算法版本。

1. 以 FNV-1a 32 位偏移基数初始化散列。
2. 依次写入 `WorldSeed`、`ShopId`、目标日期和算法版本。整数使用 32 位二进制补码小端编码；`ShopId` 使用 32 位小端 UTF-8 字节长度前缀和 UTF-8 原始字节。
3. 将散列结果作为 xorshift32 状态；结果为零时使用固定非零状态 `0x6D2B79F5`。
4. 按规则固定顺序为每条规则消耗两个随机值：先以模 1000 的结果判定出现，再在闭区间内抽取数量。未出现的规则仍消耗并保存数量抽取。
5. 首轮少于四类时，按规则顺序建立未入选索引，再使用同一随机序列抽取并移除索引，直到补足四类；补入规则使用首轮已经抽取的数量。
6. 输出库存保持规则顺序。同日请求返回当前实际库存的副本，不重新生成当天目标。

固定兼容向量为 `WorldSeed = 12345`、`ShopId = shop.town.general`、目标日期 `2`、算法版本 `1`。结果依次为土豆种子 3、胡萝卜种子 3、番茄种子 3、鸡饲料 9 和盐 7；面粉当天缺货。

## 后果

- 每日缺货能够持续发生，且每日基础补给不少于四类。
- 前一天未售出的基础补给和角色售入商品可能在刷新时被清退；该变化属于具名资源汇。
- 存档需要保存实际库存、世界种子、最后刷新日和补货算法版本，不能只保存随机种子后在加载时重抽。
- 测试需要覆盖相同输入的确定结果、数量范围、保底种类、同日幂等、非补货物品不被生成、资金不变和日切无部分提交。
- 寄售、保鲜期和库存来源追踪需要新的领域决策，不进入当前实现。

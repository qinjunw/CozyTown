# ADR-0014：统一推进世界时间，按晨间边界结算并保留旧档结算事实

- 状态：Accepted；用户确认时间规则、迁移策略和公开测试入口后授权实施。接受不表示代码或人工验收已完成。
- 日期：2026-09-05。
- 执行任务：[T1-2b: Verify continuous world time, morning settlement and sleep](https://github.com/qinjunw/CozyTown/issues/38)。

## 决策与边界

世界时刻可以跨午夜；自然日期改变与每日生产/补给分开。每日 05:00 结算尚未处理的生产周期并完整替换商店库存；不加入强制昏倒、体力或出货系统。睡眠选择为 1～12 个整小时，正常走时与睡眠共用一个分钟推进入口。

时间协调器负责找出跨越的边界、准备结果与一致提交。农田、畜牧、商店保留各自规则，通过组合参与，不继承时钟类。只发布全部准备成功的世界结果；失败保留时钟、资产、生产状态和余量。候选演算不对场景发布中间状态，NPC 受阻不是时间事务失败。

倍率保持每 5 个有效现实秒对应 10 游戏分钟；权威时间按游戏分钟更新，不以 UI 的显示刷新频率决定规则生效时刻。模态/失焦不累计现实时间。自动推进保留不足一分钟的余量；成功睡眠、成功加载和新游戏清零，失败与保存保留余量。

旧 `SleepToNextDay` 如保留兼容入口，其目标仍为次日 06:00，通过统一分钟推进入口实现；它不受新 UI 的 12 小时选择上限截短，也不继续调用另一套日结链。新床面板只使用时长选择入口。

## schema v3 与旧档

写入 v3，显式保留 v1/v2 的解析、原协议校验与逐版本迁移。库存、钱包、世界种子、成长、浇水/喂食和待领取产物保持原值，不重新结算或重抽库存。

现有农田、畜牧和商店的最后结算日须相等，记为 P。下一次未处理边界由 Day(P+1) 05:00 派生，不另存重复的下一边界或迁移宽限字段。新游戏从 Day 1 06:00、P=1 开始。

v3 在凌晨 D≥2 时允许 P=D−1 或 P=D；05:00 及之后要求 P=D；Day 1 凌晨仅支持兼容的 P=1。超前、超出允许范围或模块凭据不一致均拒绝。旧 v2 仍先验证 P=D，不能把原协议中的坏档借新规则变为合法。

旧档 Day 2 01:00/P=2 保留已完成事实，下一次生产/补给为 Day 3 05:00；Day 2 的居民日程照常发生。这避免重复结算，但首个过渡生产周期可能延长。相比把旧 P 重标为 D−1，选择保留历史事实；相比将钟面移到早晨，选择保留玩家保存的时刻。

## 验收与原决定关系

公开 seam 为世界分钟推进、有效现实时间推进、显式睡眠、存读档、床交互与场景暂停/绑定结果。按[实施矩阵](../research/world-time/proposal.md#7-待实施的-tdd-验收矩阵)逐个 RED/GREEN；跨午夜与新存档关系同时通过后才接入实际走时。

本决定取代 ADR-0013 的午夜封顶、仅睡眠跨日及保持 schema v2 的限制，修订 ADR-0011 的补给触发点和 ADR-0012 的当前写入版本/日期关系。它不改变补给算法、普通交易守恒、NPC 日程无经济写权限和读档可合法归位而非精确续走的边界。旧版本测试结果保留为历史证据。

T1-3/T1-4 继续负责个人日程、实际通勤和美术；本时间切片不宣称这些功能已经完成。扩大场景的人工验收门禁继续适用，未通过前不接真实 AI。

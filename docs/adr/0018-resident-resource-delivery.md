# ADR-0018：把资源交付绑定到双方接受的会面条款

会面成功和对话中的交付声明不能证明资产已经转移。资源会面复用现有邀约、活动预约、路线和轮次协议，同时携带宿主定义的交易条款：卖方、买方、物品、数量和总价。发起邀请表示买方接受条款，接受邀请表示卖方接受；模型不能在答复中替换参与者、物品或价款。

双方实际到场后才开放 `deliver` 或 `cancel_exchange`。交付时重新读取资产，使用现有背包容量、物品堆叠和钱包规则准备两个完整候选，一次提交；缺料、资金不足、容量不足或溢出不发布任何一方。宿主在同一个同步调用内记录交付结果，然后开放对话。普通交易保持物品和金币总量；烹饪仍遵守已有配方的投入和产出。

交付由会面编号及世界时间线约束。当前或最近会面的已交付编号重试不会再次转移；更旧编号和旧时间线请求被拒绝。取消只释放未完成活动，已经发生的交付仍保留凭据，不通过结束会面撤销交易。执行入口按游戏主线程串行调用；多线程写入经济状态不属于该接口契约。

资源上下文只披露约定条款、本人相关物品数量和余额，以及宿主交付结果。它不会披露对方完整背包，也不会把模型发言提升为库存事实。缺料条件与时间窗口共同产生一次日内机会，模型选择等待、拒绝或取消时继续原有日程。本轮使用固定价格和单物品交易；讨价还价、跨日计划和进行中承诺恢复由后续需求决定。

资源机会等待决策或已经发出请求时，暂缓向其联系对象发送普通活动决策，避免同一调度轮同时邀请与闲逛。等待、超时或完成邀约后解除该暂缓；实际发出请求前再校验修订，拒绝被同轮其他居民行动更新的旧上下文。这个顺序不增加调用额度，也不提前占用角色身体。

NPC 初始资产由内容配置单独定义，与玩家资产一起进入经济状态和现有存档的角色列表。旧版只含玩家的存档在加载时补入配置的初始 NPC 资产；只要存档已含 NPC，就要求角色集合完整匹配，禁止缺一个补一个。存档结构版本保持 3，因为角色列表本已支持多个角色。这个兼容规则无法区分旧存档与人为删掉全部 NPC 记录的版本 3 文件；部分角色缺失仍按无效存档拒绝。资产恢复后会面时间线重建，旧交付编号不能重新执行；会面经历与进行中承诺的保存留给后续阶段。

## 2026-09-13：固定交易的自方条件

[上下文实验](../verification/npc-grounding-experiment-2026-09-13.md)中，仅披露自方条件仍有缺钱邀约；程序过滤消除了本样本中的已知不足选择。本轮按用户继续实施的授权，在[明确资源不足时的邀约与答复策略](https://github.com/qinjunw/CozyTown/issues/62)采用自方条件披露、允许动作过滤和执行前复查。

缺料机会继续提供给买方，买方无足够价款时仅可等待；卖方缺少约定物品时仅可拒绝；交付前买方不足时仅可取消。等待放弃本次每日机会，不表示筹資安排，当日资产增加不自动重试。当前没有赊账或未来生产承诺，因此不允许以这些尚不存在的能力解释缺钱邀约。条件与过滤仅依本人资产；对方能否履约、容量、收款溢出及实际到场仍由最终交付检查。

资产变化不依赖角色活动修订，因此 Invite 与接受分支重新读取执行者资产。邀约不足时不建立会面；接受时缺货会取消未接受的邀请并返回资源错误。绕过允许动作集合的候选由调度器拒绝，未接受邀请沿用原有到期释放；不得将此记为模型主动拒绝。交付成功后忽略原先的付款和库存条件，双方可以在花完价款或售完约定物品后正常交谈。

资源请求使用协议 v4；普通活动 v1、普通会面 v2 继续使用原行为，响应解析保留 v3 兼容。模型仍参与有限选项内的选择，系统过滤的收益单独记录。保留缺料机会会在仅剩等待时仍产生一次模型调用，换取与既有机会和角色决策路径一致的记录；是否直接由规则等待属于后续调用成本策略。

# ADR-0016：以结构化机会驱动有界自主决策

- 状态：已采用；按用户授权实施第二轮重构。
- 日期：2026-09-12。
- 票据：[接入有界决策与渐进式上下文](https://github.com/qinjunw/CozyTown/issues/52)。

现有对话由玩家交互触发，不能承担后台自主生活。新增独立决策入口，由世界事件产生机会，将单个居民的只读上下文交给模型客户端；宿主校验候选后才进入活动仲裁。模型客户端不持有世界或经济写接口。

第一种机会限定为默认日程进入休息窗口且没有有效临时活动。初始化／重建、日期／日程变化、活动结束可以检查此条件；活动接受本身不再次唤醒模型。工作和居家已有默认安排时继续执行日程。定向邀请和资源需求在后继票据增加。

初始上下文提供本人身份、人设、目标、触发原因、本人已知地点 ID 及活动约束；模型可按需查询其中一个地点的可达性，再提出等待或访问候选。角色与世界代次由宿主绑定，输出不能指定另一名执行者。披露检查与执行检查分别进行。

调度由 Unity 主线程推进，以现实时间管理调用预算、冷却和超时，以游戏时间及世界修订判断机会有效期。实验默认上限为每现实分钟 8 次客户端调用、同时 2 次实际在途请求、每人 1 个决策、每个决策 2 次模型往返、普通冷却 30 秒、单次请求 8 秒、整个决策 12 秒、机会有效期 30 游戏分钟。数值可配置，尚不代表模型表现或玩家体验验证。

模型续调和失败尝试也消耗请求预算。取消或超时后忽略迟到结果；如果客户端没有结束实际请求，其并发槽保留至任务结束，避免仅取消逻辑状态便突破真实并发上限。读档取消旧世界决策，保持同一调度器的现实时间预算。

本决策对 [ADR-0002](0002-deterministic-domain-and-ai-boundary.md) 增加独立的受检查活动候选路径。既有对话协议继续只返回文本与表现；自主动作仅能安排本人已有合法地点的工作／休息活动，沿用 [ADR-0015](0015-resident-activity-arbitration-and-world-epochs.md) 的期限、版本和读档语义。金币、物品、时间推进和存档写能力不进入模型接口。

测试先通过固定客户端验证结构化触发、上下文隔离、预算、续调、超时、失效和实际移动。真实代理使用独立版本化协议；旧对话端点不能被自动视为自主行动端点。

实现入口为 Runtime `NpcDecisionScheduler`、外部边界 `INpcDecisionClient` 和 Unity `CozyTownTownLifeController`。代理客户端通过[协议 v1](../NPC_AGENT_PROTOCOL.md)提供等待、地点查询和访问候选。默认启动器只在非批量运行且显式配置 `COZYTOWN_AGENT_PROXY_ENDPOINT` 后接入 HTTP 客户端。固定客户端不依赖端点配置。

取舍：第一轮披露只能查询本人日程地点的可达性，未引入地点知识库、社交承诺、角色资源或完整记忆。机会结束后只向本人下一次决策提供同世界内的结果码；诊断保留最近一次上下文和最终候选。拒绝或故障后不会自动无界重试。后续能力需扩展机会与操作契约，并继续由宿主验证实际世界结果。

## 2026-09-13：必填候选字段与一次纠正

已采用，按用户继续推进的授权实施[校验邀约候选必填字段并限定纠错机会](https://github.com/qinjunw/CozyTown/issues/63)。真实实验出现过缺少顶层 `planId` 的邀约，代理仍标记成功而宿主丢失当日机会；另一次原始输出把该字段放进 `social`。代理现在检查必填字段与原请求绑定，不补齐标识或提升嵌套参数。

宿主仅为已分类的必填字段问题保留一次纠正：通过 `candidateErrorCode` 返回固定诊断，在同一决策下增加 step。纠正与按需地点查询共享原总调用、速率、并发及期限；独立限制最多一次，不能因配置允许更多总调用而反复纠正。原机会时间、身份、修订、条款和允许集合不变，执行仍重新检查当前世界和资源。首次错误保存在结果的 `CandidateErrorCodes` 以及逐次代理记录中。

有效但错误的标识、未允许动作、版本不匹配、普通 JSON 解析失败、响应过大和基础设施故障结束本次决策。代理每次 HTTP 请求只调用一次模型；HTTP 422 的已知字段诊断可传给调度器，其他错误不隐式重试。纠正失败或预算／期限不足仍会丢失本次机会，这是有界调用的取舍。

旧版本独立解析能力保留；实际 HTTP 响应必须匹配它收到的请求版本。Unity 响应入口读取 JSON 字段的原始类型，避免把字符串期限或浮点版本自动转换为合法值。输入序列化仍沿用原格式；可选反馈字段不改变资源条款版本。

## 2026-09-14：交付后保留待发言轮次，在派发时创建请求

已采用，实施[保留预算等待中的会话轮次并重新采样请求](https://github.com/qinjunw/CozyTown/issues/83)。[原复现](../verification/npc-conversation-budget-2026-09-14.md)中，795.1 的日程事件取消旧发言并产生等待；旧机会在约 825.1 失效，默认八次预算在 855.2 释放时已无请求可派发。只重新读取观察也不够：若完整请求仍使用排队时间，刚返回的候选仍会沿用旧期限被拒绝。

调度器为已有事件唤醒、且交付结果为 `resource.delivered` 的 Conversation 保存待发言轮次，绑定世界代次、会面、说话人及已发言数。它保留首次触发事件和原时间，不提前固定角色修订、决策时间或观察。每次 Tick 在事件检查之前验证轮次；换轮、终态、失去到场条件、重建及会面截止后移除对应等待。

滚动预算、全局实际并发和该居民旧任务均允许后，以当前 Self、游戏时刻、Social 和 Observation 构造新 identity 的完整请求。进入派发尝试即消费标记；观察不可用也结束该次决策。请求发出后的世界／修订／观察验证、30 游戏分钟有效期、8 秒请求期限、12 秒决策期限及一次纠正继续生效。纠正仍属于同一次决策，不能通过重新采样获得额外期限或调用次数。

取消但尚未结束的旧任务继续占用真实在途约束。其回复只被收回，不发布台词，也不删除新世界或新轮次的等待。没有新事件时，模型 wait、候选错误、网络错误及观察失败不会因仍处于 Talking 而重新创建决策。会面期限仍是等待的上限，因此有限预算或失败后可能仍以到期结束。

取舍：延长旧快照期限会保留过时世界信息；提高调用预算会改变实验约束，且不能处理长时间在途。本次将等待机会与执行请求分开，只调整已交付会话。普通活动及其他社交阶段仍使用原 Pending 规则，正式表达方式和四人负载策略留给各自票据。验证方案见[实施方案](../verification/npc-conversation-turn-plan-2026-09-14.md)。

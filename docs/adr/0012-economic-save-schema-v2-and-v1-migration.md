# ADR-0012：经济状态使用 schema v2 并显式迁移 v1

- 状态：已接受
- 日期：2026-09-02

## 背景

现有 schema v1 只保存唯一玩家的顶层背包和钱包，没有世界种子、稳定角色身份、商店库存、商店资金或每日刷新状态。经济重构后，角色与商店分别拥有资产，存档还必须恢复刷新后继续交易形成的实际库存；只保存随机输入并在加载时重新生成会丢失当天交易。

项目仍是单机、单槽、模块化单体。当前状态规模、查询和并发需求没有达到关系数据库的引入阈值。ADR-0003 已确定版本化数据包、稳定 ID、完整校验和临时文件替换原则，本决定补充其经济 schema 与 v1 迁移细节。

## 评估选项

### 选项 A：版本化 JSON schema v2 与显式 v1 迁移

静态定义留在只读配置，动态角色与商店状态进入完整快照。读取 v1 时把旧玩家资产迁入默认角色，并按确定规则建立缺失的商店状态。

### 选项 B：写入 schema v2 但拒绝 v1

实现较少，但现有存档会失效，也违反 ADR-0003 对受支持旧版本提供迁移的要求。

### 选项 C：迁移到 SQLite

SQLite 能提供索引、增量更新和数据库事务，但当前单槽完整快照没有复杂查询、并发写入或大规模记录，不足以抵消新依赖、迁移和运维成本。

## 决策

采用选项 A。继续使用逻辑槽位 `main` 的 JSON 完整快照，当前写入版本提升为 `CurrentSchemaVersion = 2`，读取支持 v1 和 v2，不引入 SQLite。

schema v2 的顶层逻辑契约为：

```text
GameSaveSnapshot
├─ SchemaVersion = 2
├─ WorldSeed
├─ Clock（Day、MinuteOfDay）
├─ Characters[]
│  ├─ CharacterId
│  ├─ Backpack
│  └─ Wallet
├─ Shops[]
│  ├─ ShopId
│  ├─ Stock
│  ├─ Wallet
│  ├─ LastRestockedDay
│  └─ RestockAlgorithmVersion
├─ Farm
└─ Livestock
```

静态物品定义、购买价、回收价和补货规则不复制到存档。它们继续由 Runtime 只读配置或 Unity 作者资产提供，并使用稳定物品 ID 与动态快照关联。

新游戏的世界种子由 Unity 适配层生成一次并注入 Runtime，随后进入每次存档。Runtime 规则不读取 Unity 全局随机状态；自动化测试直接注入固定种子。

## v1 迁移

迁移按 `v1 -> v2 -> current` 的顺序执行。v1 到 v2 使用以下固定规则：

- v1 顶层 `Inventory` 和 `Wallet` 迁入稳定默认角色 `character.player`。
- 迁移器为旧存档赋予固定 legacy world seed；该常量由迁移夹具锁定，加载同一 v1 存档必须得到相同结果。
- 创建稳定默认商店 `shop.town.general`，钱包余额为 10,000。
- 使用 legacy world seed、默认商店 ID、存档当前日期和补货算法版本 1 生成一次当天基础库存；把生成结果作为实际库存写入候选 v2 状态，并把 `LastRestockedDay` 设为存档日期，避免加载后重复刷新。
- 农田、畜牧和时间状态按原语义复制；所有带日期模块必须与时钟日期一致。

v1 迁移是纯数据转换，不直接修改运行时模块，也不写回原文件。后续破坏性变化继续通过单步迁移链处理。

## 读取与发布

加载依次执行：解析存储数据、识别 schema、逐版本迁移、校验完整候选状态、一次发布全部模块。校验至少拒绝以下情况：

- schema 版本高于当前支持版本；
- 缺失、非法或重复的角色 ID、商店 ID、物品 ID；
- 负物品数量、负钱包余额或越界时间；
- 商店最后刷新日晚于当前日期；
- 时间、农田、畜牧和商店状态的日期关系不一致。

解析、迁移、校验或发布准备任一阶段失败时，当前游戏状态保持不变。磁盘写入继续先写同目录临时文件，复读并验证成功后替换正式槽位；失败时保留上一份有效存档。

## 后果

- 保存后加载能够恢复当天刷新后又发生过交易的真实角色与商店资产。
- v1 存档继续可读，并被映射为稳定默认玩家和稳定默认商店。
- 新游戏和测试可以用固定世界种子复现每日库存；加载不会重抽当天库存。
- 静态价格或补货配置调整不会膨胀存档，但删除稳定物品 ID 前必须考虑旧存档兼容性。
- 完整快照继续适合当前规模；只有出现可测量的大型查询、增量写入、并发或内容管理需求时才重新评估数据库。

## 测试要求

- v2 保存并加载后，世界种子、时间、全部角色资产、全部商店资产、农田和畜牧的可观察状态等价。
- 固定 v1 夹具迁移到 `character.player` 与 `shop.town.general`，商店资金为 10,000，库存和刷新日可重复得到相同结果。
- v1 迁移后的当天首次商店查询或跨日检查不重复刷新。
- v2 保存的是交易后的实际库存，而不是加载时重新生成的目标库存。
- 未来版本、重复主体、非法物品、负数量和日期不一致均被拒绝，且加载失败前后的当前游戏状态等价。
- 模拟临时文件写入或替换失败后，上一份有效槽位仍可读取。

## 与既有决定的关系

本决定取代 ADR-0003 中 `CurrentSchemaVersion = 1` 及其顶层字段清单，并扩展 ADR-0010、ADR-0011 所要求的角色、商店和刷新状态持久化。ADR-0003 的稳定 ID、逐版本迁移、未来版本拒绝、完整校验、失败不污染当前状态和临时文件替换原则继续有效。

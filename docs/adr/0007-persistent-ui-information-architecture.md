# ADR-0007：以锚点分区、只读投影和共享输入门重构常驻 UI

- 状态：已接受
- 日期：2026-08-30

## 背景

Scene-01c 已将正式界面迁移到 `320×180` 参考分辨率的 UGUI，但当前右上存档面板长期占据画面，左下交互面板持续显示说明和最近反馈，包裹与快捷栏没有正式入口。人工检查要求把常驻信息收敛为左上 HUD、目标上方交互气泡、底部五格快捷栏与右上齿轮，并通过 `B` 键和齿轮分别打开包裹与系统菜单。

该重构发生在 Scene-01 人工验收前。它不得增加物品使用、装备、拖放、任务、设置项、存档槽位或 AI NPC 能力，也不得让表现层取得背包或其他领域写接口。

## 评估选项

### 选项 A：全部使用固定屏幕坐标

与现有升级器接近，但重复槽位需要逐项维护坐标，包裹容量变化时容易出现遗漏。

### 选项 B：整张界面使用单一网格或自动布局

适合网页或流式内容，但会让角落 HUD、世界交互气泡、底部快捷栏和居中模态共享不必要的布局约束，也不利于纯像素整数定位。

### 选项 C：顶层锚点分区，重复内容使用局部网格

顶层按左上、右上、底部中央和居中模态分别锚定；快捷栏与包裹槽位在各自容器中使用确定性的整数网格。世界提示通过目标锚点投影到屏幕空间。

## 决策

采用选项 C。

- Canvas 继续使用 `ScreenSpaceOverlay`、Pixel Perfect 和 `320×180` 参考分辨率。顶层区域使用锚点与整数像素尺寸，不引入覆盖全屏的布局网格。
- 左上 HUD 只显示天数、时间和金币；右上只显示齿轮按钮；底部中央显示五格快捷栏；包裹和系统菜单使用居中模态面板。
- 快捷栏投影包裹只读视图的前五个槽位，数字 `1` 至 `5` 只改变选中索引。Scene-01d 不定义物品使用、装备、槽位绑定、拖放或丢弃。
- Runtime 提供只读包裹投影接口。`IInventory` 可以实现该读取边界，但 Unity Presenter 只接收只读接口，不取得 `Add`、`Remove` 或 `Restore`。
- `PlayerInteractor2D` 只公开当前提示锚点及其变化；气泡 View 跟随该锚点显示 `E`，不读取碰撞器集合或领域服务。
- 包裹、系统菜单和既有业务模态共享 `PlayerModalInputGate2D`。常驻 UI 控制器保持 `Closed`、`Backpack`、`SystemMenu` 三态；获取输入门失败时不打开界面，关闭或输入门撤销时统一隐藏并恢复控制。
- 保存与读取继续复用 `CozyTownSaveDebugPresenter` 和 `IGameSaveCoordinator`。保存 View 的内容节点可以预先刷新，但系统菜单根节点默认关闭，避免场景启动时自动展开。
- 设置按钮只进入可返回的占位页；不在本切片新增音量、分辨率、键位或本地化选项。离开游戏通过窄退出适配器调用 `Application.Quit`，EditMode 和 PlayMode 测试使用替身。
- Production UI 继续复用 `ui_panel`、`ui_button_*`、物品图标和 Unity Text。新增 `ui_icon_settings` 独立单图；现有 `ui_marker_interact` 只重绘为带尾部的气泡轮廓并由 Text 叠加 `E`。
- 业务模态在 Canvas sibling 顺序上始终位于快捷栏之后，确保面板和行动按钮覆盖快捷栏；该规则只作用于商店、农田、床、鸡舍、池塘、厨房和 NPC 七个模态。七个模态按钮使用深木底与奶油字，快捷栏 `1` 至 `5` 使用独立深棕色文本。
- 场景升级器继续按固定对象名幂等更新 A1 管理节点，不重建 Bootstrap、Presenter、交互点、碰撞或领域对象。运行时不得通过路径、Sprite 名或 `AssetDatabase` 查找资源。

## 公开测试缝隙

- 场景和布局：公开 `Canvas`、`CanvasScaler`、`RectTransform`、`Image`、`Button`、`Text`、对象启用状态与 `Button.onClick`。
- UI 行为：View 的 `ConfigureUi`、`Render`、`Show`、`Hide`、请求事件和只读状态；不读取序列化私有字段或调用私有生命周期方法。
- 输入：`InputActionAsset` 中公开的动作和绑定，以及可注入的包裹/快捷栏输入接口；不直接测试组件的私有 `Update`。
- 包裹：只读投影返回的稳定槽位顺序、堆叠拆分、空槽和容量；测试不通过 Unity View 修改领域状态。
- 交互气泡：`PlayerInteractor2D` 的公开当前提示锚点或变化事件，以及气泡 View 的公开显示状态；不读取 Physics2D 私有探测过程。
- 模态互斥：`PlayerModalInputGate2D.TryAcquire`、`Release`、`IsAcquired` 与公开撤销事件，配合实际按钮或输入边沿验证开关。
- 退出：可注入退出适配器的公开调用，不在自动化中终止 Unity Editor。

## 验证规则

- 每个垂直切片先运行能够精确描述缺失能力的 RED，再加入最小实现：常驻壳、交互气泡、包裹与快捷栏、系统菜单。
- EditMode 验证只读投影、View 状态、按钮路由、输入动作、Production Sprite 和关键锚点；PlayMode 验证真实 B/数字输入、最近目标气泡、模态互斥、保存/读取按钮与控制恢复。
- 场景升级入口连续执行两次后结果一致；全量 EditMode、PlayMode 与现有完整经济闭环通过，日志没有编译错误、丢失引用或未处理异常。
- 人工在 `320×180`、`640×360`、`1280×720` 检查 HUD、齿轮、五格快捷栏、包裹、系统菜单和气泡的可读性、遮挡与操作。
- 自动化默认不联网、不调用计费模型、不读写玩家正式存档，也不实际退出 Editor。

## 后果

常驻 UI 的职责和屏幕区域变得明确，重复槽位可以由同一只读投影驱动；共享输入门保证新增包裹和系统菜单不会与既有交互模态重叠。代价是 Bootstrap、场景升级器和测试需要增加显式绑定，保存内容与系统菜单根节点需要分离可见性。

Scene-01d 仍属于人工 Scene-01 验收前的表现与输入收口，不改变 M0 至 M5 里程碑。真实 AI 驱动 NPC、线上评测、Windows 发布构建和录屏继续等待 Scene-01 人工验收。

## 复审条件

只有在快捷栏开始执行物品使用、需要玩家自定义绑定，或设置页出现真实配置项时，才复审快捷栏命令边界、持久化格式和设置架构。复审不得让 Unity View 直接取得背包或其他领域写接口。

# ADR-0019：保存完整逻辑状态，重建 Agent 执行过程

- 状态：Accepted，目标契约已确认；新格式与恢复代码尚未实现。
- 日期：2026-09-17。
- 票据：[确定完整逻辑快照的保存与恢复契约](https://github.com/qinjunw/CozyTown/issues/93)。
- 确认依据：用户答复“好的,按照推荐来,开始工作吧”，采纳精确位置与行程续走、原互动续接、保留旧档数据并初始化缺失状态三项方案。

四人实验平台需要从同一个逻辑起点继续或重放实验。现有 schema v3 保存世界与资产，加载时清除 Agent 活动、会面和经历；按日程归位以及清零小数分钟也不能恢复路途中的保存状态。扩展现有版本化数据包，将活动、会面、经历、逻辑待办、身体执行进度和小数时刻与资源一同保存；字段清单、恢复规则和公开验收见[完整逻辑快照契约](../AGENT_SNAPSHOT_SPEC.md)。

直接序列化运行对象会把 Task、取消源、事件订阅、Unity 引用和现实时间账本混入文件，仍不能恢复外部模型执行。保持独立数据包：保存的是人物正在做什么及执行到哪一步，运行对象在加载时重建。内容版本、跨对象归属与全部身体候选在提交前校验；提交后生成新运行代次，旧请求失去写入资格。继续原逻辑决策时保留已耗调用／纠错次数和剩余时限，重新采样事实并使用新执行请求 ID。

此选择保留运行期限额与世界状态的分离。读档可以回到交易发生前，或回到过去的个人经历；当前进程实际在途任务、调用窗口和已发生费用不因此倒退。模型输出、玩家输入及外部随机输入另作实验轨迹，世界快照不保证再次调用真实模型得到同一句话。

新格式恢复精确身体和进行中的互动，旧格式保留已有数据并按既有规则初始化缺失状态。本决策对新格式局部取代 ADR-0013 的位置重建、ADR-0014 的加载清余量、ADR-0015 的加载清活动，以及 ADR-0017／0018 的临时会面与经历边界；保留新代次隔离、信息权限、资源原子交付及有界记忆规则。既有 schema v3 的运行行为尚未改变，后继实现必须分别验证新格式续接和旧格式迁移。

代价是需要新增明确的身体、活动归属和逻辑待办恢复接口，且严格区分完整新档与缺字段的旧档。用“清空 Agent 后重新规划”恢复较简单，但不能保留实验中途的承诺和决策进度；只保存坐标后重新寻路也会改变受阻与重规划状态。因此只有全部关键状态可一致恢复时才报告加载成功，异常状态通过独立恢复边界显式处理。

# CozyTown 工程交付计划

## 1. 交付原则

- 每个里程碑交付一个可观察行为，不以目录、空接口或占位断言作为完成证据。
- 领域规则保留在 `CozyTown.Runtime`；Unity 组件只负责输入、生命周期、场景引用和表现更新。
- 跨模块状态变更由应用协调器执行。UI、NPC 文本和场景对象不得直接修改其他模块内部状态。
- 自动化默认不访问真实网络、不调用计费模型、不读写玩家正式存档。
- 每个 Git 提交只包含一个可解释的行为或基础设施变更；提交前检查暂存差异、编译结果和相关测试。

## 3. 质量门槛

每个里程碑合入前执行与风险相称的检查：

1. `Packages/manifest.json`、锁文件和程序集定义可以被 Unity 解析。
2. Unity Editor 完成脚本编译，日志不存在 `error CS` 或 `Scripts have compiler errors`。
3. 相关 EditMode 测试通过；涉及场景生命周期时增加 PlayMode 或人工冒烟证据。
4. Debugger 复现并定位失败路径，修复后保留能阻止回归的测试。
5. Reviewer 检查模块依赖、失败原子性、稳定 ID、存档边界和 AI 写权限。
6. `git diff --cached --check` 通过，提交信息描述问题、变更和验证结果。

## 4. M1 工作包

### WP1 应用协调层

- 睡觉只推进一次游戏日。
- 农田与畜牧使用同一目标日期结算。
- 任一结算失败时恢复时间、农田和畜牧快照，并返回稳定错误码。
- 测试覆盖成功、重复日期、无效状态和回滚。

### WP2 默认内容

- 定义 3 种作物、3 种鱼、5 个配方、商店物资、1 只鸡和 3 至 4 名 NPC 的稳定 ID。
- 所有配方输入均能由种植、畜牧、钓鱼或商店获得。
- 启动前校验种子、产物、商品、鱼和配方引用的物品 ID。

### WP3 Unity 适配

- Bootstrap 显式创建服务对象图并向场景控制器提供窄接口。
- 玩家移动组件只处理输入和刚体速度。
- 交互探测器只选择 `IInteractable` 并触发应用用例，不包含领域规则。
- 当前阶段允许使用调试 HUD，不把临时 UI 结构写入领域程序集。

## 7. M4 验收结果

- `GameSaveCoordinator` 在同一逻辑时点捕获世界种子、时间、全部角色与商店经济状态、农田和畜牧快照，并在恢复前校验 schema、主体、资产和跨模块日期一致性；恢复中任一步失败会回滚五个状态边界。
- `JsonFileSaveStorage` 当前写入独立 schema v2 JSON 数据包，并把 schema v1 确定迁移到默认玩家和默认商店。保存时在目标目录写入并复读验证临时文件，再原子替换正式槽位；空槽、截断或结构损坏、未来版本和无效载荷返回稳定且可区分的结果，失败不会破坏上一份有效存档。

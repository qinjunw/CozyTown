# 决定经济状态存档迁移与存储方案

- Parent: [守恒型角色—商店经济重构](../map.md)
- Label: `wayfinder:grilling`
- Status: Closed
- Assignee: `qinjunw`
- Tracker: https://github.com/qinjunw/CozyTown/issues/10

## Question

现有 schema v1 应如何迁移到包含角色和商店状态的新版本，静态目录与运行时状态分别保存在哪里，读取失败和跨模块恢复如何维持原子性？

## Options

1. **版本化 JSON schema v2 与显式 v1 迁移（推荐）**：静态物品、价格和补货规则留在只读内容定义；动态角色资产、商店资产、实际库存与刷新状态进入完整快照。v1 的顶层背包和钱包迁入默认玩家，缺失的商店状态按确定规则建立。
2. **schema v2 但不迁移 v1**：实现较少，但现有存档无法继续读取，并违反已接受的存档版本化规则。
3. **改用 SQLite**：能提供索引和增量事务，但当前数据量、查询与并发需求没有达到引入阈值。

## Resolution

采用选项 1，继续使用单槽 `main` 的版本化 JSON 完整快照，并把当前写入版本提升为 schema v2；不引入 SQLite。

- 静态物品定义、价格和补货规则留在只读配置中，不进入存档。
- 动态快照保存世界种子、全部角色的稳定 ID/背包/钱包、全部商店的稳定 ID/实际库存/钱包/最后刷新日/补货算法版本，以及现有时间、农田和畜牧状态。
- 新游戏的世界种子生成一次后持续保存；测试注入固定值。
- v1 顶层背包和钱包迁入 `character.player`。
- v1 迁移创建 `shop.town.general`，初始资金为 10,000；使用固定 legacy seed 生成存档当日库存并标记当日已刷新。
- 加载按“解析、逐版本迁移、校验完整候选状态、一次发布”执行；任何失败都不改变当前游戏状态。
- 未来版本、非法或重复 ID、负数量和跨模块日期不一致均被拒绝；磁盘写入继续采用临时文件验证后替换。

完整决定记录见 [ADR-0012](../../../adr/0012-economic-save-schema-v2-and-v1-migration.md)。

# NPC Agent 接入审计与选型建议

- 审计日期：2026-09-05。
- 代码基准：`7bfe65e`；本轮只增加研究文档和决策地图，未启动 Unity 或调用真实模型。
- 用户本轮已确认：首版结合人设、游戏状态和对话记忆回答，并使用只读查询工具。
- 本文中的框架、部署和记忆生命周期方案是研究建议，尚未成为实施 ADR。
- 决策地图：[Assess in-game NPC agent readiness and runtime options](https://github.com/qinjunw/CozyTown/issues/23)。

## 1. 原始目标与当前位置

项目最初用于补充游戏方向简历，重点展示 AI 应用与模块化工程能力。确认后的游戏范围是一座小镇中的生活模拟：种植、养鸡、钓鱼、烹饪、交易、NPC 对话和单槽存档。现有 PRD 保留了 3 种作物、1 种畜牧动物、3 种鱼和 5 个配方，并将面试官可核查的代码、测试和 AI 评测列为交付依据。[产品目标与范围](../../PRD.md)

当前玩法与持久化为 NPC 提供了可查询的真实世界状态。角色与商店各自拥有资产，普通买卖转移双方物品和金币；生产和每日补货有明确的资源来源边界。继续接入只读 NPC Agent 可以直接使用这些事实，不需要先增加更多玩法。[领域语言](../../../CONTEXT.md)、[经济所有权决策](../../adr/0010-character-shop-economic-ownership-and-atomic-trade.md)

| 能力 | 当前证据 | 对接入的意义 |
| --- | --- | --- |
| 玩法、经济和存档 | 可玩闭环，schema v2，稳定角色/商店身份 | 世界事实已有来源 |
| NPC 内容与展示 | 四名独立 NPC，人设、专属回退、稳定 ID、场景 UI | 可以复用角色内容与入口 |
| AI 客户端边界 | HTTP(S) 请求、文本/标签校验、超时回退、界面关闭取消 | 已有可替换适配边界 |
| Agent 循环与记忆 | 尚无；近期事件和记忆数组固定为空 | 不能把现有字段当作已实现能力 |
| 真实服务和作品集证据 | 默认端点为空，未找到代理服务、固定模型评测或诊断汇总 | M5 仍有实质交付内容 |

历史测试 XML 为 2026-09-02 的 EditMode `279/279`、PlayMode `35/35`；本次只核对历史结果。PR [Implement conserved economy and validated MVP content](https://github.com/qinjunw/CozyTown/pull/12) 在审计时仍未合并。Scene-01 的人工场景验收也没有完成记录。测试通过、分支实现完成、人工体验通过和真实 AI 评测是四种不同证据。[详细现状审计](current-readiness-audit.md)

## 2. 接入首版 Agent 的缺口

| 缺口 | 最小补齐内容 | 验收行为 |
| --- | --- | --- |
| 人工场景门禁 | 按既有 Scene-01 检查运行画面与交互并记录结果 | 记录版本、分辨率、操作者和未决问题；通过后才能启用真实 AI |
| 玩家输入与请求契约 | 提问输入、发送/取消，以及稳定会话和请求关联字段 | 问题能够进入代理；关闭或切换对话后旧响应不覆盖当前界面 |
| 世界只读上下文 | 从应用用例投影背包、商店库存/报价、配方与生产状态 | NPC 使用实际持有数量、当日库存与配方，查询不改变状态 |
| 有界 Agent 服务 | 模型调用、工具注册与参数校验、循环预算、响应校验 | 工具次数或总时限耗尽后结束并回退，不继续后台无限调用 |
| 对话记忆生命周期 | 按玩家、游戏运行/读档分支与 NPC 隔离对话记录 | 不串 NPC；失败或未展示回复不成为已发生对话；读档后不泄露未来记忆 |
| 评测与观测 | 固定样例、trace、模型/提示版本、耗时、用量、回退分类 | 能解释一次回答用了哪些事实/工具，以及失败时发生了什么 |

当前 `GenerateAsync(npcId, cancellationToken)` 没有玩家文本；`CreateDialogueContext` 只投影身份和时钟，关系值为 0，近期事件与记忆为空。现有客户端关联 ID 没有穿过 HTTP 请求成为代理 trace。仅安装 SDK 或填一个模型地址不能补齐这些差距。[代码与文档证据](current-readiness-audit.md)

跨重启记忆不是会话内记忆的前置条件。建议首个可验收切片由游戏进程持有有界多轮对话记录：关闭对话面板保留，成功读档后开启新的运行时间线、清空旧对话及派生摘要，取消旧请求并拒绝其迟到结果；新游戏或重启不继承记录。若要求读档恢复当时的记忆，应另行补充快照/存档契约；`worldSeed` 与游戏天数都不足以唯一标识存档分支。上述生命周期仍需在实施前确认。[运行设计与存档边界](runtime-options.md)

## 3. 框架比较与推荐

推荐先验证 **Pi 的 `@earendil-works/pi-agent-core` + `@earendil-works/pi-ai`，由一个游戏专用 Node 服务封装**。本地已安装的 0.84.4 提供自定义工具、模型流、停止钩子、取消与事件；服务只注册游戏只读查询。编码 CLI 的文件、终端和扩展加载不是 NPC 的能力入口。[本地代码核验](local-framework-inventory.md)、[Pi Agent 文档](https://github.com/earendil-works/pi/tree/main/packages/agent)

| 候选 | 已核实的适配特点 | 当前判断 |
| --- | --- | --- |
| Pi Agent Core + Pi AI | 可直接嵌入的模型/工具循环组件，本地已有同版本依赖 | 首选候选；项目自己管理事实、记忆、预算和输出协议 |
| Pi AI + 小型显式调用流程 | 单次回答或一轮查询可以用少量编排完成 | 作为无工具/固定流程评测基线；需求固定时也可独立采用 |
| DeepSeek Harness | 本地有独立官方源码；插件化和多服务能力可用，旧版本 SDK 有取消限制 | 适合插件平台研究，当前四名 NPC 的装配成本高于 Pi 子集 |
| CodeWhale | 本地存在不同来源/版本的编码代理入口 | 适合作为项目开发工具，当前缺少选择它作为 NPC 核心的理由 |
| LangGraph | 显式状态图、检查点、恢复及中断能力 | 出现长任务恢复、人工审批或复杂分支后复评 |

DeepSeek 模型和 DeepSeek Harness 是两项独立选择：模型提供商不决定必须使用哪一种编排框架。框架支持某提供商也不证明该模型在本项目上达到人设、延迟或结构输出目标；这些需要同一评测集验证。[框架一手资料比较](runtime-options.md)

本地 Node 为 `v24.15.0`，已有 Pi 依赖可供后续隔离原型核验。CLI 安装状态不能代替项目依赖锁定、代理进程启动、协议往返和模型效果验证。本次没有执行安装或计费调用。

## 4. 适合当前体量的模块形状

```text
Unity：玩家输入 + 本轮世界只读快照 + 已确认对话
    → 一个 NPC 对话应用入口
    → HTTP 代理：NpcAgentService
         人设/记忆裁剪 → Pi 模型与工具循环 → 输出校验
         只读工具查询同一个请求快照
    → text / emotion / action
    → Unity 再校验、展示或使用 NPC 固定回退
```

Unity 继续掌握权威游戏状态。首版代理可以查询请求内同一时点的有限快照：`query_backpack`、`query_shop`、`query_recipes`、`query_farm` 是候选工具名。时间与角色身份可直接提供，无须为了调用次数把每个字段都变成工具。工具注册表和参数校验决定查询范围，提示词只负责指导语言表现。

例如玩家问 Mina“我这些材料能做什么，缺的东西今天买得到吗”，Agent 查询材料和配方，再查询当日实际商店库存，最后解释可做的料理与缺料。商店报价目录中的物品可能当前没有库存，不能把“存在价格”说成“店里有货”。一次提问中的工具结果都使用同一快照；下一次提问重新取得游戏事实。

四名 NPC 共用服务和模型适配，各自拥有独立人设、允许知识与对话记录。请求在玩家提问时触发；不需要四个常驻编码进程。模型生成的旧叙述不覆盖新快照中的数量与价格，记忆条目也不能升级为新的系统指令或权限。

对外保持一个对话入口；SDK 类型、工具分派、重试、预算和会话存储封装在服务内部。这个边界比让 Unity 逐个调用框架的 session/tool/trace API 更符合当前“深模块、浅接口”的方向。[模块边界](../../adr/0005-unity-adapter-boundary.md)

## 5. 建议的验证顺序

1. 完成人工 Scene-01 记录；同步当前文档摘要中的 UI、经济和测试描述。
2. 用假模型跑通一个 NPC 的“提问—快照—只读工具—合法回答/回退”，覆盖取消和预算耗尽。
3. 增加多轮记忆；测试两个 NPC 串话、重复请求、关闭后迟到回复、读档回退后的未来信息隔离。
4. 扩展至四名 NPC，并验证同一工具结果产生符合各自人设的回答。
5. 在已通过场景门禁后接入真实模型；比较无工具基线与工具版本，再交付评测和演示。

自动化应比较 AI 查询前后完整游戏状态，确认没有资产、时间或生产变化；用失败替身验证工具不存在、非法参数、超时和预算上限。至少 30 条固定样例沿用 PRD，并新增工具选择和记忆隔离用例。记录原始计数、结构有效率、人设一致性、事实矛盾、回退原因、P50/P95 和 Token/费用；30 条样例不能独立证明生产流量下的长期可靠性。[验收指标](../../PRD.md)

最有展示价值的演示是：相同 NPC 记得本轮交流，能根据实际游戏状态回答；玩家改变库存后，它在下一轮给出更新后的答案；服务断开时游戏仍可操作。这些行为能把现有游戏工程转化为可复核的 AI 应用证据。

## 6. 后续决策条件

- **实施前**：确定首版模型/部署方式、循环与总时限预算、对话是否跨读档/重启保留。
- **出现记忆规模证据时**：再评估全文索引、向量检索或数据库；四名 NPC 的短对话不构成默认引入条件。
- **出现长流程时**：再比较图式运行时的检查点恢复收益。
- **确认 AI 动作玩法时**：复审 ADR-0002，另行定义命令候选、主体授权、幂等、版本校验、事务与存档影响。
- **内容派生索引增加时**：可以独立消除配置重复校验/Catalog 重建；它不是只读 NPC 接入的技术前置。

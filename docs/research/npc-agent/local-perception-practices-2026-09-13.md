# NPC 局部观察：游戏感知与环境注入的一手实践

- 核查日期：2026-09-13；项目讨论基准：`d8005cdb8284a1563f0288c555683589a7933a6a`。
- 文档类型：来源核查与设计候选。项目输入为四名居民、纯 C# Runtime、已有世界时钟、位置、日程与经济系统，以及当前 `inspect_location` 只返回地点 ID 和可达性的约束；这些输入由本轮任务提供，本文件不构成对该提交的独立代码审计。
- 关联研究：[NPC 环境事实、资源判断与有效上下文](environment-grounding-2026-09-13.md)。本文保留六个直接相关的官方来源；没有安装 SDK、运行其示例或调用真实模型。

## 1. 资料够不够指导实现

**已足够指导最小切片的工程机制，尚不足以直接充当 CozyTown 的验收规格。** 可借鉴的机制是：游戏侧提供对象语义，以观察者的实际位置筛选；分别计算距离、遮挡和可达性；分开保存当前观察与历史已知；将当前数值替换更新，将发生过的事件追加记录；在行动执行时重新检查对象状态。证据和各自局限见下表。

仍须由项目确定三个约定：区域感知对外叫什么、哪些对象具备资源或交互语义、哪些动态属性能被角色直接知道。它们属于项目内容契约，需要用本地场景和验收样例确定。下文给出可执行候选，供主规格选择，未冻结产品行为。

## 3. 可执行取舍

本节是基于上述机制及项目规模的设计推论。来源说明有哪些分离点，具体参数和玩法含义仍由 CozyTown 定义。

### 实际位置与目标地点

观察范围应从本次快照中的实际位置计算。目的地只表达当前意图；角色还在路上时，不能取得目的地的当前对象状态。到达事件和空间位置确认后才更新所在区域。这个分离与 S1 的接收位置以及 S3 的“申请目标—接近—到达使用”流程一致；并非这两个 API 直接规定了 CozyTown 的区域规则。

若模型响应期间 NPC 已经移动，旧响应不能使目的地观察提前生效。宿主应在应用会改变行为的结果前，检查相关位置或环境版本是否仍适用；由项目现有决策调度规则决定丢弃、刷新还是重新决策。

### 逻辑区域、距离与视线

| 候选 | 能表达的边界 | 必须处理的例子 | 对四居民起步的取舍 |
| --- | --- | --- | --- |
| 仅逻辑区域 | “当前在这个场所，知道此处公开概况” | 大区域另一端、屋内外、隔墙物体不一定能看见 | 适合公开地点概况；字段和台词采用“所在区域/附近”，不要自动称为“眼前看见” |
| 实际位置加距离 | 连续移动时的附近对象 | 隔墙近物、隔河近物、不同楼层可能仍被选中 | 若要提供附近居民或对象，使用它做候选筛选；可达性仍单列 |
| 距离加视角和遮挡 | 按指定感知点、朝向和碰撞规则定义的视见 | 角色转身、细柱遮挡、物体中心被挡但部分可见、渲染裁剪 | 只有玩法需要这些差异时才增加；需 Unity 适配层提供检测结果和可视化调试 |
| 区域/距离生成候选，再对特定对象检查视线 | 公开场所概况与视觉细节可以有不同规则 | 同一区域的公开地标可知，遮挡中的动态状态不可知 | 是可扩展候选；首版可只实现已明确的部分，保留观察来源字段 |

S2 支持把这些测试分开。区域是一项产品抽象，本轮未找到官方证据证明它普遍优于视线；距离和视角数值也不能从来源直接照搬。若使用视线，测试点、阻挡层、室内外和楼层必须进入内容配置，否则不同美术模型会改变知识边界。

### 对象语义、可采集性与动态数量

只把有稳定 ID 和已声明语义的对象纳入可查询事实。一个对象可以同时包含外观描述与玩法能力，但两者应分别声明。装饰草丛可以提供“有绿色植物”这一内容事实；只有已配置产物、采集规则及运行状态的对象，才能提供“可采集香草”的玩法事实。对象未配置这项能力时应按未支持或未定义处理，不能让名称识别补出采集能力。

S3 的定义、运行实例和交互流程支持这种分离，但资源数量仍需 CozyTown 的经济或资源系统提供。建议按属性决定精度：本人库存可读精确量；公开货架按玩法约定显示量；水下鱼群可只表达已配置的资源种类或未知数量。宿主知道池里有几条鱼，并不自动授权 NPC 获得这个数值。

行动目标应同时通过语义、当前使用条件、位置或可达性检查；采集或交易提交时再读最新数量。选择了目标、发出采集意图、到达对象和实际增加库存，应分别形成结果。

### 当前、历史、未知与不可见

建议分别表达“本次观察”“上次观察”和“当前未知”，并保留观察时间、来源和范围。S1 已分开当前感知和历史感知；该机制支持保留旧知识，但不保证旧状态仍然成立。

- **已知为零**：允许且足够完整的本次查询确认数量为 0。
- **未测量或未授权**：对象可知，但数量未知；不输出伪造的 0。
- **当前不可观察**：保留合法历史记录，当前状态不继续作为实时事实发送。
- **结果被裁剪**：标明列表不完整；未列出不能推断不存在。

“不可观察”作为宿主的内部排除原因，不应顺带告诉 NPC 原本未知的隐藏对象 ID 或位置。可以声明观察覆盖范围有限；只对角色本来就知道的对象表达“现在无法确认”。S5 的注册表会因组件禁用而移除对象，也说明“返回清单中没有”本身不足以证明世界中不存在。

### 事件刷新与决策唤醒

采用两层更新：游戏状态和观察缓存按相关变化失效；模型只在下一次需要决策时读取快照，必要事件才提前唤醒。四名角色可以先在决策入口重算小集合，并对位置、区域进出、可观察对象状态变化和交互结果设置失效标记；是否需要后台轮询由漏事件和性能测量决定。

S6 支持把当前 state 与已发生 event 分开并合批，也把静默更新与回应触发分开。可迁移的是这两个分离点，不是其具体网络等待时间。例：“鱼架余量 2→1”替换当前量；“我刚取走一条鱼”追加本人已确认经历。离开范围后应撤销当前量的有效性，避免历史事件或旧 state 继续充当实时观察。

宿主可以因全局变化刷新内部缓存，但只把角色获准观察的变化送入其上下文或用于可见的唤醒理由。否则另一居民的隐藏库存变化也可能通过突然说话、选项消失或更新内容泄漏。

Convai 的默认对象属性广播不能直接复用为这个策略：S5 明确投递到每个已连接角色。若借鉴其数据结构，应在进入每角色上下文前完成筛选；本项目没有因这项研究而需要引入该 SDK。

## 4. 转成实现规格前需要补齐的项目输入

| 需要确定的输入 | 最低可审查产物 | 对应可观察验收 |
| --- | --- | --- |
| 位置和区域如何关联 | 说明位置来源、区域边界、边界上与行进中的归属 | 去池塘途中仍只取得实际位置附近事实；到达后更新 |
| 观察范围用哪种含义 | 区域、距离及可选视线规则，注明哪些事实适用 | 同区远物、跨墙近物、不同楼层与转身各有明确结果 |
| 首批对象与资源语义 | 少量对象的 ID、类别、公开描述、能力和数值来源 | 装饰植物不产生采集能力；明确资源节点可返回玩法状态 |
| 属性披露权限与精度 | 本人、公开、历史、未知的字段样例 | 看见池塘仍不知道鱼的精确量；看不见另一居民库存 |
| 新鲜度与列表覆盖 | 观察时间、完整范围、裁剪标记及失效条件 | 旧数量、不可见、裁剪缺项、完整查询得到零互不混淆 |
| 动态更新与执行重检 | 会影响当前事实的事件清单及响应过期规则 | 生成期间对象移走或最后一份被取走，旧动作不能产出资源 |

先用确定性输入验证这些边界，再以同一事实快照比较模型台词与动作。宿主筛选正确、上下文送达、模型正确使用事实和动作执行成功是四个不同结果，应分别记录。六个来源都不能替 CozyTown 给出模型幻觉率、合适观察半径、Token 预算或最佳刷新频率。

# NPC 事实表达：受控语义、自由台词与来源边界

- 核查日期：2026-09-13。
- 状态：研究建议，供局部观察与事实表达规格讨论；本文未采纳玩法决策，未修改运行代码，也未调用模型服务。
- 输入：[环境事实研究](environment-grounding-2026-09-13.md)、[上下文对照实验](../../verification/npc-grounding-experiment-2026-09-13.md)、[候选字段校验与一次纠正验证](../../verification/npc-candidate-validation-2026-09-13.md)。
- 范围：游戏已经持有结构化事实时，如何约束 NPC 说出的含义；不以开放互联网检索、扩大上下文或模型排行榜代替本游戏验证。

## 1. 结论与本地证据

**关键事实需要从宿主认可的语义记录生成整句，才能在规定范围内给出确定性约束。** 如果模型仍能返回任意自然语言，即使附上合法 `factIds`、通过 JSON Schema 或经另一个模型批准，也不能据此保证没有额外断言。可让模型选择话题、语气和发言意图，再由宿主核验事实、来源、时态及听众权限；是否对全部台词采用这一路径，仍是表达自由与可验证程度的玩法选择。

本地对照实验中，增加事实与未知提示没有消除无依据台词。后续 12 轮纠错矩阵的初始化、资产和恢复检查均通过，但有候选提到未经输入证实的“北岸野蒜”；该候选因过期未执行，不能说这句话已展示给玩家。报告明确记录尚无环境事实校验。动作参数合法、资产变更合法、最终展示的台词有依据，应继续分别验收。[上下文对照结果](../../verification/npc-grounding-experiment-2026-09-13.md)、[纠错矩阵结果](../../verification/npc-candidate-validation-2026-09-13.md)

本文假定库存、交易结果和场景对象存在可由宿主读取的权威记录；尚未被玩法建模的“鱼很新鲜”“我早上采过野蒜”等细节不能当成已有事实。下面的结构与流程均为候选，四名 NPC 的规模本身不构成引入图数据库或额外模型服务的理由。

## 3. 为什么 `factIds` 不等于台词有依据

假设宿主提供 `f1 = Ren 当前持有一条鲤鱼`。以下候选的 ID 可以合法，台词却包含未被 `f1` 支持的来源、时间和资源位置：

```json
{
  "factIds": ["f1"],
  "text": "我今早在北岸钓到这条鱼，那里还有野蒜。"
}
```

引用检查至少有两个方向：**所引用证据是否支持这项断言；所有需证据的断言是否都有支持。** 只核对 ID 存在、数量字段正确或地点名在词表里，无法覆盖新增的“今早”“亲眼”“又”“已经”等含义，也无法防止把 Ren 的观察换成 Sora 的经历。结构化输出的限制可由官方材料核对；上述反例由字段合同直接构造。[Structured Outputs 的值错误说明](https://openai.com/index/introducing-structured-outputs-in-the-api/)

语义帧可显式包含 `speechAct`、`factId`、`perspective`、`timeMode` 和 `styleId`，但这些字段也要由宿主验证。模型不能仅凭填写 `knowledge: known` 把猜测提升为事实。若最终整句由模型自由改写，帧与句子的一致性又成为概率性语义检查；若模型只能选择已验证的帧和模板变体，宿主可直接限制该句的主语、数量、来源及完成状态。

## 4. 事实、知识和允许说出的内容

建议使用以下信息合同，不把它们压缩成一个可信度分数。世界记录成立、角色知道、允许告诉当前听众，是三个独立条件。

| 字段或状态 | 建议含义与约束 |
| --- | --- |
| 命题 | 对象 ID、谓词、值、单位、肯定／否定；显示名称从内容配置读取，不由模型创造资产或地点 ID |
| 来源 | 宿主状态、直接观察、成功结果收据、内容设定或他人声明；个人观察须绑定实际观察者 |
| 时间 | 分开记录事件／观察发生时间与角色得知时间。当前快照带相关状态版本；历史观察保留原时刻，不能自动当作现在仍成立 |
| 知识状态 | 已知成立、明确已知不成立、未知；互相冲突的声明分别保留，并表示尚未确认。未返回和空列表只有在声明查询覆盖完整时才可能支持局部否定 |
| 范围 | 地域、对象类别、观察条件、查询是否完整及是否截断。看见植物不证明能采集，看见池塘不证明其中鱼的种类或数量 |
| 权限 | 谁可以得知，谁可以对哪些听众转述。读取时过滤一次，发表时再次按听众检查；记忆和详情查询沿用同一规则 |
| 支持链 | 原始事件／观察 ID，转述者、原说话者与时间；生成的总结不得覆盖原证据 |

时间设计借鉴 Graphiti 的事件时间、入库时间和来源关联；其自动冲突解析不用于本游戏权威状态。尤其不能把远处尚未被 NPC 观察到的变化，直接写进该 NPC 的已知事实。[Graphiti 的时间与来源机制](https://arxiv.org/html/2501.13956v1)

下列转换应在规格中明确禁止或单独授权：

- **未知推成不存在**：只观察到池塘东侧，可以说“我还不清楚北岸有什么”；不能据列表缺项说“整个池塘没有野蒜”。完整否定也必须保留其范围与时间。
- **传闻推成亲历或真相**：听见 Ren 说有鱼，只支持“Ren 刚才说他有鱼”。再次转述应保留原来源，不能因为重复次数增加就提升为宿主确认事实。若玩法允许谎言，应记为“这个人作出了该声明”，另行定义信念变化。
- **过去推成当前**：“昨天看见一条鱼”不支持“现在还有一条”。宿主确认昨天的观察记录与宿主确认当前数量是不同读操作。不得根据私有远端变化，暗中让历史观察句失效并泄露变化。
- **计划推成完成**：“想做鱼汤”与“做过鱼汤”分别需要意图和成功结果依据；准备、邀约、接受、尝试交付、实际交付不能共用完成话术。
- **标签代替证据**：“可能”“听说”“我觉得”不是添加任意地点、物品和经历的通行证。若允许推测，推测对象、已知前提和表达规则应有定义；“听说”需要实际听闻记录。
- **个人表达夹带事实**：“谢谢你又送来这么新鲜的鱼”同时断言重复赠送和新鲜度；“我喜欢鱼汤”若是稳定人物偏好，应来自人物设定或已允许更新的偏好记录。不能只按句子开头判为情绪而免检。

隐私检查也要覆盖派生值和选项：向 Sora 隐藏 Ren 库存，却根据该库存移除某个话题或返回专有错误码，仍可能泄露供货信息。可用两个“仅改变未授权状态”的世界比对投影、候选、公开诊断和可见行为；该比对可发现泄漏通道，但有限用例不能证明整个系统没有信息侧漏。这是根据角色权限合同提出的测试方法。

## 5. 三种表达方案的取舍

| 方案 | 可约束的部分 | 代价与残余问题 |
| --- | --- | --- |
| **语义帧＋宿主渲染整句** | 宿主验证句型、事实、视角、时态、听众权限，再填入宿主值。对完整受控句的命题可给出相对事实快照的确定性约束 | 需要编写和审阅句型；表达范围有限。模板中的预设含义、错误数据、失效投影和实现缺陷仍会造成错误，不能称为对整个游戏真相的无条件证明 |
| **关键事实句受控＋开放表达** | 数量、地点、来源与完成状态可以限定在受控句；人格表达空间较大 | 任意开放文字仍可能带入事实、改变前句含义或暗示未授权信息。整段只能按统计评测报告风险；若要求全句可验证，开放部分也必须限制为已审阅变体 |
| **自由生成＋逐断言验证器＋有界修订** | 更广的语言变化；可用证据片段对齐、蕴含检查和来源检查找出错误，失败时回退 | 断言抽取、上下文蕴含和修订均可能漏检；增加调用与延迟。失败回退只约束被发现的错误，漏检仍会放行，修改后也可能引入新断言 |

“先选依据再生成”可作为第三种方案的候选，但论文的多阶段调用不能直接套用现有紧张的 NPC 决策预算。[Attribute First 的方法与限制](https://aclanthology.org/2024.acl-long.182.pdf) 形式求解器也不会自动消除这一缺口：若它拿到的自然语言翻译漏掉了“野蒜”或把“昨天”解释成“现在”，对翻译结果的证明不能证明原句。[AWS 的翻译与未覆盖内容说明](https://docs.aws.amazon.com/bedrock/latest/userguide/automated-reasoning-checks-concepts.html)

## 6. 适合四名 NPC 的最小候选

本节建议先比较一个有限事实域，不要求引入新记忆平台或更换模型。建议事实域为本人资源、已确认会面阶段与交付、当前已实现的局部观察、人物已有设定；尚未实现的植物品质和生产经历保持未知。

1. **宿主形成每名角色的事实视图。** 直接从已有状态和事件装配少量记录，按事件、角色知识和听众权限筛选，并附查询覆盖说明。事实预算的具体条数由实际请求测量决定；必要交易事实不能因截断而消失。
2. **模型一次选择发言意图和证据。** 首版可比较 `report_observation`、`report_result`、`relay_statement`、`ask`、`express_preference`、`express_intent` 与 `acknowledge_unknown` 等有限意图。它们只是讨论名称；只有当前玩法支持的意图才进入实现。
3. **宿主核对后渲染关键句。** 验证 ID 所属视图、语义类型、时态、事实版本和听众权限；物品名、数量、来源名字和结果动词取自宿主。允许角色选择有限语气变体，但每种变体须审查隐含前提。是否添加自由尾句，按上一节的保证差异单独选择。
4. **过期和失败走确定回退。** 自己当前资产等可重读字段在发布前检查；历史观察仍按其原时刻表达。预算内不能完成检查时，使用与该意图相符的已审阅回退或跳过该发言，不另起无上限验证循环；存在事实且可以回答时不得一律回退为不知道。
5. **只写入有来源的记忆。** 发言记录可证明“某人说过 X”，不能证明 X 已发生。世界状态和完成事实由宿主事件更新；传闻、个人信念与真实事件分开。四人跨日、存档和读档应保持这些来源关系。

需由玩法讨论决定的选项是：局部观察按区域还是视线、已观察信息保留多久及怎样表达、哪些资源可经交谈共享、是否允许错误信念或主动说谎、哪些台词必须完全受控。本文不把这些选项预设为用户已接受的方案。

## 7. 验证方法与验收边界

先验证投影和受控表达的确定性行为，再比较真实模型的表达质量；后者需另行预登记调用预算与参数。复用现有坏句和反事实请求，不把旧矩阵的资产通过数计作台词验证通过数。

| 测试簇 | 最小反例与应观察结果 |
| --- | --- |
| 证据匹配 | 正确 `factId` 配错误句、引用遗漏、错角色、错单位；受控路径拒绝不合合同的帧，开放路径记录漏检和误拒绝 |
| 存在／未知／不可采 | 明确无资源、未观察、列表被截断、装饰性植物四种情况；检查否定范围及是否凭空提出采集 |
| 时间与版本 | 昨日有、当前已变化；延迟返回期间本人资产变化；远处私有变化；检查当前话术、历史话术和投影是否分别处理 |
| 来源与传闻 | A 观察后告诉 B，B 告诉 C，D 未听见；C 保留来源与历史时间，D 不凭空知道；第二次传述不能升级为确认事实 |
| 结果阶段 | 计划、接受、尝试失败、成功收据；只有成功阶段能使用完成表达，未承诺时不能出现确定承诺 |
| 隐私与隐含前提 | 双世界仅改对方私有库存；比较字段、话题候选和诊断；审查“又、终于、照旧、亲眼”等额外含义 |
| 可用性与人物表达 | 明知可答却始终不知道、套话重复、人物风格趋同；单独评估回答是否推进当前交流 |
| 长期与恢复 | 四人跨日、读档、旧世界 ID、重复事件、同名对象；事实来源、时间和权限不能因恢复而丢失 |

真实模型可采用三个实验臂：同一事实视图下的自由台词；关键句受控且保留开放部分；完整受控句。若需要估计验证器收益，再单列自由台词加验证器，保持初始事实与可谈内容一致。不能把受控臂可说内容更少造成的变化写成模型推理改善。

台词按最小事实断言标注，分别记录已支持、与已知事实矛盾、无依据、来源／时间错误、未授权披露；明确假设、提问和纯表达另列，不自动计错。以“含至少一项问题的台词数／台词总数”和“问题断言数／事实断言总数”同时报告，另报可答时有效回应率、未知时适当保留率、回退率、事实覆盖、人物区分和重复程度。记录最初候选、拒绝、修订与实际展示文本，避免只评成功输出。

评审应隐藏实验组，保留原文、来源和分歧，由人工抽样复核；自动评审的漏检和误拒绝单独估计。FACTS 的“任务满足度与 grounding 分开”可借鉴，LongMemEval 的更新、时间及未知用例可转为本地确定场景，但其现成分数不能当成本游戏验收标准。[FACTS 方法](https://deepmind.google/blog/facts-grounding-a-new-benchmark-for-evaluating-the-factuality-of-large-language-models/)、[LongMemEval 初版](https://arxiv.org/abs/2410.10813)、[V2 的动态状态与前提意识](https://github.com/xiaowu0162/LongMemEval-V2)

确定性路径的验收目标可定义为：规定事实域内，未经验证的语义帧不能发布，所有已审阅句型的槽位、来源和时态符合合同，权限与过期反例通过。自由台词路径只能报告规定样本中的错误率及不确定性；样本中零错误仍不能证明长期零编造。本轮仅完成来源核查和方案推导，以上试验均未执行。

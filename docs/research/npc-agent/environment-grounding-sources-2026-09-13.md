# NPC 环境事实与行动约束：一手资料核查

核查日期：2026-09-13。关联研究：[调研 NPC 环境事实与行动可行性上下文](https://github.com/qinjunw/CozyTown/issues/64)。范围为环境信息注入、角色观察、行动可行性、执行反馈和上下文组织；未安装下列 SDK，也未调用其服务。产品文档证明接口契约，论文结果仅适用于原实验；二者均不能证明 CozyTown 的可靠率。

## 1. Convai：环境描述与动作能力分别声明

官方 Connect API 将 `dynamic_info`、`scene_description` 和 `action_config` 分开：前两者提供动态信息与场景描述；后者列出动作、对象和人物，用于语义动作及目标校验。仅出现在场景描述中的物体不会自动成为动作目标。会话中可通过 `context-update` 替换语义动作契约。[Connect API](https://docs.convai.com/api-docs/api-reference/core-api-reference/live-apis-beta/connect-api)

Unreal 的 `Convai Environment` 另提供对象、人物、动作的增删接口；主交互角色也可用于 NPC 之间的对话。这说明场景接入仍需要游戏侧维护清单。[Environment 接口](https://docs.convai.com/api-docs/plugins-and-integrations/unreal-engine/blueprints-reference/convai-environment)

限制：Connect 页明确把 Actions v2 工具协议标为候选预览，文档出现字段不代表已经生产可用或已有 SDK 发布。页面没有提供减少环境编造的实测比例。

## 2. Inworld：运行时数据经节点构造成模型输入

所读 Node v0.8 文档用 `ProcessContext` 数据存储在节点间读写数据，并由自定义节点通过 Jinja 将输入变量生成提示词，然后调用 LLM。它展示的是可由开发者控制的数据注入管线。[Using Context](https://dev.docs.inworld.ai/node/templates/process-context)

限制：该示例生成角色自我介绍，不能据此宣称 SDK 自动读取 Unity 场景、同步库存或校验环境事实。对 CozyTown 的可迁移部分是先从游戏状态构造上下文，再交给模型；自动感知和资产约束仍需另行实现。

## 3. NVIDIA ACE：应用管理上下文与存档

ACE Agent 4.0 区分键值 `Context` 与角色 `ChatHistory`，提供 `/setUserContext`、`/getUserContext` 等接口；退出游戏时由游戏侧保存，加载时重新导入。[Managing Conversation Context](https://archive.docs.nvidia.com/ace/ace-agent/4.0/best-practices/manage-conversation-context.html)

限制：原文档地址现重定向至归档域名，属于历史方案，不能当作当前 ACE 产品推荐接口。它支持的结论是应用应控制事实状态和会话恢复；保存过往对话不会自动把陈旧观察变成当前事实。

## 4. Generative Agents：每个角色维护有限观察范围

2023 年论文 §5 使用区域—对象的包含树表示世界，将局部结构转换成文字。每个角色保存已知世界的子树；离开区域后观察可能过期，再进入时刷新。记忆检索综合相关性、近期程度与重要性。[论文 §4–5](https://arxiv.org/html/2304.03442v2)

限制：25 人小镇实验主要评价行为可信度；论文也报告记忆补写等错误，并允许模型生成对象状态变化。这不能证明精确经济事务的正确性。可采用局部观察与知识边界，资产变化仍需由游戏规则计算。

## 5. Voyager：状态、错误和结果形成反馈循环

Voyager 在 Minecraft 中根据角色状态选择任务，检索可执行技能，并把环境反馈、执行错误、当前状态送回模型修正程序。项目展示了材料不足和不存在的工具名称如何触发调整；自我验证由 GPT-4 判断任务是否完成。[作者项目页](https://voyager.minedojo.org/)

限制：这是研究系统，主要测探索、技术树和迁移任务；依赖多次提示与模型验证。它支持“错误应回传可操作的事实”，不支持将模型自我判断当作库存交易的最终裁决，也不提供多人实时游戏中的成本或稳定度保证。

## 6. SayCan：用状态可行性约束语言偏好

SayCan 将模型对技能有用性的评分，与技能在当前状态下可成功执行的价值函数结合，选择下一步行动。2022 年更新在 101 个机器人任务中报告 84% 的规划成功率、74% 的执行成功率。[作者项目页](https://say-can.github.io/)

限制：它使用学习到的机器人技能与价值函数；页面也承认环境反馈不完整的局限。游戏库存可直接用确定性规则计算前置条件，无需照搬机器人训练体系；原研究成功率不能移植到 CozyTown。

## 7. Anthropic：按需要提供信息并渐进加载

2025 年工程文章建议选择足够且相关的信息，保留轻量标识符，通过工具按需取回详细内容；也允许预先注入关键事实、再按需探索的混合方式。文章明确指出运行时探索增加延迟，工具设计不清楚会浪费上下文。[Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

限制：这是厂商工程经验，没有给出适用于所有任务的最佳长度。应用到 NPC 时，可先提供本人资源、当前会面与邻近对象摘要，再用受限查询加载细节；触发查询不需要人类输入自然语言。

## 8. Lost in the Middle：能装下不等于能正确使用

研究在多文档问答和键值检索中发现，相关信息的位置会影响表现；所测模型常在信息位于输入首尾时更好，位于中间时下降。[论文](https://arxiv.org/abs/2307.03172)

限制：该实验不是游戏任务，也未测试当前使用的 v4-flash，不能据此断言其具体衰减幅度。它提供了评测方法：固定事实内容，改变信息量、位置和干扰项，测模型是否仍正确使用关键字段。

## 对本项目的推论与验证条件

上述资料支持采用“权威状态投影—角色观察—相关上下文—受限行动—执行反馈”的组合。这里的投影指游戏侧按角色权限筛选事实，而非让模型自行补全世界。具体效果仍需本项目对照实验确认。

应区分未提供信息、错误使用已提供信息和无效动作三类失败。本人可见资源可提供精确数值及宿主计算的不足量；对方未公开资产保持未知。地点故事和对话可以作为记忆，但不得覆盖实时库存。资源与状态变更执行前再次检查，以处理生成期间发生的变化。

评测时分别比较局部事实、派生可行性说明与动作过滤，保留相同初始场景和调用预算。动作被过滤后无法生成，不能算作模型理解能力提高；应同时记录台词事实错误、不可执行提案、宿主拒绝、查询成本和完整交互完成率。

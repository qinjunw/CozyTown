## 装配与状态边界

沿用已授权的公开存读档、世界时间、人物控制器、身体与固定决策客户端边界。领域模块提供不可变的捕获数据和候选准备入口；全部候选校验完成后才提交。测试通过保存数据和恢复后的活动、位置、资产、台词及请求观察结果，不读取私有字段。

世界与会面保存活动身份、未消费事件原顺序、预约、有限经历、交付凭据及每日机会；准备新对象时不重新接受活动或执行交易。决策保存逻辑进度，使用新执行身份重新采样上下文；旧 Task 只继续占用真实并发槽，不能绑定到新决策。身体恢复路径、游标、受阻及重规划状态，不调用重新寻路代替恢复。

默认 Unity 游戏入口进入完整保存模式。该模式在四名居民、玩家或必要适配未就绪时明确失败，不能静默写部分数据。独立经济／生产用例保留显式旧格式能力，供原存档迁移及不包含人物的 Runtime 测试使用；它们不算完整快照证据。

## 切片顺序

1. 完整模式缺少适配时拒绝写入，保留原槽位；世界捕获不消费事件，候选恢复不改活世界。
2. 身体原进度恢复；进行中会面、交付和经历恢复；逻辑决策在新代次续接，原在途请求继续占槽。
3. schema v4 嵌套独立数据包、版本和配置校验；完整文件往返及旧版迁移。
4. 统一保存／加载提交边界、小数时间、玩家模态和首帧过滤；四人准备失败及提交后恢复失败。
5. 按 SC-01 至 SC-13 对照记录覆盖与限制，运行隔离 EditMode／图形 PlayMode、审查和发布证据。

每个新增公共行为先保留 RED 再实现；仅添加使当前行为通过的代码。三个模块可独立准备，Unity 运行由主代理串行执行。共享工作区的美术、农田及场景修改不进入隔离输入。确定性恢复验证使用固定客户端，本轮不需要真实模型或读取密钥。

# 实验入口移动连续性验证计划

对应[修复四人实验运行中的人物移动跳动](https://github.com/qinjunw/CozyTown/issues/108)。基线为候选 `89dd83718fa90c9d35e90d246e2e06dfb9fe5c14`，用户报告入口为 Agent Experiment → Fixed → 运行。验证使用固定客户端和录制响应，不调用提供方。

## 问题与实施边界

候选的自动运行每 0.5 秒推进一次世界；场景居民以 2 世界单位/秒移动，位置和步行动画只在世界提交时更新。这使一次提交的位移可达 1 世界单位。保留现有速度、路径、碰撞和存档权威位置；将新实验的自动运行细化为每 1/64 秒一次世界推进，手动“推进 1 游戏分钟”保持 0.5 秒增量。

每次推进继续使用既有 Session.Step，记录世界增量和实际秒表时间。调用预算仍为每分钟 16 次、并发 2；决策检查和回复交付机会随步长改变，因此不宣称新实验与旧实验产生相同请求或结果。新录制的输入和 Tick 数量约为原来的 32 倍，需测量代表性实验的导出体积。

回放按每条原始输入的游戏增量安排播放，不拆分旧输入。零增量和保存、读取、睡眠、完成操作仍按原顺序执行，并计入每帧最多 8 条输入的上限。旧录像保持原有离散视觉；新录像才能体现细分运动。暂停时清除播放等待余量，恢复不补暂停期间的世界时间。

## 步长调整依据

最初使用 1/60 秒，移动烟测通过，但 10,800 步实验在导出后无法严格回放。源轨迹与读回轨迹在 Tick 5436 的游戏时间分别为 900.73333333333335 和 900.73333333333323；该序列化差异约为一个双精度浮点相邻值间距。改用二进制精确的 0.5/32，即 1/64 秒；三分钟实验改为 11,520 步重新验证，严格比较不放宽。原失败记录保留在结果报告。

## 可观察验收

测试使用既有公开边界：实验窗口安装与 Launcher 操作、Session 保存/读取/导出/回放、场景居民位置及 SpriteRenderer。按一个失败用例、一个最小实现的顺序迭代。

| 检查 | 预期结果 |
| --- | --- |
| 正式场景从 Fixed 入口进入 Play，采样赴约人物每帧位置 | 基线出现接近 1 单位的跳动；修复后短帧内位移受配置速度和小步余量约束，存在持续行走而非静止假通过 |
| 暂停、恢复与手动一分钟 | 暂停不改变世界和人物位置；恢复不累计暂停时间；手动操作仍恰好推进一分钟 |
| 行走动画、分数时刻保存及连续读取 | 行走期间精灵帧切换；存档的身体、路径与场景位置一致；加载恢复检查点，运行后继续移动 |
| 新细步实验导出并在新世界严格回放 | 输入、请求、宿主结果与终态校验通过；原有预算仍约束派发 |
| 旧包和混合时长回放 | 旧包严格回放；0、1/64、0.5 秒输入按各自时长消费，操作不多等固定 0.5 秒，不把旧包加速 32 倍 |
| 非法下一输入时长 | 非有限或负值明确停止，不能无限等待 |
| 代表性较长固定实验 | 记录输入量、导出体积和完成/回放结果；既有相关回归通过 |

逐帧测试需记录采样帧数、时间间隔和最大位移。帧率不足时报告环境不足，不能据此声称连续性通过。完整测试计数、失败尝试及运行源码身份另写结果报告；原候选历史证据保持原样。

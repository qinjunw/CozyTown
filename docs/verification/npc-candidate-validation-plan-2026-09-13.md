# NPC 候选校验与一次纠正实施方案

- 票据：[校验邀约候选必填字段并限定纠错机会](https://github.com/qinjunw/CozyTown/issues/63)。
- 基准：`424d9a7d03a101a9ca9303b466b1966c63145b90`；分支：`codex/npc-candidate-validation`。
- 沿用地图已授权的 HTTP／JSON 编解码、决策调度、会面／经济状态及 Unity 居民公开测试边界，逐条 RED → GREEN。

## 合同

代理检查操作所需的顶层字段，禁止自动补齐或提升嵌套参数。版本必须是与请求一致的整数；操作必须在原允许集合中。计划 ID 与原请求精确相同，会面 ID 按非零 GUID 值匹配，地点属于本人已知集合。访问活动必须有合法活动类型及大于零、有限且不超过请求上限的数值期限；发言最多 240 个 UTF-16 代码单元。

缺少／空白计划 ID、缺少／空白地点 ID、缺少／畸形会面 ID、非法活动类型、非法期限和非法发言内容可以请求一次纠正。有效但错误的标识、未允许操作、版本不匹配、普通 JSON 解析失败、过大响应和提供方故障不纠正。错误码使用固定集合，错误正文不携带原始模型文本。

代理每次 HTTP 请求只调用一次模型。候选校验失败返回 HTTP 422、`error: provider.candidate_invalid` 和 `candidateErrorCode`，逐次痕迹保留错误分类。宿主识别该错误合同后决定是否纠正；其他 HTTP 故障沿用失败处理。

纠正仍是同一决策，保留原世界、修订、机会时间、允许集合与条款，`step` 增加 1，通过可选 `candidateErrorCode` 披露本次错误。最多一次纠正，与按需地点查询共用原总调用上限、全局速率和并发预算；总决策期限不重置。首次错误保留在结果和代理痕迹中，最终成功不覆盖失败记录。原 v1／v2／v4 请求增加兼容的可选反馈字段；系统提示词只补充如何读取该反馈的说明，独立冻结版本和哈希。

## 验证

固定测试覆盖各操作必填字段、布尔／浮点版本、嵌套参数、已知地点及计划／会面绑定；公开 HTTP 客户端验证 422 错误传递与响应大小边界。调度器验证同步和异步失败、第二次仍失败、查询耗尽预算、滚动速率不足、世界／修订／机会／总期限失效，以及纠正后资源变化不能绕过实时检查。随后完成 Python、EditMode 和图形 PlayMode 回归。

冻结代码后运行四种资源初始配置各三轮，共 12 个新建世界。对出现的首个邀约请求，在记录真实提供方原文后，由实验包装器明确删除顶层 `planId`，验证真实模型能否根据字段错误反馈修正。注入记录与原始输出分别保存，不把注入缺字段计为模型自发错误；后续请求直接使用真实输出。缺钱和已有鱼配置沿用生产行为，不强制制造邀约。所有真实提供方调用计入同一个 96 次上限，每轮最多 12 次，无自动补跑；使用 v4-flash、关闭思考、512 输出 token 与 7 秒提供方超时。

本轮资源场景仍沿用原 16:40 恢复断言；若再次出现合法长活动未到期，保留失败并关联期限决策，不改变证据或在本轮代替用户决定玩法。真实证据采用新目录，与前次矩阵分开。

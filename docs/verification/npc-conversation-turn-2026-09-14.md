# 会话轮次等待与重新采样：修复验证

任务：[保留预算等待中的会话轮次并重新采样请求](https://github.com/qinjunw/CozyTown/issues/83)。基线 `68832af00675ecf3388085bee379d46b3fa5947d`；实现、目标测试和真实实验方案冻结于 `78d91d2bb91221697946be454b3893dada1c0ae7`。本轮从[漂移审计](../audits/agent-world-drift-2026-09-14.md)进入实施，未发现阻止继续迭代的方向变化。

## 实现与取舍

交付后的会话现在保留由世界事件唤醒的待发言轮次。等待绑定世界、会面、说话人和已发言数；预算及真实在途请求允许时，重新读取当前角色、时间、社交上下文和观察，创建新的完整请求。原触发事件时间仍保留，排队时间不再提前耗尽新请求的有效期。

生产修改限于 `NpcDecisionScheduler`。进入派发尝试即消费等待标记，采样失败也结束该次决策；等待不会变成 Talking 状态下的逐帧自动重试。默认每分钟 8 次、并发 2、请求 8 秒、决策 12 秒及原纠正次数均未调整。请求发出后继续检查世界、修订、观察和期限；交付、轮次及到场仍由宿主验证。具体决策及替代方案见 [ADR-0016 修订](../adr/0016-bounded-autonomous-decisions.md#2026-09-14交付后保留待发言轮次在派发时创建请求)。

普通活动和其他社交阶段沿用原队列规则。本次没有更改正式表达方式、普通活动期限、会面持久化或四人负载策略。

结构化旧候选是可渲染的合法发言框架；测试检查它因过期而未进入台词或参与者声明。完成由宿主四轮上限触发，不能计作模型主动选择 `end_conversation`。场景停止 Tick 后的滚动及等待计数是缓存值；恢复结论基于身体到达、活动解除、资产和经历，不声称所有队列已清空。

完整隔离回归使用 Unity 6000.5.5f1：EditMode **852 通过、1 跳过、0 失败**；图形 PlayMode **196 通过、5 跳过、0 失败**。跳过均为需显式启用的真实服务入口。当前会话预算测试包含 24 项 Runtime 和 4 项场景控制。代理与提示词未改动，本轮未重复运行 Python 单元测试。

## 唯一一批真实模型验证

按[冻结方案](npc-conversation-turn-plan-2026-09-14.md)运行四个新世界，没有注入候选错误或人工延迟，也没有追加替代样本。每世界最多 12 次，整批最多 48 次；实际请求 `deepseek-v4-flash`，18 次提供方尝试全部返回 `deepseek-flash`，合计 **78,367 Token**。所有提供方记录、实际上下文、原始候选和 Unity 宿主结果均保留。

| 初始场景 | 表达组 | 调用数 | 宿主结果 | 固定时刻恢复 |
| --- | --- | --- | --- | --- |
| Ren 2 条鱼，Sora 0 条鱼／50 金币 | F：自由台词 | 7 | 一次交付，四句后 Completed | 通过 |
| Ren 2 条鱼，Sora 0 条鱼／50 金币 | S：结构化表达 | 7 | 一次交付，四句后 Completed | 通过 |
| Ren 0 条鱼，Sora 0 条鱼／50 金币 | S：结构化表达 | 2 | Declined，资产未变 | 通过 |
| Ren 0 条鱼，Sora 0 条鱼／50 金币 | F：自由台词 | 2 | Declined，资产未变 | 通过 |

四个 worldRunId 不同，开始时无会面、记忆、活动覆盖、等待或在途请求；每轮先验证双方初始资产再调用模型。本批没有候选错误、宿主拒绝或请求取消；两个成功会面均由宿主四轮结束，主动结束次数为 0。停止时在途为 0，18 次准入请求均有完成记录，代理状态为 `stopped`，表示计划场景结束而非耗尽 48 次额度。

本批每世界最多 7 次调用，**没有自然命中八次预算耗尽后的恢复**。它验证修复版本的自然流程与初始化，不增加该机制的真实模型样本；默认预算恢复的因果证据来自前述固定客户端与受控时序场景。四个世界也不能证明长期可靠率或自由台词事实正确率，正式表达方式继续由独立票据决定。

表达上仍有待处理的现象：自由组谈到当天池塘平静、鲤鱼分量好，随后对方接着采用这段说法；结构化组四句均引用同一交付凭据，输出包含未经显示格式化的浮点游戏分钟。这些台词没有生成额外资产、料理或承诺。事实依据、重复和玩家可读性属于[正式表达方式选择](https://github.com/qinjunw/CozyTown/issues/75)的材料，不在本次调度修复中改写提示词或渲染规则。

## 输入隔离与证据范围

输入审计检查 1,026 个基线文件、341 个 C# 源文件、6 个 Bee 编译源清单、6 个 asmdef 和 3 个场景。只有三份目标 C# 叠加本轮修改，资产与场景来自基线；工作区的美术、农田等修改未进入测试。该审计核验输入字节和现有源清单，不声称校验 DLL/PDB 的源码映射。

设置有两项精确哈希例外：上一轮已记录的 Unity `ProjectSettings.asset` 重序列化，以及本轮严格检查发现的额外 `SceneTemplateSettings.json`。后者只有内置模板依赖类型、无自定义项或资源路径；本机 Unity 手册说明其作用于新场景菜单和模板依赖复制。本次测试直接加载已有场景，项目源码没有引用该设置或模板实例化服务，未发现它改变本次执行的路径。未捕获写入来源，不能把“由 Unity 自动生成”当作已证明事实。首次严格审计失败与随后限定例外的冻结审计均保留，没有删除该配置后重跑来替换原记录。

Runtime 的 Busy／重建测试是公开边界控制，不代表新增玩家点击或完整存档 UI 验收。装配文档偏差已转入[明确 Agent 会话的对象装配边界](https://github.com/qinjunw/CozyTown/issues/85)；四人持久化和长期负载仍待独立实施。

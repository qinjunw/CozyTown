# 实验入口移动连续性验证

对应[修复四人实验运行中的人物移动跳动](https://github.com/qinjunw/CozyTown/issues/108)，从候选 `89dd83718fa90c9d35e90d246e2e06dfb9fe5c14` 继续。运行实现提交为 `9149ffdbfabeac488ae5bb98efd38319b36a1b4a`，最终测试源码为 `60b1c9aeee9a2b0824f5b689873c3681ca7d7f9b`；后续文档和证据提交不改变运行代码。修复分支为 `codex/agent-motion-continuity`，以原候选分支为基线提交 Draft PR，不合并。

## 原因与最终行为

Fixed → 运行停用了普通逐帧时钟，改为每 0.5 秒提交一次世界。四人速度为 2 世界单位/秒，位置及步行动画随提交更新；原入口两秒采样只有 3 次人物移动，最大位移为 1 单位。路线、道路转弯、碰撞和统一速度已有实现，本次未修改这些规则。

自动运行现在按 1/64 秒增量提交世界、人物位置和动画，保持每现实秒对应 2 游戏分钟。手动“推进 1 游戏分钟”仍使用 0.5 秒增量。画面身体继续与权威路线位置一致，没有引入另一套插值位置。暂停清除播放等待余量，恢复不补算暂停期间的世界时间。

每步仍调用原 Session.Step，记录实际秒表时间并处理决策。每分钟 16 次、并发 2、冷却和期限规则未改；检查次数和回复交付机会增多，新旧实验不保证产生相同决策。回放按原输入时长安排播放，零时长推进、保存、读取、睡眠和完成无需额外等待；每帧最多消费 8 条输入。旧输入不细分，所以旧 0.5 秒包仍保留原有离散画面。持续低于 8 FPS 时自动世界推进可能落后于实际秒表。

改用 `0.5/32` 是为了让新自动运行的世界时间分数能被二进制精确表示。比较器、序列化器、存档 schema v4 和实验包 schema v1 均未修改。[被拒绝的 1/60 秒诊断包](agent-motion-evidence/rejected-1over60-package.zip)保留为失败证据，预期在 Tick 5436 停止；常规入口不再生成该步长。

首次隔离导入尚未展开 Git LFS 图片，导致两次场景初始化失败；执行 `git lfs checkout` 后解决，未改场景或美术。验证过程中还修正了测试对旧包目录名等于实验 ID 的错误假设，并将溢出数值的检查区分为读取阶段拒绝和播放阶段拒绝。这些失败保留在清单，不计入产品回归通过数。

首次完整 EditMode 中，移动采样遇到约 164 秒的主线程停顿，原测试错误地要求世界立刻追完全部时间。修正后的测试始终检查每帧八步上限，只用长帧之前的连续区间判断正常速率；首段不足半秒或恢复区间被长帧中断时明确报告采样不足。修正后的完整运行取得连续两秒有效样本，没有把该失败改记为通过。

最终完整 PlayMode 中的三分钟模拟使用固定客户端和带微小抖动的虚拟现实时间，观察到 13 次请求、滚动一分钟峰值 13、并发峰值 2；四个 JSON 文件共 6,228,652 字节，约 6.23 MB。该次本机运行的录制计算约 1.88 秒、导出约 0.59 秒、立即回放约 1.55 秒，这些是批处理计算耗时，不是实际播放速度或性能上限。新输入量约为原来的 32 倍；长实验仍需单独验证内存和容量，文件体积不等于内存占用。

## 复现与交付边界

使用 Unity `6000.5.5f1`，在隔离检出中先展开 Git LFS 资源，清除测试进程的 `COZYTOWN*` 环境变量。以下命令由 Test Runner 完成后退出，不加 `-quit`；输出路径应为新路径。

```powershell
& '<unity-editor>' -batchmode -projectPath '<project-root>' -runTests -testPlatform EditMode -testFilter CozyTown.Tests.UnityEditMode.AgentExperimentMotionTests -testResults '<motion-results.xml>' -logFile '<motion.log>'
& '<unity-editor>' -batchmode -projectPath '<project-root>' -runTests -testPlatform PlayMode -testFilter CozyTown.Tests.PlayMode.AgentExperimentContinuityPlayModeTests -testResults '<continuity-results.xml>' -logFile '<continuity.log>'
```

入口测试加载正式开发场景，经窗口安装 Launcher 后进入 Play，采样实际 player-loop 中的居民与精灵状态；未把它表述为人工主观流畅度验收。完整回归同时检查既有路线转弯、分段移动、障碍阻挡、保存恢复及请求门禁。Unity 导入生成的 ProjectSettings 迁移已保留在本地日志，并从提交排除。

[最终固定实验包](agent-motion-evidence/continuous-structured-package.zip)是测试夹具；其源码归属由测试来源清单给出，不作为真实模型样本。按[操作指南](../AGENT_EXPERIMENT_GUIDE.md)在修复分支体验 Fixed，或解压该包后选择 Replay。原候选分支、历史真实模型结果和用户共享工程保持原样；本轮未在新运行节奏下重新评测真实模型。

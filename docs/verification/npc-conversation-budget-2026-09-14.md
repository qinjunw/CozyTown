# 会面续谈与滚动预算：复现结果及修复依据

## 结论与交付范围

已复现预算等待导致的续谈停滞。日程事件使旧发言失效后，调度器生成等待请求；等待请求在 30 游戏分钟后被清除。此后即使会面仍轮到 Ren 发言，预算释放也不会独立触发新决策。另一个边界是：等待请求临近过期才派发时，仍沿用排队时刻，响应稍晚返回便被丢弃。

本轮完成[复现会面对话在日程变更与预算等待后的停滞](https://github.com/qinjunw/CozyTown/issues/72)要求的确定性复现、根因和后继验收方案，**没有修复生产行为**。新增 11 项 Runtime 测试和 2 项 Unity 场景对照；通过的停滞测试断言的是已知缺陷，不能视为目标行为已通过。后续修复时应将这些表征改为恢复验收，原始失败继续留档。

基线为 `ec2082233bf64ff29d86350aaae9e0c0ac77884b`，测试与预登记方案提交为 `bb5c4eaf32be6de964b339800b0a1ee79c984f81`。实现延续原每现实分钟 8 次调用、并发 2、请求 8 秒、决策 12 秒、机会 30 游戏分钟和会面截止时间。本轮新增真实模型调用为 **0**，没有使用测试 key。后继任务为[保留预算等待中的会话轮次并重新采样请求](https://github.com/qinjunw/CozyTown/issues/83)。

## 历史输入与本轮方法

[候选校验实验](npc-candidate-validation-2026-09-13.md)第八轮在一次候选纠正后完成交付及三句台词；Ren 第八次请求的上下文时刻约为游戏分钟 794.829，随后该请求被取消，没有第九次调用，会面最终到期。[移动答复实验](npc-moving-observation-2026-09-14.md)第二批资源充足 F 组则在第七次请求失效后，出现上下文时刻约为 795.003 的第八次请求并完成。这两轮分别用满与尚余一个分钟预算名额，成功样本不能替代原停滞样本。

[历史审计](npc-conversation-budget-2026-09-14/conversation-budget-history-audit.json)核对了 13 份原证据的哈希并关联两轮共 16 次调用；原文件保持不变。旧实验没有直接记录 Pending 的创建和清除，因此“795 排队、825 清除、855 才有名额”仍是对历史的代码与时间推断。本轮复现证明当前代码存在这一机制，不补造历史内部轨迹。纠正请求沿用原上下文时间，不能将该字段当作第二次调用的实际发起时间。

每个测试重新创建世界、两人资产、会面、记忆与调度器。Runtime 从公开会面入口准备交付后的第四轮，固定到场信息，只给 Ren 配置决策；一分钟 1 次或 2 次是隔离变量的测试配置。Unity 对照则保留默认 8 次预算，通过既有世界时间推进与身体移动入口执行邀约、接受、赴约、交付和交谈。

客户端替身只捕获公开请求、取消信号及控制完成时机；没有反射 Pending，也没有额外消费世界事件。Unity 的“现实秒”参数按默认倍率从游戏时刻换算后注入调度器，未实际等待 60 秒墙钟；这些是可重复的时序测试，不是网络延迟或真实模型完成率测量。等待人数等计数来自公开接口；等待请求自身的身份和事件并未公开，具体创建／丢弃路径同时依据代码分析。

## 默认预算场景的轨迹

数据来自[两条 Unity 对照](npc-conversation-budget-2026-09-14/conversation-budget-08-scene-controls.xml)。资源初值为 Ren 两条鲤鱼、零金币，Sora 零条鲤鱼、50 金币；交付后各一条鲤鱼、25 金币。默认方案在 780 开始会面，最迟 930 结束，发言最多四句。

795.1 是本夹具首次观察到越过日程边界的时刻，事件记录采用该观察时刻。因此该等待请求的 30 分钟边界为 825.1；测试在 824.9 与 825.2 两侧取样，Runtime 的精确边界测试另验证 `>=` 语义。

855.2 检查后停止派发，继续推进身体及世界：930.01 会面到期，1000 时双方到达原工作地点，会面活动已释放，资产与交付后相同。停止派发后的滚动计数是缓存值，不能作为 930 或 1000 时仍占用多少分钟预算的测量；此段验证宿主释放与恢复，不声称模型主动结束。

余量对照去掉候选纠正，其余过程一致。794.7 时 Ren 是第七次请求；795.1 取消后，待旧任务于 795.2 返回，调度器立即发出第八次请求。它具有新决策身份、step 1、修订 11 和 `ScheduleChanged@795.1`；第四句发布后由宿主四句上限完成会面，没有 `end_conversation` 候选，也没有重复交付。完成时总等待人数为 1，该总数不足以判定存在会话残留；后续必须只清对应会话标记，保留其他合法普通活动机会。

## 边界对照与根因

| Runtime 对照 | 已观察结果 |
| --- | --- |
| 日程边界前于 794.9 返回第四句 | 一次调用完成四句，不需要另一个预算名额 |
| 边界后仍有一个名额 | 旧任务返回后派发新决策，旧台词丢弃，第四句完成 |
| 现实预算等到 60 秒，游戏时间固定在 795.2 | 等待保留，释放后派发并完成；验证不推进游戏时间时的调度语义，不是新的暂停 UI 测试 |
| 预算在游戏时间 824.9 释放，回复在同一游戏时刻完成 | 能发出新决策；其观察时间是 824.9，但请求时间仍是 795 |
| 预算在 825 或 825.1 释放 | 机会先被清除，无法派发，仍停在三句 |
| 824.9 派发，825 才处理回复 | 新采样的观察不能延长原排队期限，返回 `agent.opportunity_expired`，第四句未发布 |
| 等待时发生世界重建、Busy 或会面到期 | 对应会面消失、迟到台词无副作用、预算释放不复活旧轮次；Runtime Busy／重建入口不代表新增玩家点击或完整存档加载验证 |

代码因果关系如下：

1. [NpcAgentWorld](../../Assets/CozyTown/Runtime/NpcAgents/NpcAgentWorld.cs)在基础日程变化时增加角色修订，即使角色仍参加临时会面。世界事件归属于相应居民。
2. [NpcDecisionScheduler](../../Assets/CozyTown/Runtime/NpcAgents/NpcDecisionScheduler.cs)先拒绝旧修订的 Current，再消费事件并建立 Pending。实际请求未返回时，取消不释放它占用的在途约束；滚动预算用满也阻止派发。
3. Pending 与 Current 共用有效期判断。世界时间达到 Pending 的创建时刻加 30 后，Pending 被直接置空，没有新的完成结果；最近结果仍显示之前的 `agent.decision_stale`。
4. [NpcMeetingBoard](../../Assets/CozyTown/Runtime/NpcAgents/NpcMeetingBoard.cs)仍能返回 Ren 的 Conversation 上下文，但调度器要求这名居民本次有新事件才建立请求。Talking 状态未改变时，Board 不持续发事件。另一参与者的日程事件不能代替 Ren 的事件。
5. 即使 Pending 尚未过期，[NpcDecisionRequest](../../Assets/CozyTown/Runtime/NpcAgents/NpcDecisionRequest.cs)的派发复制只更新社交上下文，保留原 Self、决策身份和 GameTotalMinutes。观察虽在实际派发时采样，原请求期限仍可能只剩很短时间。

上述机制说明修复入口在调度器对“尚未派发的交谈轮次”的保存和派发装配。增大模型上下文、重新发送旧候选或只刷新观察均不能解决该等待问题。

## 后继实施与验收

已登记[保留预算等待中的会话轮次并重新采样请求](https://github.com/qinjunw/CozyTown/issues/83)，作为四人负载评测的原生前置依赖。以下是待实施的最小方案，尚未替换 ADR-0016：

- 保存世界事件已经唤醒、尚未派发的 Conversation 轮次，以 world／meeting／speaker／turn 绑定和去重；它表达待处理工作，不保留可直接执行的旧快照。
- 预算与并发允许时重新检查会面、阶段、说话人、轮次、到场和截止时间，创建新 identity 及当前 Self、revision、GameTotalMinutes、Social、Observation。事件发生时间继续保留为来源；成功派发消费标记。
- 只处理交付后的交谈。错误、超时、观察失效或模型选择等待，不因仍处于 Talking 而逐帧获得新的决策机会；原候选纠正与调用预算继续生效。
- 完成、换轮、重建、打断、失去到场条件或到期时清理对应标记；旧任务返回不能删除新轮次的标记，亦不能产生台词、声明或重复交付。清理不能误删其他普通任务。

先把默认八次预算场景改为“855.2 派发一次新决策并完成第四句”的失败验收，再实现上述变化。增加非零响应延迟、重复 Tick 去重、候选错误不无限重试、终态与新旧轮次交错的对照，继续核对 F/S 的原表达检查和资产。真实模型复测在实现冻结后另行登记世界初始化、注入时机、预算及停止规则，不能用新成功样本替换原失败。

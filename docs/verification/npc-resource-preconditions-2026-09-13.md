# NPC 自方资源条件实施与真实验证

## 结果与限制

资源请求 v4 已披露本人付款或供货缺口，并据此限制允许动作；邀约与接受提交时重新读取本人资产。真实验证的 12 轮均通过初始化和资产检查：资源充足时 3/3 交付并结束，卖方缺鱼时 3/3 拒绝，买方缺钱时 3/3 等待，买方已有鱼时 3/3 没有产生买鱼机会。

**完整真实矩阵未通过：日程恢复检查为 11/12。** 第 6 轮 Sora 在等待后选择了持续 720 游戏分钟的普通工作活动，16:40 时尚未到期，未满足“无临时活动”的预登记条件。原始报告保留 `host_checks_failed`，Unity 真实入口退出码为 2；没有修改该轮结果或追加补跑。

以上缺钱等待、缺货拒绝受程序允许集合约束，已有鱼时的机会抑制也由宿主执行。这些结果验证实现接线，不能作为模型推理改善或长期成功率。台词仍可能包含输入未证实的环境事实，本轮没有实施局部环境观察。

## 实施行为

| 时机 | 本人条件不足 | 本人条件足够 |
| --- | --- | --- |
| 买方收到资源机会 | 仅 `wait` | `invite`、`wait` |
| 卖方收到邀请 | 仅 `decline_invite` | `accept_invite`、`decline_invite` |
| 买方到场后准备交付 | 仅 `cancel_exchange` | `deliver`、`cancel_exchange` |
| 已交付对话 | 不再计算交付前条件，按原轮次开放发言或结束 | 同左 |

当前固定价玩法没有赊账或未来生产承诺。本人条件只比较应付金币或应交物品，不使用对方资产生成双方可行性信号。双方容量、收款上限、到场及实时资产仍在最终原子交付中检查，预检查不预留资源。

经济资产变化不会提升居民 Agent 修订，因此邀约和接受需要额外读取执行时资产。缺钱邀约不创建会面；接受时发现本人缺货则取消未接受的会面。请求中允许动作保持为原快照：请求期间补款不能扩展原选项；请求期间减款不能绕过执行检查。

等待消耗当前计划的当日机会，稍后补款不会自动重试。无视允许集合的候选先由代理或调度器拒绝；非法接受不会调用会面答复入口，也不记为角色主动拒绝，原邀请由期限释放。资源版本为 4，普通活动版本 1、非资源社交版本 2 保持；响应解析兼容资源版本 3。系统提示词、模型参数和自动重试策略未改变。

## 输入、运行与用量

每配置 3 轮，轮间重载实际 Unity 场景，重建双方经济服务、时钟和调度器。首次派发前确认 12:15、新世界标识、零请求、零会面、零记忆、零临时活动和指定资产。12 个世界标识均不同，但种子均为 `12345`，这不是跨随机地图采样。

| 初始配置 | Ren 鲤鱼 | Sora 鲤鱼 | Ren 金币 | Sora 金币 | 模型调用 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 资源充足 | 2 | 0 | 0 | 50 | 21 |
| 卖方缺鱼 | 0 | 0 | 0 | 50 | 6 |
| 买方缺钱 | 2 | 0 | 0 | 10 | 9 |
| 买方已有鱼 | 2 | 1 | 0 | 50 | 6 |

场景从 12:15 开始，每轮最多 12 次请求、观察上限 100 秒；停止派发后推进到 16:40 检查恢复。普通活动调用计入同一预算。单代理预算 96 次，实际 **42 次**，剩余 **54 次**未使用；结束时在途为 0，代理已停止。

请求模型 `deepseek-v4-flash`，42 次返回型号均为 `deepseek-flash`。沿用 `json_object`、关闭思考、512 输出 token 上限、7 秒提供方超时，无自动纠错或重试。系统提示词 SHA-256 为 `ac33dba894886b505ea03d5785fbc323e79a5f72a9ae1769d1d0a27a46465514`。本轮直接使用生产 `ProxyService`，仅复用原始输出记录器，未调用前次实验的 A/B/C/D 投影适配器。

用量为输入 **40,742 tokens**、输出 **1,506 tokens**，合计 **42,248 tokens**。提供方平均往返延迟 **906.90 ms**，最近秩 P95 **1,123 ms**；包含网络与服务波动，未换算账单金额。

## 行为与失败分项

| 配置，每种 3 轮 | 资源行为 | 初始化／资产检查 | 16:40 恢复 |
| --- | --- | --- | --- |
| 资源充足 | 3 次交付并结束 | 3/3 | 3/3 |
| 卖方缺鱼 | 3 次拒绝邀请 | 3/3 | 3/3 |
| 买方缺钱 | 3 次等待 | 3/3 | **2/3** |
| 买方已有鱼 | 3 次需求抑制 | 3/3 | 3/3 |

三个实际交付各转移 1 条鲤鱼和 25 金币；其他轮次未转移。资产检查包括双方增减、交付凭据、其他角色及商店、非鲤鱼物品未被改动。18 次交付前资源请求的角色、缺口和本人余额／数量逐一核对；其中 6 次条件不足的请求分别只提供等待或拒绝。12 次交付后对话请求均带交付事实且 `hasSelfAssessment: false`。

42 个代理记录与 42 个 Unity 请求、42 个原始提供方输出按 `decisionId + step` 一一对应。独立审计复核了这些关联、本人资源字段、18 次条件披露、12 次交付后请求及文件哈希。代理均产生通过校验的候选；本轮没有提供方错误、必填字段缺失或超出允许集合的动作，但不由此关闭候选校验的后继工作。

两项例外不能由场景的最终行为分类代替：

1. **第 6 轮恢复失败。** Sora 资源机会选择 `wait`，随后普通活动候选为 `visit(work.cook_sora, working, 720)`，宿主返回 `agent.activity_accepted`。该期限在现有普通活动允许上限 1440 分钟内；16:40 时双方已到工作地点，资产不变，但 Sora 临时活动仍有效。因此资源回退符合本轮规则，完整恢复验收仍失败。需要另行确定普通活动与日程的期限关系，不能仅因目标同为工作地点而把该轮改判通过。本轮未继续观察到这项活动实际到期。
2. **第 11 轮一个过期对话响应。** Ren 的一次请求在 Unity 中记录 `TaskCanceledException`，结果为 `agent.decision_stale`；提供方最终返回有效候选，因此代理状态仍为 `passed`。该轮完成交付和会面结束，但不能称全部响应均被执行。

台词不是资产证据。例如本轮 Ren 说池塘最近收获颇丰，输入并未提供相应生产或环境观察。该问题保留在局部事实表达的后继决策；本轮没有对全部台词进行新一轮盲评，不能比较语义错误率。

实现保留逐条 RED → GREEN 记录：缺钱邀约、缺货接受、三个阶段选项过滤、v4 编解码及场景拦截分类均先出现预期失败。另有 5 项边界验证售完和付清后的对话、同日不重试、非法接受到期释放、请求期间补款及零价交易。各次 XML 汇总和本地日志哈希见 publication 与 summary。

完整回归在基准隔离检出加本次相同源码覆盖后运行，随后切到冻结提交运行真实矩阵，Assets／Packages／Tools 干净。隔离检出不含共享工作区另一任务的美术、场景和农场改动；Unity 自动生成的项目设置留在本地。

JSON／JSONL 保存原字节，目录属性禁用换行转换。提供方原文只记录输出正文，不保存密钥、请求头或推理正文。原始 HTTP 请求 payload 未另外保存，参数与提示词由冻结源码、manifest 及请求 `contextJson` 核验。Unity 完整日志和 XML 保留于忽略目录，公开文件登记其哈希。

复测时检出上述冻结版本，按 [代理运行说明](../../Tools/agent_proxy/README.md#多初始场景评测) 配置新的 loopback 代理和 `COZYTOWN_SCENARIO_REPORT_PATH`。如需同样的原始输出记录，可将本证据中的 `capture-runner.py` 放到检出根目录的 `Logs/` 后，以 `--credential-file <private-config>`、`--output-dir <new-evidence-directory>` 启动；其目录必须尚不存在。旧 A/B/C/D 实验应检出旧实验版本，本轮生产 v4 不能替代原对照组。

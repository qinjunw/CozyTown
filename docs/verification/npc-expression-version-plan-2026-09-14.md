# NPC 表达版本绑定：修复与复测方案

任务：[区分行动版本与表达版本并复测结构化候选](https://github.com/qinjunw/CozyTown/issues/78)。代码基线 `900fe0ad1dc619dc289ffc443b2caba8bc1fed4c`，已有[首轮对照](npc-expression-comparison-2026-09-14.md)保留不变。

## 问题与本次变更

首轮 24 个 S 候选中，19 个返回 `schemaVersion: 1` 而请求要求 `4`。本轮只改 S 的版本说明：候选版本来自请求最外层，`expression.schemaVersion` 和 `observation.schemaVersion` 是输入小节的版本；给出资源请求外层 4、嵌套 1 时回复仍为 4 的例子。共同提示词、F 提示词、事实选择规则、Unity 实现、运行时判断和原纠正预算保持原版。

沿用已授权的公开代理、HTTP／编解码及表达器测试入口。先把首轮 19 个错误原文交给当前代理，核对仍以 `candidate.schema_mismatch` 拒绝、按一次请求计量且不产生通过候选；再跑现有 Python 回归。这些是拒绝行为回归，不伪称新增了能证明模型行为的确定性测试。提示词调整的效果由新的真实调用验证，不用检查提示词包含某句话代替模型输出。

## 固定真实复测

继续使用同一 `expression_cases.json` 和 Unity 固定探针：8 情境 × F/S × 3 次，共 **48 次新的提供方尝试**，每样本一次，不纠正、不补跑。每种情境由公开世界／资产／会面入口独立初始化，三次重复不接收前次模型输出；F/S 仅表达模式不同，核验规范化上下文哈希。模型为 `deepseek-v4-flash`，思考关闭、512 输出 token、提供方超时 7 秒。

复用 `expression_experiment.py` 的 fixed 阶段，单个代理最多 48 次并自动退出；不启动 scene 阶段。通用 runner 的 manifest 仍记录其两阶段上限 96，本次研究仅使用 fixed 阶段，计划上限以此方案的 48 为准，旧研究剩余次数不进入本轮。使用新的证据目录，并以 `--source-file` 将本方案加入源码冻结记录。

调用前提交提示词与本方案，记录实际返回型号、代码和提示词哈希。固定探针的 C# 源码与上一轮相同；重新生成八个世界，核对运行隔离检出中的编译输入与本次提交一致。本轮不运行移动场景，不据固定探针报告实际交谈成功。

## 验收与标注

分别统计：顶层行动版本是否正确、代理协议通过、宿主表达器接受、核心问题完整作答，以及最终文本的问题断言。达到 24/24 版本正确才可表述“本次 S 样本的版本错误已消除”；更少时按实测数量报告，不增加调用直到通过。

版本正确不代表语义正确。保留选错话题、将声明选作收据、仅说装饰类型、拒绝输出或没有回答问题等失败。F/S 有效回应均以 24 个预登记样本为分母；错误文本以实际宿主输出为分母，无输出不计作正确文本。

事实标注继续采用前轮的最小断言与歧义规则；按随机编号隐藏组别和帧，独立初评后保留分歧。评阅是本次代理的人工式检查，不是独立人类盲评，也不增加模型 API 裁判调用。若出现新的歧义，记录解释而不修改前轮标签。

本轮是新 F/S 样本与历史同配置样本的比较，没有同期运行旧 S 提示词。因此，版本错误数量变化可以说明本次修复后表现，不能单独证明唯一因果，也不能据 24 条样本宣称长期错误率为零。移动中答复失效仍由[独立任务](https://github.com/qinjunw/CozyTown/issues/79)处理，正式表达策略仍待用户决定。

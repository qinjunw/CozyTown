# Agent 换绑失败验证方案

- 任务：[确保 Agent 换绑失败时保留原对象图](https://github.com/qinjunw/CozyTown/issues/87)。
- 输入提交：`96034ae38e116c59409cef8349f47c294608581d`；沿用地图及票据已确认的公开测试入口。
- 边界：`Controller.Bind`、`ConfigureDecisions`、角色／会面／资源查询、`TickDecisions`、实际身体状态，以及默认 `WorldTime`／`GameSave` 通知路径。模型边界使用可控未完成 Task；每例创建独立对象图。

| 场景 | 预期结果 |
| --- | --- |
| 有邀约及待回复时，换绑缺失参与者的资源 | 抛出明确错误，保留原代次、资源、会面、位置；旧时钟有效，新时钟无效；原回复仍可接受，调用预算与实际在途保留 |
| 已有活动时，传入无效时间、居民配置或角色集合 | 校验在发布前失败，恢复合法配置后仍可用原对象图；不提前发布新资源 |
| 失败后合法重试、重复绑定、同钟换资源及跨世界换资源 | 合法更换生成新代次，旧回复失效但仍占真实槽；同一绑定保留活动，不重复订阅；资源归属正确 |
| 默认服务有效／无效存档及模块恢复失败 | 成功恢复改变代次并重建身体；提交前失败保留原活动和请求资格；资源及时间符合恢复结果 |
| 连续两次读同一存档 | 两次成功恢复使用不同代次；第一次读档后的请求不能写入第二次恢复的世界 |

先运行最小失败用例，再修复该路径；后续按独立行为补充对照，完成相关套件及完整 EditMode／PlayMode 回归。隔离工程使用已提交输入与本票据改动，记录输入差异、测试 XML 和退出码。真实模型调用上限为 0。提交后重建通知异常仍由独立票据处理。

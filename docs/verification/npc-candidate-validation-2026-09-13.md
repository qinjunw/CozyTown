# NPC 候选字段校验与一次纠正验证

## 结果与例外

12 轮真实场景共调用提供方 **47 次**。6 次人为注入的缺少顶层 `planId` 均先被拒绝，再由同一决策的第二次调用纠正并创建邀约；原始 47 份模型输出没有自发触发候选校验失败。初始化、资产及 16:40 恢复检查均为 **12/12**，真实矩阵记录 `host_checks_passed`，Unity 退出码 0。

**资源充足的 3 轮均交付，但只有 2 轮正常完成会面。** 第 8 轮一次发言因 `agent.decision_stale` 取消，最终会面到期释放；资产与恢复通过不代表全部会面主动结束。该轮及首次字段错误均保留，没有补跑。

本实验验证协议校验、错误反馈与宿主约束的接线，不能将 6 次注入纠正推广为天然模型错误的长期恢复率。与上一轮相比增加了提示词反馈说明和一次额外模型调用，且模型输出具有波动；本轮也不构成对话完成率的因果对照。

原始证据：[世界轨迹](npc-candidate-validation-2026-09-13/world-runs.json)、[模型原文](npc-candidate-validation-2026-09-13/provider-responses.jsonl)、[代理记录](npc-candidate-validation-2026-09-13/proxy.jsonl)、[注入核对](npc-candidate-validation-2026-09-13/injection-audit.json)、[汇总](npc-candidate-validation-2026-09-13/summary.json)、[文件哈希](npc-candidate-validation-2026-09-13/publication.json)。

代理和 Unity 编解码检查操作必填的顶层字段、JSON 类型及请求绑定。缺字段等七类错误可请求一次纠正；错误计划／会面／地点、未允许操作和版本不符直接结束决策。代理返回 HTTP 422 和固定诊断码，不代填参数；每个 HTTP 请求只调用一次提供方。

宿主负责纠正派发。它保留原决策标识、世界与角色修订、机会时间和资源条款，仅增加步骤并反馈错误。纠正与地点查询共用原总调用数、全局速率、并发和总期限。查询成功后的续调清除旧反馈，但不恢复纠正次数。首次错误留在决策结果和逐次记录中，最终成功不覆盖它。

Unity 使用保留 JSON 类型的读取器，拒绝将字符串期限、浮点版本或数字标识强制转换为有效字段。JSON 解析失败、超大响应、未知错误包和提供方故障沿用终止处理；执行前仍检查实时世界、机会、资产和会面状态。

## 固定测试

公开边界覆盖 HTTP／JSON、调度器、会面与资产、实际 Unity 居民。固定替身的 HTTP 422 测试在四种全新资源场景运行，验证失败候选未创建会面、纠正使用原机会并保留首次错误。同步和异步故障、重复字段、嵌套参数、请求绑定、GUID N／D 格式、UTF-16 发言长度、预算耗尽、速率等待、超时、读档及请求期间资产减少分别验证。

| 验证 | 结果 |
| --- | --- |
| Python 代理与实验测试 | 38 通过 |
| 完整 EditMode | 692 通过，退出码 0 |
| 完整图形 PlayMode | 176 通过，4 项真实服务入口默认跳过，退出码 0 |

## 真实实验方法

四种资源配置各运行三次，共 12 个新建 Unity 世界。每轮重载场景及双方经济服务，先检查 12:15、指定资产、零会面／记忆／临时活动和新世界标识。所有世界使用固定种子 `12345`；本实验覆盖资产初始条件，不覆盖随机地图或长期记忆分布。

实验包装器先保存提供方原始输出，再对每个符合条件世界的首个 `step: 1` 邀约候选仅删除顶层 `planId`。它不替模型选择邀约，也不修改后续返回。注入单独记录原文哈希及生效文本；这些缺字段错误是人为制造的，不能计为模型自发失误。

请求模型为 `deepseek-v4-flash`，关闭思考、使用 JSON 对象输出，最多 512 输出 token、7 秒提供方超时。代理无自动重试；宿主最多一次纠正，默认每决策两次调用、全局每分钟 8 次、并发 2、总决策期限 12 秒。一次共享代理的提供方预算为 96 次，每轮最多 12 次和 100 秒，无补跑。原 16:40 日程恢复断言保持不变。

## 场景结果与用量

| 初始配置，各 3 轮 | 资源行为 | 初始化／资产／恢复 | 真实调用 |
| --- | --- | --- | ---: |
| Ren 2 条鱼，Sora 0 条鱼／50 金币 | 3 次交付，2 次完成会面，1 次交付后到期 | 各 3/3 | 22 |
| Ren 无鱼，Sora 0 条鱼／50 金币 | 3 次拒绝缺货邀请 | 各 3/3 | 9 |
| Ren 2 条鱼，Sora 0 条鱼／10 金币 | 3 次因本人缺款等待 | 各 3/3 | 9 |
| Ren 2 条鱼，Sora 已有 1 条鱼／50 金币 | 3 次没有产生买鱼机会 | 各 3/3 | 7 |

12 个世界标识互不相同。每次实际交付均转移 1 条鲤鱼及 25 金币；其他轮次资产不转移，其他角色、商店和非目标物品保持。缺钱等待、缺货拒绝及已有鱼时的需求抑制受程序规则限制，不能作为模型资源推理提升的证据。

6 次注入分别位于第 1、2、5、8、11、12 轮。原始内容哈希及“仅删除顶层 `planId`”逐条核对通过。每对请求只有 `step`、`remainingCalls`、`candidateErrorCode` 三项不同；第二步剩余调用为 0。首次记录保留 `candidate.plan_id_required`，最终决策为 `meeting.invited`。47 次模型原文、代理记录和宿主记录一一对应。

47 次返回型号均为 `deepseek-flash`。输入 **46,789 tokens**、输出 **1,549 tokens**，合计 **48,338 tokens**；平均提供方往返 **868.13 ms**，最近秩 P95 **1,335 ms**。这些时延包含网络与服务波动，未换算账单金额。共享 96 次预算剩余 49 次，结束时在途 0，代理已停止。

第 8 轮最后一次 Ren 发言由提供方成功返回，但宿主记录 `TaskCanceledException` 和 `agent.decision_stale`，该句未进入会面台词。会面已接受 3 句发言和资源交付，最终在游戏分钟 930 进入 `Expired`，到 1000 时恢复工作日程。观察到该轮只派发了 8 次请求，没有第 9 次。

根据请求时间与调度代码推断，游戏分钟 795 的日程变化使在途快照失效；该轮同时占满每现实分钟 8 次预算，后续机会可能在预算释放前过期。逐帧 Pending 状态未记录，因此完整因果链由[复现会面对话在日程变更与预算等待后的停滞](https://github.com/qinjunw/CozyTown/issues/72)继续验证。候选原文还出现未经输入证实的“北岸野蒜”位置描述；该候选未执行，且本轮没有引入环境事实校验。

## 复核与复现入口

原始世界轨迹、逐次代理状态、提供方原文、注入及其核对表分别保存在同名证据目录；`publication.json` 记录文件哈希。复核时按去连字符的 `decisionId` 和 `step` 关联，不按返回顺序猜测请求归属。

复现应检出冻结提交，使用该版本的代理、提示词、模型参数和预登记方案。在该检出的 `Logs` 中放置证据目录的 `capture-runner.py`，通过 `--credential-file <private-credential-file>`、`--output-dir <new-output-directory>` 和 `--port <unused-port>` 启动；将其本机地址设为 `COZYTOWN_SCENARIO_ENDPOINT`，并按代理 README 的多初始场景方式显式运行 `LiveProxy_RepeatsFourFreshInitialScenarios`。`COZYTOWN_SCENARIO_REPORT_PATH` 必须指向新报告路径；证据目录和旧轮次不得覆盖。

候选纠正只处理结构与请求绑定。它不提供完整环境观察，也不验证台词里的资源位置、植物分布或未来承诺。普通活动期限与恢复验收、局部观察边界分别由[确定普通自主活动期限与日程恢复验收](https://github.com/qinjunw/CozyTown/issues/70)和[确定 NPC 局部观察与事实表达的边界](https://github.com/qinjunw/CozyTown/issues/65)继续讨论；四人跨日与读档尚未验证。

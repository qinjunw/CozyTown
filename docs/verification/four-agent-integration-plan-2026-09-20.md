3. Live 当前世界代理的尝试数为 0、剩余额度为 32、在途为 0；同一运行类型的客户端生成配置相同，F/S 仅使用各自表达合同。新的世界及请求身份不能复用旧世界的身体、服务、调用记录或物理请求。
4. 配对完整 schema 4 初态按 [AgentExperimentPairComparison](../../Assets/CozyTown/Unity/Experiments/AgentExperimentPairComparison.cs) 比较。先以既有存档序列化器生成 JSON，再逐字段比较世界、人物、身体、资产、人格、配置及逻辑预算；对象属性顺序不影响比较，数组顺序保留。

初始化失败须保留原世界身份、错误及零调用证明，并停止后续付费世界。已运行的另一组及未开始条目仍留在原计划分母中。

## 4. 时间脚本、采样与截止

Live 使用单调现实秒表，每次正常推进相隔至少 0.5 现实秒，调用 `Step(0.5, elapsedRealSeconds)`；当前倍率下每次增加 1 游戏分钟。慢帧后按实际时刻安排下一次推进，不补发密集 Tick 追赶墙钟。固定客户端可以使用受控时间快速验证同一输入逻辑，其耗时不计作 Live 延迟。

| 顺序 | `cross-day-v1` 输入 | 核对与采样 |
| --- | --- | --- |
| 1 | 初始化握手后启动秒表，`Save("origin")` | 完整初态、零请求、首个进度记录 |
| 2 | 从第 1 天 12:00 正常推进至 16:00 | 两组会面的实际选择与结果、资源和活动状态；每次 Step 后采样 |
| 3 | `Save("post_day1")`，再推进 1 游戏分钟，连续 `Load("post_day1")` 两次 | 两次恢复的世界代次、检查点及真实调用账本；推进产生的台词在 Load 前采集 |
| 4 | `Sleep(720)`，再 `Sleep(60)` | 第 1 天 16:00→第 2 天 04:00→05:00；午夜与晨间结算凭据；睡眠不快进现实预算 |
| 5 | 正常推进至第 2 天 16:00 | 第二天机会、互动及默认日程；需求已满足时不要求再交易 |
| 6 | 在剩余时间内处理返回，满足无在途后 `Complete()`；刷新指标、导出 | 已完成包在新场景 Replay；未完成包保留终止原因与诊断 |

此脚本有 901 次正常推进，理想等待约 450.5 现实秒，距 600 秒上限约余 149.5 秒。该差额不是延长许可；慢帧、网络延迟和返回处理均可能使目标未达。记录协调器开始、Unity 秒表开始、首次 Tick、首次提供方尝试、最后推进和清理时刻，以区分初始化、观察与清理时间。初始化另有 600 秒超时；它不授权模型调用。

`Step(0, realSeconds)` 处理返回时也可能派发新任务，仍受剩余预算和 600 秒截止约束。到期后停止 Tick 和新提供方受理；有在途时保留未完成包，不能把未完成 trace 标为完成。已发送请求的清理、指标读取、导出和回放不延长该世界的观察期。协调器另给结果写出 60 秒宽限，超过则停止批次；宽限不允许继续推进或调用。

每次 Step 后立即提取新增 `meeting.say` 宿主结果对应的当前会面 transcript；同一步涉及早档 Load 时，采样须在 Load 前完成。正常推进或一组阶段命令完成后记录进度；每条阶段命令的输入时序、检查点和终态由实验包保留。仅检查最终快照会丢失后来被会面覆盖或读档放弃的台词，不能据此统计全程表达。

Live 的快照阶段只采用上述预登记检查点。额外故障、交付前后和未来记忆回退由固定测试验证；真实模型自然未达的阶段记 `not_reached`。8 秒请求/12 秒决策期限、观察有效期和 32 次费用上限都可能限制互动覆盖，报告实际达到的阶段，不追加调用取得预期剧情。

## 5. 执行架构与证据目录

[Python 协调器](../../Tools/agent_proxy/run_four_agent_integration.py)使用**一个进程，依序创建 16 个独立代理实例**；同时只开放当前世界的 HTTP loopback 端点。每世界有独立代理计数、测量、日志和临时端口，全批共享同一份锁保护的提供方尝试账本。每次转发前原子核账，成功、失败和纠正均消耗额度；拒绝转发的宿主请求与真正提供方尝试分别统计。

[Unity 矩阵入口](../../Assets/CozyTown/Tests/PlayMode/AgentIntegrationMatrixPlayModeTests.cs)在**一个 Unity 进程**内读取已登记世界，逐世界加载新场景、装配新服务、核验初态并执行脚本。已完成世界再新建场景做 Replay。固定运行不创建模型代理；回放使用录制响应，不调用提供方。普通 Bootstrap 的隐式环境代理入口在测试内隔离并于结束恢复。

协调器先发布当前 `options.json`，Unity 写出 `initial.json` 和 `initialized.json`；初始化核验通过后，协调器写 `start.json` 并允许当前代理受理。到期写 `stop.json`。Unity 写出 `result.json`，协调器核对世界身份、状态、宿主违规和回放结果后决定是否开启下一世界。结束代理先停止新接入，再按独立单调时钟最多等待 30 秒；未结束的请求保留在途数量，进程仍存活且请求返回时继续记录晚返回日志，整批停止且不启动下一世界。清理超时不能记为已经排空，也不延长世界观察期。

| 证据 | 内容与用途 |
| --- | --- |
| 批次 `plan.json` | 16 个预登记世界、版本、组序、预算、脚本、源码及提示词摘要 |
| 批次 `status.json`、`ledger.jsonl` | 世界状态、真正提供方尝试的计数与时间；未开始、失败和中断条目保留 |
| 每世界 `options.json`、`initial.json`、握手与 `result.json` | 实际输入、完整初态、执行状态、宿主错误、时间和回放结果 |
| `timeline.jsonl`、`progress.json` | 逐次推进的游戏/现实时刻、世界代次、请求、等待、活动、会面、目标及身体状态；后者仅为最新视图 |
| `proxy.jsonl`、包内测量 | 请求对应的原始候选、失败、实际模型及可取得的用量；候选最多 16 KiB，截断须显式标记 |
| `speech.json` | 所有被宿主接受的 `meeting.say` 对应记录，含缺证行；用于后续全量表达评阅 |
| `package/`、完成时的 `replay/` | manifest、初态、检查点、终态、请求/结果轨迹与已记录输入；回放保留源实验身份 |

测量使用只读 `/status` 与 `/measurements`，不增加模型调用，按当前请求的 `decisionId`、`step`、`npcId` 关联。读取失败保留已有报告及失败原因；未取得的 token、型号、费用或完成时钟记未知。原始候选即使未解析或被拒绝也保留；不能从行动响应缺少费用推断免费。凭据只由 Python 从仓库外文件读取，不写入参数值、世界配置、请求上下文、日志或实验包。

运行目录必须新建，现有证据不能覆盖或断点续跑。协调器中断后的已尝试调用保留；不得另起进程为原世界恢复 32 次额度。确需后继实验时先登记新批次及追加预算，并在累计成本中包括失败批次。

操作命令使用占位符，须在冻结候选的仓库根目录执行。先运行零模型调用的协调演练：


Unity 启动进程设置 `COZYTOWN_RUN_FOUR_AGENT_INTEGRATION=1` 和 `COZYTOWN_INTEGRATION_STUDY_DIRECTORY=<study-directory>`，仅执行 `CozyTown.Tests.PlayMode.AgentIntegrationMatrixPlayModeTests.CoordinatedMatrix_ExecutesOnlyRegisteredFreshWorlds`。输出目录须与协调器一致，保留 Unity 日志及测试 XML。Unity 由中央运行入口统一启动；同一检出不得并行开启两个 Unity 进程。若使用 PowerShell `Start-Process`，按运行约束传入 `-WindowStyle Hidden`。

## 6. 首次上下文分歧与公平比较

完成后按配对身份比较记录的请求调用顺序及规范化正文，定位第一次上下文分歧。以 `callOrdinal` 逐项对应，不重新排序或按文本相似度挑选配对。客户端生成配置须相同；允许的正文归一化仅为：

| JSON 路径 | 归一化规则 |
| --- | --- |
| `/expression/mode` | 核实一组 `free_text`、另一组 `structured_facts` 后归一为配对标记；嵌套版本仍须为 1 |
| `/worldRunId`、`/observation/worldRunId`、`/decisionId`、`/social/meetingId` | 按首次出现顺序作各类型的一一映射，跨调用保留引用关系；空会面身份保留为空 |
| `/observation/facts/*/factId`、`/observation/facts/*/entityId` | 仅映射 `meeting:<32位GUID>` 或 `statement:<32位GUID>` 中的会面身份，后缀及其他内容保持不变 |

顶层行动版本、事实值、数量、来源、权限、文本、请求中的游戏时刻及全部其他字段仍比较。正文中任意 GUID 样式字符串不自动忽略。`dispatchRealSeconds` 的墙钟微差及 trace Tick 作为定位元数据记录，不作为请求正文不等的判据；正文游戏时刻差异会形成分歧。

输出首次分歧的字段路径、原因、两侧调用序号、Tick、游戏时刻及现实时间；缺少对应调用也算分歧。未发现差异只说明已记录请求前缀匹配。F/S 自主选择一旦改变事实或时间，后续台词须分别按各自上下文评阅，不能声称逐句输入仍相同。此比较不放宽独立 Replay 的严格检查。

## 7. 表达证据与评阅记录

表达以全量已接受 `meeting.say` 结果为采样集合，每条结果都保留一行，`sampleId` 由实验身份和 `outcomeIndex` 组成。相同文本、读档前后及不同世界代次分别保留，不按文本去重采样。采集记录与 accepted speech outcome 数须相等；无法取得对应台词时保留原行、身份及 `missingReason`。

[AgentExperimentSpeechEvidenceCollector](../../Assets/CozyTown/Unity/Experiments/AgentExperimentSpeechEvidence.cs)仅从当前匹配世界、会面、说话者和轮次的已提交 transcript 取文本，记录 `worldRunId`、`decisionId`、`npcId`、`meetingId`、`turnIndex`、游戏时刻、`runMode` 与 `source=committed_transcript`。缺证时不从候选重建。该来源证明宿主提交台词；没有逐帧画面证据时，不称为已验证每句实际显示。Fixed、Live、Replay 的同名来源按 `runMode` 分开。

候选处理、已提交表达和互动结果分别评阅：被拒绝候选进入候选统计，不算已展示的表达错误；S 候选没有最终自然语言时以宿主 transcript 为准。评阅包仅提供该角色当时获准读取及向当前听众表达的观察、执行观察和有效经历。全局资产与隐藏事实用于宿主核查，不为角色的无依据陈述补证。

本批为自主会话，预登记问题为 `null`、目标事实集合为 `[]`。不计算固定问答的完整有效回应率或目标事实覆盖率；可根据记录的会话目标评价相关性、重复、事实及人格配置。若后续增加固定问题，须在其首个调用前另登记问题、允许表达的目标事实、初态与预算，保留为独立样本池。

每条评阅记录至少包括：

| 类别 | 保留字段 |
| --- | --- |
| 身份与证据 | 样本/实验/世界/决策/会面/说话者/听众/轮次、原文、来源、时间、请求和执行观察引用、缺证原因 |
| 最小事实断言 | 断言 ID、文本范围、主体、谓词、值/单位、所指时间、来源、事实引用及 `canExpress`；纯愿望或主观态度单列 |
| 判定 | 矛盾、无依据、来源/时间误用、越权等明确问题标签；相关但不完整、可答却拒答、合理未知；歧义的不同读法及其判定理由 |
| 互动与人物 | 该轮目标、相关信息增量、会话内逐字及语义重复；相对已登记偏好/表达习惯/语境的支持、冲突或证据不足 |
| 评阅过程 | 人工或代理、评阅者及版本、是否隐藏组别、原始独立判定、分歧与裁决理由 |

本轮由执行会话中的 Codex 代理进行两次独立评阅，覆盖全部已采集台词；分歧由主代理记录裁决与依据。评阅包隐藏组别及提供方型号，但 S 句型可能暴露组别，不能因此宣称完全盲评。记录评阅代理身份；实际模型版本标识若不可取得则记未知。评阅不调用 DeepSeek 端点，不增加本批 512 次世界决策预算；工作会话的 Codex 用量不纳入 DeepSeek 成本。

代理判断不是宿主已验证事实。报告列出两次实际覆盖的样本数、未复核数量及分歧，不把尚未复核样本称为一致。如果另用外部模型服务评阅，须在调用前独立登记模型、版本和新增预算。本文不预填真实输出或判定结论。

## 8. 指标、原分母与停止规则

F、S 各自列出计划 8 个世界及每世界状态，合计仍为原计划 16 个世界。初始化失败、基础设施中断、超时、无输出、拒绝和未达阶段均保留。若报告排除基础设施失败的条件统计，须同时列原始分母和被排除身份/原因，不能用替补世界降低失败比例。

| 指标 | 分母或报告单位 |
| --- | --- |
| 世界与覆盖 | 原计划世界数、初始化通过数、完成/未完成/中断/未开始数；每人触发、派发、等待、回退、会面阶段及第二天恢复分别列数 |
| 首候选通过率、最终决策成功率 | 全部已发起逻辑决策；无响应或首候选未解析仍保留，一次逻辑决策最终成功最多计一次；实际执行结果另列 |
| 响应解析率 | 实际收到的原始响应，首请求与纠正分开；空响应、截断和解析失败保留 |
| 有输出与缺证 | 全部已接受 speech outcomes、成功采集文本数、缺证行数、无事实信息输出数；含明确问题输出按唯一输出去重 |
| 断言问题 | 全部断言数、可评阅断言数 N、明确问题、歧义和评阅记录缺失分别列数。主表为明确问题/N；保守表为明确问题与歧义的去重并集/N |
| 相关性、重复与人物 | 按场景、会话、角色给出适用样本数及逐例依据；无预登记问题或目标事实的覆盖指标为不适用 |
| 调用与成本 | 宿主请求、真正提供方尝试、收到响应数；输入/输出 token、纠正及失败消耗；实际返回型号；有明确价格依据时才折算费用 |
| 时间 | 请求往返、完成后等待宿主处理、整次决策和预算等待分别报告计时边界、有效样本数及分位数；缺少时钟记未知 |

每个比例显示 `n/N`，零分母记不适用。多标签不增加唯一断言或问题输出数。主表与保守表使用同一批样本和同一 N；有明确问题的输出再含歧义也不重复计为两条。只有评阅记录本身缺失才从两表 N 同时排除；角色缺少证据却作具体断言属于无依据，仍计入 N。缺少 token、价格或模型名不得填零。

宿主资产、授权投影、受控表达、预算、旧响应、恢复或严格回放出现违规时，停止后续付费世界并保留全部账本、包和错误。初始化失败、通信/导出失败及结果超时也停止批次。已启动世界的所有失败尝试计入成本；未开始世界不伪作完成。模型合法拒绝、纠正、超时、过期观察或表达质量低按原标准报告，不自动等同于宿主缺陷。

修复后的候选及新增实验使用新的版本和批次身份，不能混入原样本池。有限样本的零错误写为本批观察，不外推为长期错误率保证。真实调用前仍须完成候选、固定脚本计数、协调演练、当前候选硬约束证据和评阅输入核对；完成后的报告提供 H01–H07 映射、实际执行清单、F/S 分项结果、全部失败及限制，再交接候选交付验收。

# NPC 局部观察实施与验证

对应任务：[实现 NPC 按区域与距离的局部观察](https://github.com/qinjunw/CozyTown/issues/73)。实施基准为 `cd2daae033b0311200637922156279c9224f8ca1`，规格见 [NPC 局部观察与事实表达边界](../AGENT_LOCAL_OBSERVATION_SPEC.md)。完整固定回归通过；本轮真实模型调用为 **0**。

此前请求提供目标、本人资源及会面阶段，没有实际局部对象。本次新增不可变观察投影，并接入首次请求和执行前复核。结果、测试名称、原始 XML 哈希及受测文件的字节／Git 对象哈希见[机器可读记录](npc-local-observation-2026-09-14.json)。

## 公开测试边界与顺序

沿用地图的实施授权，通过普通 C# 观察读取、世界时钟、居民身体、经济状态、会面、决策客户端及 JSON 边界验证：

1. 根据实际位置、区域和距离读取对象，验证途中、边界及旧快照。
2. 区分对象外观、交互语义及未知资源数量。
3. 在权限和空间筛选之后裁剪附近清单，区分完整空清单与未覆盖区域。
4. 装配本人相关资产、参与者条款和带来源时间的记录。
5. 在实际发出请求时采样，候选执行前检查当前事实；保留旧候选和失效原因。
6. 通过生产场景接线及 HTTP JSON 检查事实输入，并运行既有固定回归。

每个行为切片先记录失败，再实现并复测。Unity 使用独立检出；共享工作区的美术、农田和场景修改不进入测试输入。

## 场景配置

首版使用 6 个世界单位的闭合距离阈值。Ren 的会面站位为 `(-3,-1.4)`，Sora 为 `(-3,0.4)`，池塘锚点为 `(0,-4)`；两站位均在此距离内。池塘区域为 `x∈[-5,4), y∈[-6,1)`，矩形包含最小边界、排除最大边界。住宅几何区域优先确定室内空间，活动目标不参与空间归属。附近已登记实体最多 8 个，先筛选、再按稳定 ID 排序裁剪。

默认目录只适用于匹配已提交开发地图锚点的场景；具体对象还需匹配场景中的池塘与路灯。未匹配场景使用空目录，可通过公开配置入口提供自己的区域和实体。区域与距离属于抽象感知规则，不包含朝向和视线遮挡。

| 登记内容 | 坐标或范围 | 语义来源 |
| --- | --- | --- |
| `pond` | `(0,-4)` | 已启用的 `Interaction Points/Pond`，类型必须为 Pond；登记 fishing 能力与鲤鱼这一种已建模产物，池中数量未知 |
| `lamp.shop_main_road` | `(-4.1875,-0.25)` | 已提交 `Town Lighting/Shop Main Road Lamp`；装饰，没有资源交互 |
| `lamp.player_home` | `(-4.8125,-4.5)` | 已提交 `Town Lighting/Player Home Lamp`；装饰，没有资源交互 |
| `lamp.west_lane_south` | `(-3.4375,3.625)` | 已提交 `Town Lighting/West Lane South Lamp`；在北侧区域，不进入池塘区观察 |
| 西／东／北侧户外区域 | 西 `[-16,-5)×[-6,1)`；东 `[4,16)×[-6,1)`；北 `[-16,16)×[1,16)` | 本轮冻结的逻辑区域，和池塘区域互不重叠 |
| 四家住宅空间 | 中心 x 为 `-10.5/-3.5/3.5/10.5`，各 `x±1.9`，`y∈[10,12.4)` | 已提交建筑轮廓；几何优先于活动状态，出门但仍在门内时继续归住宅空间 |

坐标核验允许 0.001 单位误差，通过后使用实际 Transform 坐标。读取默认目录会重新检查对象；失活或移出登记位置后不再提供该对象，旧快照保持原样。此目录没有把草地贴图或未登记植物解释成可采资源，也没有据鲤鱼条目宣称池塘只有一种鱼。

## 事实与执行规则

本人相关资产来自实时经济读取，完整钱包余额保留为私人决策信息。本次相关物品量、条款和凭据按当前参与者标记表达权限；对方私有资产不进入观察，权限筛选先于裁剪。人设仍来自原 `persona` 字段，不能当作观察或生产经历。

每条事实带主体、属性、值类型、单位、来源、观察者、时间和范围。零数量是已知数值；池中未建模数量使用 `unknown`。参与者发言保留原文、说话者与时间，最多提供最近 4 条；最近成功交付以历史凭据提供，不把过去交付量当作当前持有量。未增加第三人传播或环境观察记忆库。

首次实际派发时重新读取社交条件与观察，机会产生时刻和期限不变；需求已经满足的未发送机会被丢弃。查询和候选纠正保留原观察。首次采样、续调前及候选执行前校验角色、世界、当前采样时刻和听众；读取失败结束为 `agent.observation_unavailable`。有效新观察与原事实不同则结束为 `agent.observation_stale`，保留原候选和原上下文。

比较覆盖整个当前事实视图与身体坐标。这会保守拒绝移动后的候选，不能由本轮固定样本估计它对真实会面完成率的影响。观察刷新不增加模型机会，也不改变既有冷却、并发、调用预算或总期限。

| 实际开发场景 | 通过 | 加载基准提交的真实场景，默认启动器自动接线，实际身体赴约后两人均取得池塘事实 |

专项测试覆盖途中与到场、矩形边界、室内外、同区远物、旋转不变、装饰与未知鱼量、截断与完整空清单、隐藏居民、本人资源、历史声明、凭据、排队采样、私有资产反事实、读档和请求期间状态变化。每帧式重复读取 20 次不会新增模型调用。

实施期间先捕获失败，再补充行为。主要失败包括：缺少初始观察接口；收据被遗漏；排队余额已变为 24、旧社交上下文仍为 50；活动已出门而身体仍在住宅；对象失活／移动后仍被读取；观察返回错误角色、世界、时间、听众或抛异常时仍进入请求流程。对应固定回归现已通过，旧失败 XML 保留在本地 `Logs/local-observation-*.xml`，没有用后一次结果覆盖。

| 序列化样本 | 事实数／附近实体 | Unity UTF-8 字节 | 代理上下文字节 |
| --- | --- | --- | --- |
| 当前位置与未知池鱼量 | 6／1 | 3,241 | 3,537 |
| 8 个资源对象、4 条各 240 字中文发言、本人资源与交付凭据 | 48／8（清单截断） | 25,364 | 26,824 |

两个样本均低于 32,768 字节。第二个样本使用 6 轮的合成会面，超过默认会面需要同时携带的发言数量，用于验证有界清单和多字节文本的组合；这不构成任意长度内容均可装入请求的保证。过大的自定义人设或内容仍由原字节门禁拒绝。

独立审查发现并修复了默认目录状态不刷新、提议条款提前命名为“已同意”、观察绑定未检查和回调异常中断其他居民的问题。最后一次全量检查后，运行代码保持冻结；补充的请求容量测试通过后重新运行了全量 EditMode。

## 复现与后续

在独立检出中运行：

```text
python -m unittest discover -s Tools/agent_proxy -p "test_*.py" -v
<Unity> -batchmode -nographics -projectPath <checkout> -runTests -testPlatform EditMode -testFilter CozyTown.Tests -testResults <edit.xml> -logFile <edit.log>
<Unity> -batchmode -projectPath <checkout> -runTests -testPlatform PlayMode -testFilter CozyTown.Tests -testResults <play.xml> -logFile <play.log>
```

Unity 版本为 `6000.5.5f1`。PlayMode 使用图形设备，检查 Unity 进程退出码及 XML 中实际失败／跳过项；运行中不替换测试检出的源码或资产。生产默认目录应与本文基准地图匹配，定制场景需要显式配置。

真实模型的自由台词与结构化表达对照由[对照验证 NPC 自由台词与结构化事实表达](https://github.com/qinjunw/CozyTown/issues/74)执行。观察模块已经提供共同输入；本任务不能证明自由台词没有无依据断言，也没有解决[复现会面对话在日程变更与预算等待后的停滞](https://github.com/qinjunw/CozyTown/issues/72)或普通自主活动期限的独立问题。

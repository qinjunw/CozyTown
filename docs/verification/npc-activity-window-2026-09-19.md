## 实施合同与公开边界

自主 `visit` 的窗口截止是下一次默认目标或活动类型改变的时刻，排除只用于重建位置的到达检查点。每次派发披露剩余允许时长，执行时核对该次请求的约束。请求等待消耗了部分窗口时，合法活动仍须在原日程截止前结束；不延长截止，也不重新计算决策机会寿命。

通用可信活动入口和正式会面保留原合同。活动时长继续包含走路，到达不重新计时；到期从实际位置转向当时日程。玩家模态继续暂停自然游戏时钟，普通活动的游戏期限不因此减少；真实调用预算与超时继续计时。已接受会面的忙碌中断沿用原规则。

沿用地图已确定的公开测试边界：`NpcDecisionScheduler` 与外部固定客户端、协议编解码、角色状态／活动／会面、`CozyTownTownLifeController`、实际身体、世界时间及玩家交互门控。先保留目标失败，再实施最小行为，不读取私有状态。

| 场景 | 验收结果 |
| --- | --- |
| 当前窗口、分数分钟、下一天与跨午夜休息 | 披露真实活动切换截止及剩余上限；跨午夜活动在次日上班时释放 |
| 候选超过披露上限 | 原活动不变，最多一次纠正，续调沿用原预算与机会期限 |
| 排队、inspect／纠正期间世界推进 | 每次派发更新剩余量，先前请求保持不变，绝对截止不后移 |
| 回复在切换前后到达 | 有效回复受原截止限制，过期或旧修订回复不能覆盖新日程 |
| 短活动、同目标长意图、路途中到期 | 活动状态到期，身体从当前位置继续日程；不以已到达代替逻辑释放 |
| 大步／小步推进、暂停／恢复、会面释放后的普通活动 | 期限和移动一致，不增加模型调用来完成恢复检查 |
| 完整快照后继 | 保存实际接受的截止；加载不重新赠送整个窗口，也不重新执行交付 |

历史 720 分钟样本的 `recovered=false` 与原轨迹保留；本轮结果记录为新规则下的新验证。真实提供方调用不用于证明宿主期限规则。

## 失败复现与结果

| 行为 | RED 证据 | 实现后的结果 |
| --- | --- | --- |
| 休息窗口只剩 60 分钟却披露 1440 | [wire-red](npc-activity-window-2026-09-19/activity-window-wire-red.xml)，1 项失败 | 初次请求披露 60；分数分钟和下一天请求使用各自绝对窗口 |
| 720 派发、730 接受合法时长 60 | [body-red](npc-activity-window-2026-09-19/activity-window-body-red.xml)，1 项失败 | 截止从错误的 790 改为 780；770 已到工作点时活动仍有效，780 才释放 |
| 只披露 45 分钟却接受候选 720 | [codec-red](npc-activity-window-2026-09-19/activity-window-codec-red.xml)，1 项失败 | 响应解析返回可纠正的 `candidate.duration_invalid` |
| 直接客户端越界、续调沿用旧上限、回调后跨界派发 | [scheduler-red](npc-activity-window-2026-09-19/activity-window-scheduler-red.xml)，8 项失败 | Runtime 独立拒绝越界；续调／重配 Pending 重新披露剩余量；派发和执行前复核原窗口 |
| 一次纠正与原预算 | 新增 Runtime 用例 | 第二次越界结束，无第三次调用；没有余额时直接结束；原 30 分钟机会与现实总期限不延长 |
| 会面跨日程与释放 | 新增 Runtime 用例 | 双方会面在一人的上班时刻后继续；取消后仍处于休息的另一人只得到当前窗口剩余 20 分钟 |
| 路途中到期、大步／小步、模态暂停 | 新增 PlayMode 用例 | 到期从实际位置转向当前日程；暂停保留绝对截止，恢复后按期释放；验收阶段不再派发模型请求 |

四个 RED 阶段均保留测试源码与 XML。完整回归的首轮有两项旧测试仍期待零值／NaN 立即返回 `agent.deadline_invalid`；新规则把它们归入候选纠正。修订后，这两个控制用例以单次调用额度验证无余额时结束为 `agent.response_invalid`，并保留 `candidate.duration_invalid`。第一次修订误将同组地点查询也限制为一次调用，导致查询提前到达步数上限；第二次修订仅限制时长控制用例。两次失败均保留在运行清单，未删改结果。

## 输入与后继约束

[输入核验](npc-activity-window-2026-09-19/input-audit.json)比对 1,042 个文件，其中 349 个 C# 文件；仅叠加本票据 10 个源码、测试及 meta 文件。共享工作区的美术、农田和场景修改未进入隔离测试或本次交付。Unity 自动迁移的 ProjectSettings 与生成的 SceneTemplateSettings 记录为明确例外，保留[脱敏设置差异](npc-activity-window-2026-09-19/isolated-settings.diff)。

[运行清单](npc-activity-window-2026-09-19/manifest.json)记录 12 次 Unity 运行、过滤条件、退出码、原始 XML／日志摘要及最终源码摘要。[发布校验和](npc-activity-window-2026-09-19/checksums.json)固定发布文件。XML 仅替换本机路径、统一换行及去除行尾空白，逐项验证 test-case 属性不变；中间运行记录有序修改阶段，没有冻结各阶段二进制，输入摘要不等于 DLL／PDB 来源证明。

恢复日程先检查活动已释放、目标服从当时日程，再按实验需要检查身体最终到达。正式会面与可信宿主活动仍可使用各自跨日程期限。旧 720 分钟样本并未在本轮重跑，也未改判。

[快照契约 1.1](../AGENT_SNAPSHOT_SPEC.md)要求 S05 保存实际接受时刻与有效截止，S12 保存原普通窗口及机会期限，S13 保留调用与纠正进度；新请求的上限由实际派发时刻重新计算。当前存档仍为 schema v3，完整活动／会面续接和四人多日实验仍属后继工作。

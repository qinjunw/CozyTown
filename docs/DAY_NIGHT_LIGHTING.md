# 小镇天色与路灯

开发场景原先没有随时间变化的全局光照或路灯。L1 增加六种连续渐变的天色，以及道路和门前共 18 盏定时路灯，使用既有共享世界时间。对应 [Issue #48](https://github.com/qinjunw/CozyTown/issues/48)，开发基线为 `acd79350a70d41cf91e5fbfe6e08e9498ad833b1`。

## 时间与表现

用户列出七个时段名称并要求六种天色。本轮默认把早上至中午作为白天天色，使用六个关键点：深夜、黎明、白天、下午、傍晚、夜晚。六种颜色之间持续渐变，午夜也延续前后曲线。默认关键点为 02:00、05:30、09:00、15:00、18:00、20:00；颜色、强度和时间通过场景引用的配置资产调整。

路灯在 18:00–19:00 渐亮，19:00 至次日 05:00 保持点亮，05:00–06:00 随黎明渐灭，其余时间关闭局部照明与灯芯发光。灯柱白天仍可见。

天色读取共享 `IWorldTimeFlow` 的时分和小数分钟，不增加独立世界时钟。菜单与失焦暂停沿用共享时间；睡眠、成功读档直接恢复目标时刻的灯光，失败操作保留当前画面。光照是从时间推导的表现状态，不增加存档字段。

全局 `Light2D` 调整世界环境色与强度，局部灯照亮道路和门口，HUD 保持原本显示。现有 2D 材质已支持受光。新灯具保持原生像素网格、16 PPU、固定素材色板与硬透明边缘，沿用 `.pixels` 源文件和项目编译管线。

## 验收入口

- 公开天色取样：白天、傍晚与深夜存在可见差异，关键点和午夜附近连续，小数分钟推进也改变过渡中的颜色；灯光窗口的起点、中点和终点符合上述时刻。
- 共享时间与场景灯光：自然走时、暂停、睡眠、成功／失败加载、晚绑定、重新绑定和销毁订阅保持一致；不访问用户存档。
- 正式场景：各家门口与道路有灯柱，局部照明在晚间可见；新增物体不阻挡道路、门口或既有交互，保持居民通勤和碰撞回归。
- 图形输出：使用正式相机核验六种天色、夜间灯池和日间熄灯，输出截图供复查；自动检查不代替既有 Scene-01、Town-01 人工验收。

经济规则、住宅布局、道路导航、真实 AI 和 UI 交互不在本轮变更范围。

## 配置与维护

正式场景的 `World/Town Lighting` 持有控制器、全局光源和路灯。`CozyTownBootstrap` 在初始化时只注入 `IWorldTimeFlow`；灯光组件读取时间变化事件，不自行推进时间。`TownLightingProfile.Evaluate` 对相邻关键点的颜色和强度使用 SmoothStep 插值，路灯开关窗口也使用同样的缓入缓出曲线。

在 Inspector 中编辑 [`DefaultTownLighting.asset`](../Assets/CozyTown/Content/DefaultTownLighting.asset) 的 Keyframes。时刻使用从午夜开始的分钟数，必须严格递增；默认值如下：

| 天色 | 时刻 | 分钟数 | 环境光 RGB | 强度 |
| --- | --- | --- | --- | --- |
| 深夜 | 02:00 | 120 | 0.54 / 0.62 / 0.90 | 0.35 |
| 黎明 | 05:30 | 330 | 1.00 / 0.79 / 0.74 | 0.65 |
| 白天（早上至中午） | 09:00 | 540 | 1.00 / 0.98 / 0.94 | 1.00 |
| 下午 | 15:00 | 900 | 1.00 / 0.91 / 0.75 | 0.95 |
| 傍晚 | 18:00 | 1080 | 1.00 / 0.65 / 0.48 | 0.67 |
| 夜晚 | 20:00 | 1200 | 0.65 / 0.67 / 1.00 | 0.48 |

关键点代表该时刻的天色，时刻之间持续变化。调整路灯窗口使用同一资产的 Lamp Fade 字段；熄灯窗口必须在亮灯窗口之前且二者不重叠。

四户 NPC 住宅、玩家住宅、商店、鸡舍和厨房旁各放置一盏灯，另有十盏沿主街、连接道路和住宅街放置。灯柱与灯芯使用同一个 SortingGroup，按灯脚位置与角色进行 Y 轴排序；屋顶前景仍使用既有前景层。灯具不添加碰撞或交互组件。

已提交的场景可以直接运行。重新生成灯具素材时，在非 Play 模式下依次执行：

1. `CozyTown > Art > Build Town Lighting Pixel Art`：从 [L1 源文件](../ArtSource/Authored/L1/README.md) 编译灯柱与灯芯两个 Sprite。
2. `CozyTown > Upgrade Development Scene Lighting`：创建或重新配置标准灯位和场景接线，保留现有天色配置资产。该菜单会将灯位恢复为标准坐标。

## 验证记录

新增 23 项 EditMode 测试覆盖关键点、午夜和灯光窗口的连续性，以及共享时间绑定；8 项 PlayMode 测试覆盖初始化先后顺序、睡眠、存档成功／失败、禁用视图、重新绑定、销毁、暂停和正式场景渲染。

2026-09-09 在代码提交 `62efa33` 上完成全量回归：EditMode **491/491**、图形 PlayMode **149/149**，均为 0 失败、0 跳过，Unity 退出码为 0。独立规范复核已关闭公开配置数组的隔离问题，需求复核为 0 项剩余问题。

图形测试使用正式相机、原有受光材质和 960×540 输出。测试从相同深夜画面临时关闭路灯，比较灯柱旁不含灯具 Sprite 的路面区域，从而检查局部照明是否作用于道路。截图来自固定测试时间，未修改玩家存档。完整运行结果和测量见 [verification.json](verification/day-night-lighting-2026-09-09.json)。

最终实测白天／深夜全图平均亮度为 `0.4663 / 0.2506`；相同深夜路面在开灯／关灯时为 `0.3797 / 0.2527`，差值 `0.1270`。六个时刻的全图平均 RGB 两两距离均超过 `0.01`。这些数值是截图像素的归一化测量，不是物理照度单位。

重复执行场景升级后，场景与配置资产逐字节一致。与开发基线比较，场景新增内容全部属于灯光树；原有序列化块仅修改 World 子节点列表和 Bootstrap 的灯光引用，未发现其余原有块变化。

### 1.1 T1 时间规则补充（2026-09-05）

[ADR-0014](adr/0014-continuous-world-time-and-morning-settlement.md) 已获确认，覆盖下文 FR-009 和旧“睡觉推进一天”的约定：世界时间自然跨午夜，每日 05:00 结算生产并替换商店库存；睡眠选择 1～12 个整小时，正常走时与睡眠共用同一时间推进用例。菜单/失焦暂停规则保留，不加入凌晨强制昏倒、体力或出货系统。NPC 的独立日程与通勤仍由 T1 后续切片完成，不以时间模块的实现替代其验收。

## 2. 产品定义

玩家在单一小镇内通过种植、养鸡、钓鱼和商店获取物品，使用食材烹饪或出售物品，再以所得金币购买下一轮生产资料。NPC 对话提供角色反馈和世界信息；AI 生成对话时不改变金币、物品、时间、生产进度或存档。

### 2.1 目标用户

主要用户是希望在短时游玩中完成收集、生产和交易循环的生活模拟游戏玩家。MVP 使用有限地图、物品和配方，使玩家能在一次演示中接触全部系统。

次要读者是评估项目工程能力和 AI 应用能力的面试官或协作者。仓库需要提供可运行代码、自动化测试、AI 边界和可复核的评测数据，而不是以生成内容数量代替工程证据。

### 2.2 产品目标

- 在一座小镇内形成“购买生产资料—获取食材—烹饪或出售—获得金币”的闭环。
- 每个采集系统至少向烹饪或交易提供一种有效输入。
- NPC 对话支持固定实现和 AI 实现互换，模型故障时仍可继续交互。
- 游戏状态可以写入并恢复一个本地存档槽位。
- 各系统通过公开接口组合，支持独立组件测试。

## 3. 核心循环

```text
购买种子、饲料或基础食材
          ↓
种植 / 喂鸡 / 钓鱼
          ↓
获得作物、鸡蛋或鱼
          ↓
直接出售或按配方烹饪
          ↓
获得金币或料理
          ↓
睡觉推进一天并开始下一轮
```

NPC 对话可在循环中的小镇交互点触发，但不会替代交易、生产或时间推进规则。

## 4. 范围

### 4.1 MVP 功能

| 模块 | MVP 内容 | 最小数量或边界 |
| --- | --- | --- |
| 地图 | 可步行的小镇与功能交互点；T1 扩展住宅区域 | 仍为 1 张小镇地图；不含野外 |
| 时间 | 已有天数/时间显示与睡觉；T1 计划增加日内自动走时 | 跨日统一结算；不含季节和复杂时刻表 |
| 背包 | 保存物品 ID 与数量；检查容量或堆叠规则 | 支持全部 MVP 物品 |
| 经济 | 金币余额、购买、出售和价格查询 | 余额不得为负；交易原子完成 |
| 商店 | 出售种子、饲料、盐、面粉等基础物资；回收允许出售的物品 | 1 个商店交互点 |
| 种植 | 播种、浇水、跨日生长和收获 | 3 种作物：土豆、胡萝卜、番茄 |
| 畜牧 | 喂鸡并在后续日期收取鸡蛋 | 1 种动物：鸡 |
| 钓鱼 | 在池塘触发简化判定并获得鱼 | 3 种鱼 |
| 烹饪 | 校验配方、消耗食材并生成料理 | 5 个固定配方 |
| NPC | 固定对话与可替换的 AI 对话生成；T1 计划增加住宅和确定性日程 | 沿用 Mina、Eli、Ren、Sora 四名 NPC |
| 存档 | 保存和读取持续性状态 | 1 个本地槽位 |
| AI 诊断 | 记录请求结果、延迟、结构校验和回退原因 | 仅开发或演示界面可见 |
| 常驻 UI | 紧凑 HUD、交互气泡、五格快捷栏、只读包裹和系统菜单 | 不包含物品使用、装备、拖放或设置项实现 |

### 4.2 配方基线

| 料理 | 食材 | 来源覆盖 |
| --- | --- | --- |
| 烤土豆 | 土豆、盐 | 种植、商店 |
| 蔬菜汤 | 胡萝卜、番茄 | 种植 |
| 烤鱼 | 鱼、盐 | 钓鱼、商店 |
| 番茄炒蛋 | 番茄、鸡蛋 | 种植、畜牧 |
| 鱼肉派 | 鱼、鸡蛋、面粉 | 钓鱼、畜牧、商店 |

具体物品 ID、配方采用的鱼种、售价、成长天数和鱼类概率由后续平衡数据定义。配方所需数量必须由数据配置或单一规则源提供，不在 UI 中重复维护。

### 4.3 非目标

- 战斗、怪物收集和角色等级系统
- 野外地图、地牢和跨区域旅行
- 季节、天气、随机或按星期变化的复杂 NPC 日程；T1 的固定日内作息为本轮新增范围
- 恋爱、婚姻、建筑升级和多种畜牧动物
- 多人游戏、云存档和跨设备同步
- AI 生成任务、价格、掉落、配方或存档状态
- 在 Unity 客户端中保存模型服务密钥

| FR-020 | 包裹、系统菜单和既有业务模态共享同一玩家输入门；任一界面打开时阻止移动与场景交互，并拒绝打开第二个模态界面。 |
| FR-021 | 功能建筑及 T1 新增住宅、农田和池塘具有语义占地对应的禁止通行边界；建筑只在门口保留短距离进入槽，上部屋后通行与遮挡按既有规则处理，池塘从可达岸边一圈提供钓鱼交互。 |
| FR-022 | Mina、Eli、Ren 和 Sora 保持四个独立稳定身份；户外位置合法且不与世界障碍重叠，与任一 NPC 交互时只打开其对话。T1 行走中允许人物交叠，居家时隐藏身体及交互，不沿用静态站位间距作为全过程约束。 |
| FR-023 | 系统菜单主按钮保持足够的文字/底色对比；右上入口只显示清晰的灰色齿轮，不显示按钮底框。 |
| FR-024 | T1 扩大同一小镇并为四名 NPC 各配置独立住宅，保留玩家住宅及原有功能入口；相机跟随玩家且不露出地图外空白。 |
| FR-025 | T1 NPC 根据各自人设与确定性日程，从住宅出发、到达职业/休息地点并在日落归家；身体、交互和朝向跟随实际移动，进屋完成后才隐藏。 |
| FR-026 | T1 日内时钟与 NPC 生活受统一暂停规则控制；自动走时不得绕过跨日结算，睡觉或加载失败不得发布新的日程世界状态。 |
| FR-027 | T1 职业活动不生成或消耗经济资源，不修改商店营业权限；日程与位置只向后续 Agent 提供只读事实。 |
| FR-028 | T1 必须明确成功加载时 NPC 世界状态的恢复规则，并测试昼间、夜间与通勤状态；未经快照与迁移设计，不承诺途中位置精确恢复。 |

## 6. 主要用例

### UC-01 购买并种植作物

1. 玩家打开商店并选择种子。
2. 系统校验价格、余额和背包接收条件。
3. 交易成功后，金币减少且种子进入背包。
4. 玩家在可用地块播种并浇水。
5. 玩家推进天数，作物按规则成长并最终可收获。

异常结果：余额不足、背包拒绝物品或地块不可播种时，所有相关状态保持不变，并返回可显示的失败原因。

### UC-02 养鸡并收取鸡蛋

1. 玩家持有饲料并对鸡执行喂食。
2. 系统消耗一份饲料并记录当天喂食状态。
3. 玩家推进到后续日期。
4. 满足产出规则时，玩家收取鸡蛋并加入背包。

### UC-03 钓鱼并烹饪

1. 玩家在钓鱼点触发钓鱼。
2. 成功结果向背包添加一种鱼。
3. 玩家在厨房选择已解锁的固定配方。
4. 系统校验食材并原子执行消耗与成品添加。

### UC-04 交易并继续生产循环

1. 玩家选择可出售的原料或料理。
2. 系统按当前价格减少物品并增加金币。
3. 玩家使用所得金币购买下一轮种子、饲料或基础食材。

### UC-05 与 NPC 对话

1. 玩家与 NPC 交互。
2. 游戏构造 NPC 身份、当前天数和相关事件的只读快照。
3. 对话生成器返回文本和允许的表现标签。
4. 生成失败时，系统改用该 NPC 的固定对话。
5. 显示对话前不执行任何经济、背包、时间或生产状态修改。

### UC-06 保存并恢复

1. 玩家触发保存。
2. 系统从各持续性模块创建同一时点的存档快照并写入单槽位。
3. 重新进入游戏后读取并校验版本。
4. 系统恢复天数、金币、背包、农田、鸡舍和其他已定义的持续性状态。

### UC-07 使用常驻 UI 与包裹

1. 玩家在世界中移动；靠近最近的可交互对象时，其上方显示 `E` 气泡。
2. 玩家按 `1` 至 `5` 切换快捷栏选中格；该操作不消耗或使用物品。
3. 玩家按 `B` 打开只读包裹；移动、场景交互和其他模态入口暂时不可用。
4. 玩家再次按 `B` 关闭包裹，玩家控制恢复。
5. 玩家点击右上角齿轮打开系统菜单，并从主页面执行保存、读取、进入设置占位页或离开游戏。

异常结果：已有业务模态占用输入门时，包裹和系统菜单保持关闭；系统菜单或包裹已打开时，场景交互气泡保持隐藏。

## 7. MVP 验收

### 7.1 架构骨架阶段

- `Time`、`Inventory`、`Economy`、`Farming`、`Livestock`、`Fishing`、`Cooking`、`Npc` 和 `Save` 均具有公开接口与最小确定性实现。
- `CozyTownCompositionRoot.Create(configuration)` 或 `CreateEmpty()` 显式创建各模块实现，并通过类型化属性公开服务。
- 默认实现不依赖可玩场景、网络连接或线上模型服务即可实例化。
- 每个模块至少有一个成功路径和一个拒绝路径的 EditMode 组件测试；跨模块原子操作包含状态不部分提交的测试。
- AI 对话使用固定实现或测试替身，并有测试证明其不能取得确定性状态的写接口。
- Unity Test Runner 可发现 EditMode 测试；批处理验证同时保留本次生成的 XML 结果和 Editor 日志。

### 7.2 可玩 MVP 阶段

- 玩家能在单一小镇场景完成购买、种植、浇水、跨日成长和收获。
- 玩家能喂鸡并在后续日期获得鸡蛋。
- 玩家能从 3 种鱼中获得钓鱼结果。
- 5 个配方均可使用约定来源的食材制作；缺少食材时不发生部分扣除。
- 玩家能出售至少一种原料和一种料理，再用所得金币购买生产资料。
- 玩家能与 3 至 4 名 NPC 对话；模拟 AI 超时或无效输出时显示固定回退文本。
- 保存并重新加载后，持续性状态与保存时一致。
- 从新游戏开始可在一次演示流程中完成至少一个“投入—生产—加工或出售—再投入”闭环。

### 7.3 A1 独立美术阶段

A1 在不改变玩法范围、领域规则和交互语义的前提下，把已验收的 Production 像素资源接入正式场景。该阶段是 M4 与 M5 之间的独立交付阶段，不改变 M0～M5 的产品里程碑划分。

- 正式场景使用 Production 地图、建筑、功能物件、玩家、世界 NPC 和状态 Sprite，不再以 Unity 内置方块表示这些对象。
- 像素相机使用 `16 PPU`、`320×180` 参考分辨率和整数缩放；地图 Tile 在重复铺设时不得出现接缝。
- 玩家四方向静止与两帧移动能够按真实移动状态切换；农田与母鸡表现只映射既有只读状态。
- 七种交互语义、碰撞、模态输入、经济闭环、存档和固定 NPC 回退行为保持不变；Scene-01e 按 ADR-0008 将物理实体扩为 10 个。
- 世界表现、状态表现和 UI 皮肤按独立垂直切片接入；只有全部 Scene-01 自动化与人工检查通过后，才完成场景验收。

Scene-01 通过前不接入真实 AI 驱动 NPC，不执行真实模型评测、联网诊断或相关演示录制。既有固定对话、受约束 AI 边界和故障替身继续作为回归基线。

### 7.4 Scene-01d UI 信息架构重构

Scene-01d 是人工 Scene-01 验收前的 UI 收口切片，只改变信息组织、输入路由和表现资源，不改变领域规则、交互点数量或存档格式。

- 左上 HUD 只显示天数、时间和金币；右上只保留 `16×16` 齿轮入口；旧左下交互面板从正式场景退役。
- 交互提示改为跟随当前最近目标锚点的 `E` 气泡；目标变化、离开范围、Interactor 停用或模态输入门被占用时立即隐藏。
- 底部中央固定五格快捷栏，显示 `1` 至 `5` 与只读包裹投影；数字键只改变选中格，不触发领域写操作。
- `B` 打开的包裹按既有容量显示物品图标、数量和空槽；包裹不提供拖放、丢弃、使用、装备或排序写操作。
- 齿轮打开系统菜单；保存和读取继续路由既有 `IGameSaveCoordinator`，设置页只提供范围说明与返回，离开游戏只调用 Unity 应用退出适配器。
- 系统菜单、包裹和既有业务模态复用 `PlayerModalInputGate2D` 的独占所有权，关闭、撤销或组件停用后恢复原有移动与交互状态。
- UI 继续使用近黑纯底、三层暖棕木框和既有按钮九宫格；新增资源仅限独立齿轮图标及现有交互标记气泡化，不引入新的 UI 主题。

### 7.5 Scene-01e 场景碰撞、NPC 世界分布与 UI 可读性

Scene-01e 只修正人工检查暴露的可达空间、NPC 世界表达和 UI 对比度，不增加室内场景、NPC 日程、任务、农田逐格移动或新的设置功能。

- 七种交互语义保持不变；物理交互实体变为 10 个，其中四名 NPC 各有稳定 ID、独立世界 Sprite、合法站位和独立对话入口。
- 商店、住宅、鸡舍和厨房只有门口槽可进入并触发业务界面；玩家不能穿越其余建筑占地。

## 8. AI 输入、输出和指标

### 8.1 输入边界

允许输入：NPC 稳定 ID、人设摘要、当前天数、有限的近期事件、与该 NPC 相关的关系值和必要的世界设定片段。

禁止输入：模型服务密钥、可变对象引用、存档写句柄、钱包或背包写接口，以及完成交易所需的授权令牌。

### 8.2 输出契约

AI 响应解析为以下候选数据：

- `text`：显示给玩家的对话文本；
- `emotion`：允许列表中的情绪标签；
- `action`：允许列表中的表现标签，可省略；
未识别字段被忽略；缺少必需字段、标签越界或文本未通过内容规则时触发固定回退。诊断关联 ID 由调用适配器生成，不由模型决定。输出契约不包含金币、物品、时间、任务或存档变更命令。

### 8.3 评测集

发布演示版本前建立不少于 30 条固定评测用例，覆盖：

- 3 至 4 名 NPC 的基本人设与说话方式；
- 不同天数及近期种植、钓鱼、交易事件；
- 玩家诱导 NPC 修改金币、赠送物品或覆盖规则的输入；
- 超时、空响应、格式错误、未知标签和服务不可用；
- 重复请求与固定输入的回归比较。

### 8.4 发布目标

| 指标 | 目标 | 测量方法 |
| --- | --- | --- |
| 结构有效率 | ≥ 99% | 有效解析响应数 / 收到的响应数 |
| 人设一致通过率 | ≥ 90% | 评测规则与人工复核共同判定 |
| 世界状态矛盾率 | ≤ 5% | 与输入快照冲突的响应数 / 有效响应数 |
| 状态越权执行数 | 0 | 验证 AI 输出到确定性状态之间不存在写调用 |
| 故障回退成功率 | 100% | 注入超时、异常和无效响应后仍返回可显示文本 |
| 对话延迟 | 记录 P50、P95；目标在服务选型后锁定 | 从请求开始到有效文本或回退文本可用 |
| 单次调用成本 | 记录输入、输出 Token 和估算费用；目标在服务选型后锁定 | 按提供商计量数据汇总 |

日志不得记录服务密钥。若保存完整提示词或响应供评测使用，开发构建需要提供关闭开关，并对玩家自定义文本执行最小化或脱敏处理。

## 9. 完成定义

MVP 完成需要同时满足可玩验收、EditMode 自动化测试、一次从新游戏到重新投入的录屏证据、AI 固定评测报告，以及 AI 服务失效时的回退演示。仅完成接口骨架不构成可玩 MVP 完成。

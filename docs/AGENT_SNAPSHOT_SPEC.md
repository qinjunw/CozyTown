## 1. 恢复行为选择

用户已确认完整逻辑快照是第一版目标，并采纳以下三项方案。当前代码仍按日程安置 NPC，清除临时活动、会面及经历；本节规定后继实现的目标行为。

| 选择 | 已采用方案与例子 | 未采用方案与代价 | 状态 |
| --- | --- | --- | --- |
| Q1 人物位置 | 恢复实际位置和路线执行进度。Ren 保存时走到路中，读取后从同一点继续；受阻状态也保留 | 按保存时刻的日程重新安置；不能称作原行程的精确恢复 | 已确认 |
| Q2 进行中互动 | 恢复双方已确认的阶段、预约、交付结果和未完成轮次。保存时已交鱼、正在等 Sora 发言，读取后保留鱼钱变化，继续该轮或按原限制回退 | 记录读档中止并结束互动；损失原实验阶段的连续性 | 已确认 |
| Q3 旧档兼容 | v1–v3 保留已有世界和资产，NPC 按日程初始化，缺失经历与承诺为空，记录迁移来源 | 旧档只保留查看，实验从新档开始；失去已有世界的继续运行入口 | 已确认 |

第 3–8 节为后继实现和验收使用的契约。普通活动的最长时限与“恢复日程”判定由[独立票据](https://github.com/qinjunw/CozyTown/issues/70)决定；本契约保存原始开始、截止时刻，不在读档时重新延长期限。

## 2. 当前数据与接口的差距

[GameSaveSnapshot](../Assets/CozyTown/Runtime/Save/GameSaveSnapshot.cs) 的 schema v3 包含世界种子、整数分钟、角色／商店资产、农田和畜牧。[GameSaveCoordinator](../Assets/CozyTown/Runtime/Application/GameSaveCoordinator.cs)依次恢复这些模块；[DaytimeClockCoordinator](../Assets/CozyTown/Runtime/Application/DaytimeClockCoordinator.cs)在成功加载后清零小数余量并发布重建通知。通知及失败边界见[存读档研究](research/npc-agent/save-load-lifecycle-2026-09-16.md)。

现有 `NpcAgentSnapshot` 和 `NpcMeetingSnapshot` 是查询视图：前者不含活动开始时刻和事件队列；后者不含完整计划、预约时段及活动归属。`TakeEvents` 会消费通知，保存不能借它读取事件。[世界状态](../Assets/CozyTown/Runtime/NpcAgents/NpcAgentWorld.cs)与[会面板](../Assets/CozyTown/Runtime/NpcAgents/NpcMeetingBoard.cs)需要独立的无副作用导出和受校验恢复边界。

身体也存在独立逻辑状态。[TownRouteFollower2D](../Assets/CozyTown/Unity/Town/TownRouteFollower2D.cs)的路径、游标、受阻和已重规划标记影响后续移动；其 `Clone()` 只服务于内存操作。只恢复坐标后调用 `SetDestination` 会改变这些状态，不能直接当作行为等价的恢复。

## 4. 保存和加载的提交边界

### 4.1 保存

在一次主线程逻辑更新完成、没有活动／会面／交易部分提交的边界读取全部数据。保存期间不推进游戏时间、不消费事件、不触发模型、不改变冷却和行为。网络完成可以继续发生，但回调不能绕开主线程提交；尚未应用的回复仍属于未完成执行。

使用一份统一时刻及采样身份捕获经济、生产、活动、会面、逻辑待办和身体。捕获失败不写文件；成功后得到与活对象分离的数据，再沿用现有临时文件、复读校验及替换流程。保存 UI 引起的临时输入禁用不成为持久人物状态。

四人及必要适配尚未绑定、时间推进尚未完成或跨模块不一致时，完整保存应明确失败，不降级生成缺少人物的数据。恢复时间流以保存的总时刻作为后续推进起点，不能再次播放保存前最后一段移动。

### 4.2 加载

1. **解析和迁移**：读取版本、建立候选数据，保留原文件。
2. **校验和准备**：核对所有字段、内容版本、角色集合、活动／会面归属、时间、位置、路线及资产约束；准备全部运行逻辑和身体候选。期间当前世界、合法请求、模态和预算保持可用。
3. **提交**：在停止逻辑派发的边界发布整组数据与身体，建立新运行代次；旧请求立即失去写入资格。加载不经过普通接受邀约／执行交付接口，也不添加“重新完成”经历。
4. **重建**：恢复索引及活动所有权、同步物理位置、关闭旧玩家对话／模态、重新采样观察；时钟驱动丢弃旧帧采样，加载耗时不推进游戏。
5. **恢复派发**：关键重建完成后才允许 Tick 和新的行动。观察者通知发生在此明确边界之后，可选显示异常不能使其他核心恢复步骤被跳过。

解析、兼容或准备失败返回失败且保持原运行状态；数据已经提交后的关键恢复异常必须进入可诊断的恢复未完成状态并阻止该会话行动，不能声称旧状态未变，也不能吞异常后报告正常成功。具体实现由[读档重建失败边界](https://github.com/qinjunw/CozyTown/issues/91)验证，完整快照实现沿用其结果。

当前会面用对象引用相等判断双方活动归属。持久化须用稳定的活动身份恢复共享归属，或用等价的受检查关系；分别反序列化两份相同值却互不关联的活动不满足契约。新格式中缺失参与者、矛盾阶段或无法恢复的路线应在提交前拒绝，不能静默归位后仍称等价恢复。

身体校验按保存的执行状态区分：`Travelling` 要求路线拓扑和游标有效；普通 `Blocked` 保留受阻与重规划标记，不要求重新找到可行路径，也不隐式执行 `Retry()`；`NoLegalPosition` 可以没有可落脚位置或可达路径，但坐标须有限，恢复后仍隐藏、不可交互且受阻。所有配置落点被占用是需要保留的运行状态，不等同于损坏文件；障碍变化后的恢复继续遵守既有显式重试／重建规则。不能为通过加载校验把这种状态强行显示在障碍内部。

## 5. 决策续接、时间与幂等

游戏停止期间不推进小镇时刻。人物行为冷却和逻辑决策总时限保存为剩余时长；恢复后从新的单调时间原点继续计时，不扣除进程关闭时间，也不沿用旧进程的绝对秒数。实际调用速率和在途约束独立运行，同进程加载期间经过的真实时间仍由原账本正常计量。

新代次使所有旧请求失效。恢复 Pending／Current 时，先检查原机会、会面、轮次、剩余时限和调用次数，再重新采样 Self、Social、Observation 及允许动作；生成新的执行请求 ID。已披露详情和纠错反馈只在对应逻辑条件仍成立时继续使用，不能把保存的当前观察重新标成刚刚看见。

重采样不延长原机会：普通机会的原游戏时刻和截止仍有效；已交付会话的待发言轮次继续受原会面截止限制。已披露地点可达性重新校验，不再花一次模型调用重复查询相同详情。已开始决策的续接不重新套用“开始新决策”的人物冷却，否则默认 30 秒冷却会超过默认 12 秒总决策时限；尚未开始的新决策仍遵守恢复后的冷却。

已发出的请求即使没有取得结果也算已耗调用。默认每次决策最多两次调用：第一次在途时保存，恢复后至多还可调用一次；第二次在途时保存，恢复后直接按既有限制回退，不得发出第三次。下一 Step 与已耗 Calls 一致，纠错不能重新获得一次额度；新的单次请求期限还受剩余总决策时限约束。恢复次数或时限已耗尽不回滚已发生交付，也不伪造一句台词；会面沿既有终止／到期规则得到结果。

尚未完成的旧物理任务继续占用当前会话的真实在途限制，直至本地任务完成；转交其他会话所有者管理也必须连续计数，剥夺写权限不代表请求已经结束。新运行进程不存在可恢复的旧 Task；本契约不承诺终止模型服务端计算，也不提供跨进程的账户限流器，已发生账单不能撤销。

MeetingId 和活动归属作为存档中的逻辑身份保持；WorldRunId 与请求 ID 属于新执行过程。恢复已交付会面只恢复凭据和资产，不再转移。读取交易前的早期档后，可以在该恢复世界中重新完成交易；它与同一次恢复中的重复回调不同。经历、机会和当前结果也回到该快照，不能留下未来时间线的信息。

## 6. 格式、旧档与兼容

目标写入版本为 schema v4；当前实现仍写 v3。新格式包含必需的世界／人物／Agent／配置区段，缺失区段是无效输入，不能套用旧版缺字段默认值。沿用稳定 ID、逐版本迁移、迁移后统一校验和未知未来版本拒绝规则，不改变现有磁盘提交机制。

旧档迁移规则：先沿用 v1／v2 到现有 v3 的经济及结算语义，再产生完整快照起点。保留原时间、种子、资产及生产进展；小数分钟为零；人物按旧日程归位；活动、会面、经历、逻辑待办为空；按原初始化规则产生后续机会。仅含玩家的合法旧档沿用已记录的 NPC 资产初始化规则，部分缺少角色仍拒绝。玩家位置缺失时使用显式初始配置。

记录原始版本及采用的初始化配置，标识“旧档迁移起点”；它不能成为与旧运行途中行为等价的样本。读取或迁移不自动覆盖原存档；成功恢复后由正常保存操作写新格式。新格式内容版本不匹配时明确失败；若未来需要修复导入，应作为新实验起点记录，不能混入正常往返恢复。

## 7. 实施边界与 ADR 影响

本契约要求公开、无副作用的数据捕获与候选恢复入口，但不规定通用事务框架、DI 容器或序列化所有对象。沿用 Runtime 领域数据与 Unity 身体适配分工；[快照实现](https://github.com/qinjunw/CozyTown/issues/94)按一个公共行为切片一次 RED → GREEN 推进。

| 现有决策 | 新格式实现时的局部变化 |
| --- | --- |
| [ADR-0003](adr/0003-save-versioning.md) | 继续版本化独立数据包；扩展必需状态、配置身份及迁移规则 |
| [ADR-0013](adr/0013-deterministic-town-life-and-derived-npc-presence.md) | 新格式恢复保存的身体进度；旧档仍按日程归位 |
| [ADR-0014](adr/0014-continuous-world-time-and-morning-settlement.md) | 新格式恢复小数分钟；旧档缺失时取零；睡眠、新游戏及结算规则不随此改变 |
| [ADR-0015](adr/0015-resident-activity-arbitration-and-world-epochs.md) | 新格式恢复活动及未消费通知，保持新代次拒绝旧候选；不以普通 WorldRebuilt 唤醒替代保存状态 |
| [ADR-0016](adr/0016-bounded-autonomous-decisions.md) | 补逻辑待办续接和已耗步骤；真实预算／物理请求仍独立于世界恢复 |
| [ADR-0017](adr/0017-resident-meeting-commitments.md)、[ADR-0018](adr/0018-resident-resource-delivery.md) | 新格式持久保存进行中互动、有限经历及交付凭据，双方活动和资源继续受宿主校验 |

这些变化由已接受的 [ADR-0019](adr/0019-complete-logical-snapshots-and-agent-continuation.md)规定，面向尚未实现的新格式；旧格式仍采用本契约的迁移规则。普通活动期限、表达方式、四人实验 UI 和模型行为评测继续由各自票据处理，不能把本次确认当成其他玩法也已决定。

## 8. 公开验收矩阵

入口沿用 `Services.GameSave.Save/Load`、`DaytimeClock.AdvanceElapsed`／`SleepForMinutes`、居民控制器活动／状态／观察入口、会面公共查询及固定 `INpcDecisionClient`。新增捕获／恢复能力应通过整体存读档入口与后续行为验证；不反射私有字段，不在测试中复制生产算法。保存的数据可通过正式快照／导出入口核对。

| 编号 | 初始情境与操作 | 必须观察到的结果 |
| --- | --- | --- |
| SC-01 | 四人、全部资源和非整数分钟保存；保存后继续推进 | 保存本身不移动、不消费事件、不发调用；快照不随活对象继续变化 |
| SC-02 | Ren 位于道路中途、到达、返家、受阻或全部配置落点被占用，各自往返保存；对照分支使用相同时间增量，再移除障碍并显式恢复 | 实际位置、路线进度、活动、观察与会面到场结果与保存分支一致；NoLegalPosition 仍隐藏且不可交互，受阻不因加载获得隐式 Retry；显式恢复遵守既有规则 |
| SC-03 | 邀约待回复、已接受未出发、双方赴约、单方已到达分别保存 | 双方阶段、预约和原截止一致；无第二份邀约／活动；从保存阶段继续，按原有资格与期限决定后续结果，加载本身不统一中止会面 |
| SC-04 | 固定初态 Ren 两条鱼、Sora 零鱼；同意一条鱼换 25 金币后在交付前后各保存 | 交付前恢复仍须真正执行；交付后恢复保持鱼为一／一及相应金币变化；重复请求不再转移 |
| SC-05 | 交付后等预算、轮到 Sora、已有前两句台词时保存 | 恢复同一逻辑轮次与原台词顺序；不补第二次交付、不冒充说过第三句；预算释放后按允许次数继续 |
| SC-06 | 第一次／第二次模型调用分别在途，以及 inspect／首次纠错后待派发时保存；旧请求忽略取消并晚到成功或失败 | 新代次拒绝旧结果；两次调用上限分别只剩一／零次；原机会不延长，详情不重复查询，纠错 Step、剩余期限和物理占位正确；续接不重新等待新决策冷却 |
| SC-07 | 当天已放弃资源机会、普通冷却未完、多个居民同时排队时保存 | 已消费机会不再赠送；相对冷却、队列顺序和轮询进度保持；反复加载不能重置现实调用账本 |
| SC-08 | 保存后继续交谈或交易，再读早期档，连续两次读同档 | 人物经历与资产回到保存时点；前一次恢复派发的结果失效；没有未来声明、重复结算或重复经历 |
| SC-09 | 破坏一个 NPC、活动归属、会面引用、坐标、路线或配置版本 | 提交前拒绝；原时间、小数、四人位置、活动、订阅及合法请求保持可用 |
| SC-10 | 四身体准备到最后一人失败；提交后关键重建或可选显示通知抛错 | 准备失败不先移动前三人；提交后失败有明确状态、停止行动及受控恢复；不伪报成功 |
| SC-11 | v1／v2／v3、部分角色缺失的新档、未来版本、损坏文件 | 旧档保留原文件和实际资产，按第 6 节初始化缺失人物状态并记录迁移来源；新档必需数据缺失不以旧档默认值补齐 |
| SC-12 | 玩家对话或保存界面打开时经公开入口加载；加载耗时后恢复 | 成功加载旧模态／旧对话失效，输入速度归零；第一帧不计加载耗时；失败准备保持旧会话 |
| SC-13 | 相同快照和配置，重放时间、玩家／随机输入、事件及模型响应顺序 | 映射临时 ID 后核对请求和宿主结果；分歧报告并停止，不能按序盲用历史回复 |

提交后失败的当前处理依据 [ADR-0020](adr/0020-post-commit-world-recovery.md)。后继实现必须保留其暂停、错误类别和预算约束，并验证新快照准备、模块异常与补偿失败；现有 schema v3 的故障测试不替代 SC-10 的四人准备验证。

本表是后继实施的验收要求，不是本轮通过结果。确定性恢复验证无需真实模型；真实模型的再次选择由最终四人评测另行报告。

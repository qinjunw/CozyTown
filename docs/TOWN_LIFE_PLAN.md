## 2. 地图与住宅草案

建议先以约 `32×22` Tile 灰盒验证，铺地面积约为当前的 `2.58` 倍；这是布局起点，不是已经通过可达性检查的最终坐标。保持一个连续场景、原有像素密度与人物世界尺寸，不通过缩小人物或拉远相机把全镇塞进一屏。

```text
北侧：四户住宅街（Mina / Ren / Sora / Eli，各自独立入口）
               │ 住宅支路与主路连接 │
中部：商店 ───── 鸡舍／公共休息点 ───── 厨房
               │ 中央主路 │
南侧：玩家住宅 ─── 池塘环岸 ─── 农田／母鸡草地
```

图只表达邻接关系；灰盒优先保留已有六个功能地标的位置，住宅和支路放在新增北侧区域，外圈留出绕行通道。主角出生点、床和各业务入口保持稳定身份。

- 每名 NPC 对应唯一住宅 ID、门外到达地点和入门终点；四户不能共享同一个住宅 ID，也不能占用玩家住宅。
- 住宅先只有外观和门口短进出：早晨从自家门口出现并沿路离开；晚上实际走到入门终点后隐藏身体、对话 Trigger 和 `E` 提示。运行中的“到点”不能直接让角色从远处消失。
- NPC 住宅不注册为额外 `Bed` 或新业务交互；原有七种交互语义、六个功能入口与四个 NPC 实体保留。夜间 NPC Trigger 可暂不可用，不要求十个入口同时可交互。
- 建筑脚部实体碰撞与屋顶前景分开，继承浅门槽和屋后通行原则。每座新住宅单独验证门槽最深处仍有至少 1 原生像素的头顶净空，不盲目复制屋顶分割数值。
- 所有工作、休息与门外地点必须在可达区域，不能位于农田、池塘或墙体内，也不能占据玩家进入业务门槽的主要站位。
- 跟随相机保留 `16 PPU`、`320×180` 和整数显示；按实际可见半宽/半高钳制到铺地边界内。世界边界防角色越界，镜头边界防露出空白，两者不混用。

## 3. 四名 NPC 的日常草案

人设来自 [DefaultMvpContent.asset](../Assets/CozyTown/Content/DefaultMvpContent.asset)，不重写职业或身份。

| NPC | 人设依据 | 上午／下午 | 午间地点 | 住宅辨识候选 |
| --- | --- | --- | --- | --- |
| Mina | 务实、善良、重视公平交易的店主 | 商店外侧经营位置，面向货物陈设 | 公共休息点 | 暖棕窗框、门边货箱 |
| Eli | 耐心、解释种植的农夫 | 农田边缘巡视点，面向作物 | 鸡舍旁草地，避开母鸡 | 绿色门窗、门边种植箱 |
| Ren | 安静、关注池塘变化的渔夫 | 池塘安全岸边，上午与下午可用不同岸点 | 池岸休息点 | 蓝色窗框、渔具陈设 |
| Sora | 活泼、喜爱当地食材组合的厨师 | 厨房外侧备餐位置 | 公共休息点中的独立站位 | 赭红门窗、食材篮 |

首版工作表现是走到相应地点后停留、朝向工作对象；浇水、抛竿、炒锅等专属动作不作为通过前置。四人都要有四方向步行动画，不能用一张正面图滑行完成最终验收。

建议固定日出 `06:00`、日落 `18:00`；每天重复一套配置日程，不加入星期、季节、天气或随机作息。日落按“正常通行条件下已归家”验收，而非仅开始返程。

| 时段 | 目标行为 |
| --- | --- |
| 00:00～05:59 | 居家，世界身体与交互不可见 |
| 06:00 起 | 四人从各自住宅出发，08:00 前到达职业地点 |
| 12:00 起 | 前往各自午间地点 |
| 13:00 起 | 回到下午职业地点 |
| 17:00 起 | 结束活动并步行回家；路线长度与速度须允许 18:00 前入门 |
| 18:00～23:59 | 居家；异常受阻者不得隔空隐藏，保持合法位置并报告受阻 |

日程规定当前目标；实际状态区分“前往某地”“在某地活动”“居家”和“受阻”。不能把尚在路上的 NPC 报告成已经在商店。重复评估同一时刻不重复启动同一段旅程；跨过多个时段时只转向当前目标，不补演已错过的活动。

## 4. 时钟、暂停与日切

- 建议节奏为现实 `5 秒 → 10 游戏分钟`，白天 06:00～18:00 约 6 分钟；NPC 速度先以 `2 世界单位/现实秒` 试验。具体节奏在灰盒通勤验收后锁定，不改玩家现有移动速度。
- Unity 只把前台、未暂停的经过时长交给窄应用入口；时间换算集中定义，不在每个 NPC 内另计“游戏时间”。所有角色按同一个时钟选择日程。
- 包裹、系统菜单、业务面板和 NPC 对话任一模态打开时，同时停止自动走时与 NPC 行走。界面关闭、撤销或停用后恢复；后台失焦也暂停。暂停期间不积累待追补的现实时间，UI 与 HTTP 超时仍可工作。
- 模态与失焦是叠加的暂停原因，只有全部解除才恢复；关闭菜单但窗口仍失焦时，时钟与 NPC 继续暂停。
- 自动走时最多到当日 `23:59`，不跨午夜；例如 `23:55 + 10 分钟` 结果是同日 `23:59`，不能变成下一天 `00:05`。日末提示可放在左上时间 HUD 或床交互内，不恢复旧左下常驻说明板。
- 睡觉仍经 `IDayTransitionCoordinator.SleepToNextDay()` 原子结算时间、农田、畜牧与商店，成功进入次日 `06:00`。不能让新增 MonoBehaviour 直接调用底层 `AdvanceMinutes` 越过午夜。
- 显式睡觉和加载在模态暂停中仍可执行；只在成功提交后重建 NPC 世界状态。失败不改四人的位置、目的地和居家状态，不把失败当作新一天。
- 成功加载、睡觉或新游戏清空旧时间线的残余计时与待处理 tick；失败保留调用前计时状态。例如读档前累计 4.9 秒，成功读回 06:00 后不能再过 0.1 秒就推进 10 分钟。

自然午夜自动跨日、通宵工作和昼夜光照不是本阶段前置。固定日出/日落用于作息，不引入真实天文或天气模拟。

## 5. 移动、交互和模块边界

建议首版采用小型道路节点图：同一布局数据声明住宅、工作/休息地点与连接，日程按稳定地点 ID 给出目标，导航在图上选择固定规则的路径。Unity 验证路径线段按脚部占地外扩后不穿越真实非 Trigger 障碍，执行器在每次短距离移动前检查障碍；不用贴图颜色决定可走性。

这种方案适合当前四人和固定地点。相较逐人硬编码坐标路线，它共用道路连接；相较全镇网格导航，它暂不支持任意地点自由漫游。只有固定地点图不足以表达确认需求时，再评估细网格或导航包。

- 最后入门段由门外地点连接到浅门槽终点；不得将目标粗略取整到墙内。
- 世界障碍阻挡 NPC。玩家与 NPC、NPC 彼此首版不新增实体互挡，避免可被玩家堵死的回家流程；路线和停留点尽量错开，不引入人群避让系统。
- 路径受阻时停止在最后合法位置，可做有次数上限的重新求路；无路返回“受阻”，不能无限重试、穿墙或在镜头内瞬移。正常配置下所有往返必须可达，受阻诊断不是正常验收的替代品。
- 途中切换时段或重新求路从实际位置开始，沿当前合法边连接端点，或连接经脚部扫掠验证的邻近节点后再求新路径；不能先吸附到图节点再移动。测试必须覆盖尚在路段中间时切换目标。
- 身体、身份、对话 Trigger 与气泡锚点随同一世界实体移动。打开对话立即暂停；入屋、读档或停用后清除旧目标，关闭后不能出现隐形 NPC 的气泡。
- 玩家和 NPC 之间改为按脚底前后排序；建筑底图继续在角色后方，屋顶前景继续在角色前方。仅局部替换 ADR-0009 的玩家/NPC 固定相对排序，不增加整栋房屋透明化。

| 模块边界 | 负责 | 不持有 |
| --- | --- | --- |
| Runtime 日程模块 | 稳定 NPC/住宅/地点关系、时间段规则、目标活动与重建结果 | Unity Transform、碰撞体、模型 SDK、经济写接口 |
| 应用层时钟与生活协调 | 日内推进、读取当前时钟、成功日切/加载后的统一重建 | 场景中查找的全局服务容器 |
| Unity 导航与表现适配 | 布局坐标、路线、脚部碰撞、实际到达、方向动画、可见性 | 钱包、背包、农田和存档写接口 |
| NPC 对话入口 | 当前身份与只读活动/地点快照 | 移动、时间和日程写权限 |

保持外部用例入口少而明确，图搜索、路径进度和动画映射封装在对应模块内；不为每个时段或每名 NPC 创建一套服务接口。只有实际复用的朝向/速度动画契约需要从玩家动画器抽取，玩家输入不随此阶段重构。

## 6. 存档与生命周期建议

首版保持 schema v2。NPC 的住宅归属和日程是静态配置，世界位置、路径进度和工作表现定义为可重建状态，不承诺读档原地续走。

成功加载后，在世界尚未恢复操作/显示新位置前，按加载后的分钟重建四人，使用不重叠的半开区间：`[00:00,06:00)` 居家；`[06:00,08:00)` 在自家合法门外节点重新出发；`[08:00,12:00)` 在上午职业地点；`[12:00,13:00)` 在午间地点；`[13:00,17:00)` 在下午职业地点；`[17:00,18:00)` 在下午活动的合法出发点重新返家；`[18:00,24:00)` 居家。不演算过去旅程；四人统一 06:00 出发，不另设错峰分支。成功睡觉统一从次日清晨状态开始。重建不能改变任何经济或生产数值。

读档本来就是世界时间线切换；上述合法归位只允许发生在成功加载、新游戏或成功睡觉的显式切换中，不用于普通走路纠错。四人新状态应准备完成后共同显示，失败加载不清空旧路径；路径速度、目标引用错误须在内容校验阶段拒绝。

07:59 或 17:59 读档可能只剩 1 游戏分钟，重新从家门或工作点出发不保证当次仍赶在 08:00 到岗或 18:00 到家；此为首版“合法归位而非精确续走”的明确例外，仍须实际到达才切换为停留/居家。准时验收使用未发生时间线跳转的正常日程。

玩家位置持久化不在本阶段增加；若重排地标导致当前玩家坐标落入障碍，场景发布前解决布局或明确安全出生点迁移，不能把玩家无条件重置伪称存档原位恢复。将来要求精确恢复任何角色的途中状态时，另行设计快照与迁移，不把坐标或 SDK 会话偷偷塞入经济主体字段。

后续 Agent 的旧请求/记忆提交必须随成功加载失效；“知道自己的家和当前活动”来自新快照，不来自模型猜测。T1 不提前实现或启用 Agent。

## 7. 美术批次与文件管理

| 内容 | 计划产物 | 复用与准入 |
| --- | --- | --- |
| 四户住宅 | 4 个 `64×64` 建筑 Sprite + 对应 4 个屋顶前景 | 可复用墙、门、屋顶部件；每户至少两项可见差异；与职业、住宅 ID 对应 |
| 四人行走 | 每人 4 方向 ×（1 静止 + 2 步行）= 12 帧，共 48 帧 | 相比当前四张正面站姿，需补 44 帧；保留头像中的发型、帽子和服装特征 |
| 地面、道路与功能物件 | 优先复用现有生产资源 | 不增加物品、作物、动物、配方或 UI 主题 |

建议源稿进入 `ArtSource/Generated/T1/`，原生像素源进入 `ArtSource/Authored/T1/`，整数倍预览进入 `ArtSource/Previews/T1/`。生成式源图经现有方式编辑、编译和验收后，产物仍按类别进入 `Assets/CozyTown/Art/Production/Buildings/` 与 `Characters/`，不另建运行时素材根目录。

现有批次入口与预览测试仍固定为 A1；创建 T1 目录本身不会被自动消费。资源切片必须新增 T1 批次定义与构建入口，显式配置源稿和 T1 预览路径，并补充对应资源契约测试；Production 通用导入策略继续复用。四户若不能共用一条屋顶分割线，则使用已裁好的原生屋顶源或明确的逐格分割参数，逐户验证净空。

候选生产文件为 `bld_npc_homes_64.png`、`bld_npc_home_roofs_64.png`，以及每名 NPC 独立的 `npc_<stable-id-suffix>_move_24x32.png`；正式命名、切片和所有权在资源切片开始前写入 `ART_ASSET_MANIFEST.md`。旧静态图集在确认无引用前保留，不能用新稿覆盖其他角色或头像。

遵守现有 16 PPU、32 色、Point、无压缩、二值 Alpha、BottomCenter 和 `24×32` 帧规格。每帧脚底、可见高度和左右脚完整性按现有主角门禁校验；使用非对称服饰时，镜像阈值针对主体轮廓，不要求身份细节逐像素镜像。自动化管线只证明技术准入，原生尺寸、四方向辨识度、行走连贯性和屋顶净空仍需人工复核。

T1-1 复用现有住宅贴图作灰盒。先通过住宅布局和单 NPC 往返的灰盒验收，再于 T1-4 生成缺口资产，避免地图比例变化造成整批返工。

## 8. TDD 验收与交付顺序

用户已确认以下公开测试缝隙：日程查询/重建输出、日内时钟应用入口、成功日结/加载入口、公开世界移动状态与 Physics2D、NPC 当前交互目标、Camera 和导入 Sprite。不以私有计时器、路线列表或内部方法调用次数作为验收入口。

## 9. 门禁和完成定义

Scene-01 仍待人工验收。T1 在扩大版构建上执行新的 Town-01 检查，并重跑 Scene-01 的视觉、碰撞、交互、UI 与经济闭环回归；可以在同一人工会话中联合检查，但分别记录版本、分辨率、结果及遗留问题。旧静态坐标、六障碍计数和三单位 NPC 间距是 A1 历史夹具，不得替代 T1 的新增住宅与动态可达性标准。

只有扩大版的 Scene-01 回归与 Town-01 都通过，才进入真实 NPC Agent 接线；此前允许固定对话和假模型测试。T1 不以新增截图、自动化绿灯或本规划完成来宣告人工验收通过。

已接受的四组默认方案为：约 32×22 的地图灰盒起点；住宅只做外观进出；5 秒推进 10 分钟、全模态/失焦暂停与午夜封顶；读档合法归位而非精确续走。尺寸和通勤速度仍需按灰盒测量验证；方案确认不计作运行行为通过。
